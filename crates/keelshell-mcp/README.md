# KeelShell MCP server

This crate exposes KeelShell capabilities to external agents. It does not connect to third-party MCP servers.

Build with `cargo build -p keelshell-mcp --locked`, then launch `keelshell-mcp` with no arguments. The process uses newline-delimited JSON-RPC on stdin/stdout; diagnostics are static stderr text. It supports MCP `2026-07-28` discovery/per-request metadata and `2025-11-25`/`2025-06-18` initialization compatibility.

**The standalone executable is disabled and disconnected by default.** Tool discovery works, but calls return `DISABLED` until the desktop user explicitly grants access. Build both `keelshell-app` and `keelshell-mcp`, connect an SSH session in the application, then use its MCP panel to select the permitted session, tools, terminal selections and SFTP directories. The panel supplies temporary startup configuration for the external agent.

With that configuration, the companion forwards stdio requests over authenticated, encrypted loopback IPC to the running desktop application. The desktop checks the current session, route and granted paths before using its SSH/SFTP handles. The companion does not log in to SSH or unlock credentials. Revoking access, reconnecting or exiting the application invalidates the old grant; restarting does not restore it. `DesktopIpcClient` names this dedicated bridge, not a client for third-party MCP servers.

The fixed tools enumerate permitted session labels, read explicit terminal selections, list/read scoped SFTP paths, read cached monitoring fields, enqueue immutable command or existing-file replacement proposals and inspect typed desktop action state. There is no external approval, arbitrary execution, file-write, SSH-login or vault-unlock tool. A proposal can only become an action after a separate human review in the desktop application.

See the [external MCP guide](../../docs/product/EXTERNAL_MCP.md) for setup and all eight tools, [ADR 0037](../../docs/adr/0037-external-mcp-stdio-server.md) for the protocol contract and [ADR 0039](../../docs/adr/0039-authenticated-desktop-mcp-ssh-bridge.md) for desktop authorization and IPC. The [capability ledger](../../docs/product/CAPABILITIES.md) and linked test records distinguish implemented behavior from the external-client and native-platform workflows still under verification.

The eighth fixed tool, `keelshell_propose_file_change`, requires separate desktop consent and a scoped canonical directory. It accepts an exact expected complete SHA-256 and up to 64 KiB of UTF-8 replacement; it only enqueues review and exposes no current preimage/hash without a read grant. Existing 128 KiB encoded frame limits still apply. Human approval uses the captured SSH handle and checked POSIX atomic replacement, with no create/delete/move or non-atomic fallback. See the [file review guide](../../docs/product/MCP_FILE_CHANGES.md) and [ADR0051](../../docs/adr/0051-reviewed-mcp-file-replacement.md). Historical seven-tool vendor/native receipts remain historical evidence.
