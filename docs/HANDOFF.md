## 产品范围与工程要求

- 使用 Rust 与原生 GPUI Kit，支持 macOS、Windows 和 Linux。仅管理远程 SSH，不开发本地终端、RDP 或串口。不能将编译、夹具、部分切片或桌面单次操作表述为完整产品验收。
- 默认简体中文，维护英文及两份 README。外观默认跟随系统，也可切换浅色/深色；保留会话、草稿与在途任务。应用图标白底并适配各平台，连接、监控、终端、文件/命令与 AI 保持清晰分区。
- **MCP 是 KeelShell 向外部智能体提供的服务。** 不开发通用第三方 MCP 客户端。外部访问默认关闭，限定已授权会话、工具、路径及终端片段；命令和文件修改只形成需要人工审核的提案。见[对外接入](product/EXTERNAL_MCP.md)与[设计计划](product/DESIGN_AND_AGENT_PLAN.md)。
- API 与本地 Claude Code/Codex 推理入口独立。上下文由用户明确选择，回答和提案可完整审阅，模型不能自主执行。配置与交互研究见[参考记录](research/dbx-ai-reference.md)。
- UI、领域/存储、传输和 AI 分层；阻塞 I/O 不进入 UI 线程。直接 registry 版本使用 `x.y`，保留 Cargo.lock 补丁锁定和精确工具链。公开库 API 有 rustdoc，测试使用隔离数据和有界等待。
- 凭据默认临时；显式保存走 OS 存储或认证加密 vault，主密码与明文凭据不进入 metadata。不引入私有 Git 依赖、开发者绝对路径、真实凭据或客户日志；公开文档通过自身能力介绍产品。
- 已只读评估 Reef 与模板的工程/生命周期方案，见[研究目录](research)。用户已授权公开 GitHub、提交推送及标签触发多平台 Release；没有授权遥测、自动安装 CLI 或覆盖既有应用。
- 功能完成后新开非作者子 agent 审查，合入前完成格式、Clippy、行为测试、依赖策略及相关原生检查。保留失败证据，及时归档不再需要的工作树、分支与缓存。
