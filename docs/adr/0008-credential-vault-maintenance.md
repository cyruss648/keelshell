# ADR 0008 — 凭据库检查、清理与主密码轮换

日期：2026-10-03。状态：已采用。

## 背景

SSH 和 AI 的可选凭据保存共用经过认证的本地凭据库。配置保存失败或引用被解除后，库内可能留有未关联条目。用户需要查看这些条目的用途、清理它们，以及更改主密码，同时避免显示秘密或破坏配置引用。

## 决定

- 延续 [ADR 0006](0006-authenticated-credential-vault.md) 的 schema 2、完整 manifest 认证、条目身份绑定和文件并发快照协议。新增 AI API 密钥角色编码 `3`，既有两种角色编码不变。
- `CredentialVault::entries()` 只提供经过认证的引用、所属配置 UUID 和凭据角色。维护页使用工作区提供的配置名称辅助识别；找不到名称时显示“未保存或已移除的配置”。不解密或显示秘密。
- `rotate_passphrase()` 在临时对象中生成新盐、新派生密钥和逐条新随机 nonce，完整重新加密并验证大小预算后才替换当前对象。条目引用、所属配置、角色、顺序保持不变；任何中途失败都不产生部分内存轮换。
- 轮换保留原已认证磁盘快照。后续 `VaultStore::save()` 仍比较读取时的旧磁盘字节与 revision，不使用新密钥去解密旧文件，也不把旧文件误判为未经读取的库。
- 原生维护页每次操作都要求重新输入当前主密码。检查结果只保留元数据列表，不缓存主密码、派生密钥或已解锁库。更改主密码要求重复输入一致，删除要求先选择条目、再次输入主密码并明确确认。
- 工作区仅在其他配置写入和登录流程空闲时打开独占维护页，在页面存续期间冻结本进程配置引用变更。页面提供 `is_busy()`；关闭忙碌页面会请求取消并等待后台结果，后台返回后才发出 `Close`，并把最终成功、取消或失败状态传给工作区；关闭页面不会吞掉已准入写入的结果。所有 KDF、vault/state 文件读取及保存均由后台阻塞任务执行。
- 删除只允许“当前已保存配置未关联”的条目。保护集合包括打开页面时工作区提供的引用，以及后台本次从磁盘重新读取的活动 SSH、回收站 SSH、AI 身份认证、额外请求头和代理凭据引用。保存前再次读取磁盘引用，发现关联就拒绝删除。冻结的工作区引用与刷新后的磁盘引用分别维护，后续检查不积累已经解除的历史磁盘引用。
- 维护使用 `VaultStore::load_existing()`：在实际读取分支拒绝缺失库，检查不存在的凭据库不会创建库文件，也不会因存在性预检竞态创建空库。凭据库位置和配置位置由调用方显式传入，使实际配置与隔离测试使用相同路径规则。

## 边界

取消检查发生在任务开始、KDF 后、变更计算后及保存开始前。已经进入保存的操作可能完成；取消不能撤销已开始的原子替换。页面仍等待该任务并报告真实结果，不把已完成保存声称为未发生。关闭整个应用时不能承诺撤销已经开始的后台写入。

`state.json` 和 `vault.json` 仍是两个独立文件。删除前刷新磁盘引用缩短了竞态窗口，但另一个进程可能在最后一次读取之后保存新引用，也可能持有尚未保存的草稿。本协议不是跨文件事务或跨进程维护租约。删除确认准确限定于当前已保存配置，不能证明所有外部草稿都不再使用该条目。

主密码与秘密所有权使用零化包装；界面提交、关闭及锁定时清空输入。GPUI 输入/撤销缓冲区、分配器副本、系统交换区和崩溃转储不在完整擦除保证之内。删除加密条目不等于对文件系统历史版本或备份进行安全擦除。

本切片未引入新密码学算法、OS Keychain 或跨平台原生验收声明。验证范围见 [专项记录](../testing/records/2026-10-03-vault-maintenance.md)。
