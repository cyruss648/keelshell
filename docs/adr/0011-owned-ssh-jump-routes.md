# 0011 — 专属 SSH 跳板路线

日期：2026-10-03。状态：已实施，集成与各平台验收结果按专项测试记录维护。

后续扩展：[ADR 0013](0013-upstream-ssh-proxies.md) 增加每跳上游代理，含代理的路线使用版本 2，且第一跳带代理时也使用路线作用域指纹。下文版本 1 与旧直连信任规则只适用于无代理路线。

## 用户流程与模块职责

连接配置可选择一条已保存的 SSH 配置作为跳板。跳板本身可以继续引用其他配置，最多 4 个跳板，再加 1 个最终目标。选择器支持搜索、分页和路线预览，阻止自引用、经过当前配置的回路以及超深选择。不可用的既有引用保留并显示错误，不能静默变成直连。选择器使用草稿快照，保存时仍须以当前连接库重新验证完整图。

连接按外层跳板到最终目标依次进行。认证和指纹确认界面显示当前步骤、配置名称、完整账号地址与整条路线。只有最终目标生成终端标签及最近成功记录；跳板是该路线内部的连接，不生成额外终端。界面默认中文，也提供英文，切换语言保留当前选择、草稿及在途路线。

职责分为三层：

| 层 | 职责 |
| --- | --- |
| `keelshell-core` | 保存引用，验证依赖图，解析有界路线快照，规范化路线身份，管理作用域指纹及连接库变更。 |
| `keelshell-session` | 在已认证 SSH 的 `direct-tcpip` 通道上建立下一跳 SSH，完成独立核对、认证、重试和有界资源清理。 |
| `keelshell-app` | 顺序推进步骤，收集每跳认证输入，显式确认指纹，将异步结果绑定到当前路线与弹窗，保存配置。 |

`Connection.jump_host: Option<Uuid>` 表达保存的关联。`AppState::connection_route` 返回拥有自身数据的 `ConnectionRoute`，其 `hops()` 按实际连接顺序排列，包含配置元数据和不透明凭据引用，不包含密码、解密结果或私钥内容。解析不做网络、凭据库或私钥文件 I/O。

## 路线身份与每跳信任

`RouteEndpoint::from_connection` 是端点规范化的统一入口：DNS 名转小写并去掉末尾点，IP 使用标准规范形式，端口精确匹配，账号保持大小写。`RouteIdentity` 是版本为 1 的结构化有序端点数组；直连也使用单元素数组。路线身份排除配置 UUID、名称、标签、目录、收藏与凭据引用，因此改名及等价 DNS 写法不改变网络身份。

`identity_prefix(index)` 包括从第一跳到当前跳的全部端点，`host_key_scope(index)` 由已验证快照构造相应的信任作用域。顺序属于身份的一部分，不能仅使用目标地址或某个配置 UUID 代替路线。

| 场景 | 指纹存储与匹配规则 |
| --- | --- |
| 直连或路线第一跳 | 沿用 `known_hosts` 的规范化 `[host]:port` 键，兼容既有直接连接的信任记录。 |
| 路线第二跳及以后 | 使用 `route_known_hosts`，键为完整路线前缀的规范 JSON，包含每个端点的主机、端口、账号及顺序。 |

下游指纹查询不回退到直连记录。两个网络中的同名私网目标不共用指纹；上游主机、端口、账号或路线顺序变化后，下游进入新的信任作用域。显示名称变化不要求重新确认。私钥路径和认证方式不属于服务器指纹身份。

每跳建立自己的 host-key handler，未知或变化的密钥在认证前失败。用户明确批准后，应用先持久化该次观察对应的作用域，再重新进入当前跳认证；不会将一次输入的密码跨越指纹确认自动重用。批准前再次检查整条路线、请求标识和步骤，防止将旧路线观察写成新路线信任。旧作用域记录可以继续保留，但不会被不同路线自动采用。两种指纹表合计最多 10,000 项，仍受状态文件大小上限约束。

## 专属父链与传输所有权

每次连接请求从第一跳重新建立专属父链，不借用其他终端标签的 SSH 会话。这样一个路线的取消或异常清理不会关闭无关标签。完成后的最终 `SshSession` 通过通道 relay 持有上一跳，上一跳继续持有自己的父连接；外部不需要另存一个全局父会话池。

`SshSession::connect_through` 与 `connect_through_with_retry` 接收已认证的父 `SshSession` 和当前跳 `SshOptions`。下一跳名称交给父服务器的 `direct-tcpip` 解析，不在本地解析该目标域名，不创建本地监听，也不在通道失败后回退直接 TCP 连接。每跳可分别选择本地 SSH agent、密码或私钥。使用本地 agent 签名不等于向跳板转发 agent。

每次完整尝试共用一个截止时间，覆盖通道打开、目标 SSH 握手及认证。应用目前为每次尝试提供 15 秒，并使用既有有界退避策略；这是每跳每次尝试的预算，不是整条路线含用户输入的总时限。身份、凭据及明确通道拒绝不重试；瞬态重试通过同一个已认证父连接打开新通道。该接口不负责重新连接已经关闭的父会话。

通道打开前已有独立 owner，因此调用者取消时，已发起的请求仍可在原截止时间内接收并关闭迟到确认。已确认通道通过有界 64 KiB duplex relay 传输，子会话的控制器只取消自己的 relay；relay 保持父会话存活，但不反向保留子会话控制器，避免所有权环。

正常目标失败、取消和关闭会释放其通道并保留仍被使用的父 SSH。若打开请求永不确认，或 CLOSE 无法进入协议队列，有界清理可以关闭所属父连接。专属父链使这种兜底局限于当前路线。CLOSE 入队、本地关闭状态与远端完成释放是不同证据；不能把前两者当作远端确认。最终标签及其后台工作释放最后一个会话引用后，无人使用的整条链随之清理。

## 凭据绑定与保存边界

各跳使用自己的配置与凭据引用，默认口令仅用于本次认证。显式保存沿用主密码加密凭据库：配置文件只存不透明引用，外层条目仍绑定配置 UUID 与凭据种类。主密码和解锁后的凭据库不常驻工作区。

SSH 加密条目内部的 `BoundCredential` payload 使用版本 2，绑定当前跳的完整 `RouteIdentity` 前缀、规范化目标端点以及当前跳认证方式，包括私钥路径。复制其他配置的引用不能绕过外层所有者校验。历史版本 1 payload 仅允许在没有跳板、路线只有一个端点的直连配置解锁；不能把旧直连密码自动用于某条新路线。这里的 payload 版本与凭据库容器 schema 是两个独立版本。

保存生成新的随机引用，先写密文，再写配置关联；不覆盖已有可用条目。配置关联成功只更新当前认证弹窗及路线中的引用元数据，要求用户显式解锁后继续认证。两次文件写入不是事务：已获准的加密操作或磁盘写入可能在取消后完成，并留下未关联密文；取消不能承诺回滚已经完成的持久化。迟到结果不能自动发起 SSH，解除关联也不会删除密文。

更改某个节点的规范化路线身份，或更改该节点认证方式时，核心会清除受影响节点及下游配置的凭据引用和最近记录，包括回收站中的引用。名称、标签等展示变化保留引用。这里的上游认证变更由配置变更规则使关联失效；payload 的路线前缀只序列化网络端点，不能将它误称为包含所有上游认证参数的密码学承诺。

## 取消、迟到结果与并发保存

`ConnectRoute` 保存独立请求 UUID、不可变路线快照、当前步骤、已认证父链及取消信号。网络操作在后台执行，监听取消并涵盖重试退避。取消清除认证输入、指纹弹窗与当前路线；丢弃工作区也会发出取消。连接结果发布前同时匹配请求 UUID、步骤，并重新解析当前配置检查完整路线及每跳认证。旧请求的成功或失败不能替换新请求的界面或建立终端。

认证弹窗另有独立 token 和取消标记。提交、解锁完成及凭据关联完成均验证弹窗和当前配置；已启动的 KDF 无法中途停止，但其迟到结果不能跨弹窗使用。信任保存后续动作携带请求 UUID 与步骤，凭据关联后续动作携带弹窗 token。取消后写入可以完成，但这些 token 不再有权恢复认证。

配置保存继续使用 `StateStore` 的 revision、锁和原子替换。保存中冻结本进程其他配置写入；出现外部修改冲突时不覆盖磁盘新状态。某跳成功恰逢其他保存时，下一步等待保存结束，再检查路线后继续。保存失败保留明确错误和可取消的当前流程，不绕过持久化去使用刚批准而未保存的指纹。

最近成功记录仅针对最终目标。排队保存时携带完整路线快照，在入队与真正写入前检查目标及整条路线，包括上游认证变化，防止旧成功结果在编辑后重新写回。

## 连接库变更与兼容性

所有活动配置与回收站配置构成一个受限依赖图，合计最多 10,000 项。领域层拒绝空 UUID、自引用、缺失节点、重复 UUID、循环及超过 4 个跳板的路线。不同 UUID 的配置可以具有相同规范化网络端点，不能把重复 UUID 与端点别名混为一谈。活动配置只能经过活动节点；回收站配置可继续引用仍存在的活动或回收站节点，以保留可恢复关系。

`AppState::update_connection` 对候选快照替换既有节点并验证全图，成功后一次性提交内存变化；缺失 ID 不隐式新增，失败保持原状态。复制生成新 UUID，保留跳板关联并清除副本自身的凭据引用。

有活动依赖者时不能将跳板移入回收站，需先处理下游配置。永久删除或清空单个回收项还需检查回收站中的依赖者；恢复按上游到下游顺序，依赖尚未恢复时拒绝操作。恢复也检查完整规范化路线是否与活动配置重复。不会通过自动清除引用把原本需要跳板的配置改成直连。

导出包含全部活动配置及目录，保留内部跳板关系，清除所有凭据引用，不导出指纹、回收站或最近记录。导入先验证输入图自洽，不借用本机同 UUID 节点补齐缺失的输入依赖；再建立新旧 ID 映射，最后重写全部跳板引用，因此输入顺序不影响合法链的导入。相同 ID 的冲突定义、含糊的本机匹配、仅存在于回收站或认证不兼容的复用节点，不能成为新依赖者的静默映射。涉及不可映射的依赖时整个导入失败，不留下部分配置。

原有状态格式中缺省 `jump_host` 视为直连，缺省 `route_known_hosts` 视为空表；空新增字段省略序列化。导入格式沿用既有版本并采用同样的缺省规则。旧版严格 reader 遇到新增字段会拒绝读取，不能宣称新路线配置可被旧版无损打开或安全降级。

## 验证与当前边界

领域验证及真实 `StateStore` 往返、冲突、原子失败结果见 [领域验收](../testing/records/2026-10-03-jump-domain.md)。下一跳解析、独立指纹、PTY/exec/SFTP、通道迟到确认、取消、重试、链式生命周期与异常清理见 [传输验收](../testing/records/2026-10-03-jump-transport.md)。界面回归通过真实回环 SSH 和独立临时配置验证认证步骤、信任保存、最终目标标签及路线取消；具体整合结果应以同一提交的测试记录为准。

这些本机受控证据不等于生产服务器认证策略、真实跨网络环境或 Windows/Linux 原生界面验收。当前路线仅由已保存 SSH 配置组成，不包含任意 `ProxyCommand`、外部代理脚本、交互式多轮认证、agent 转发或会话断线后的自动恢复。后续扩展必须继续遵守每跳显式认证、作用域信任和专属父链的边界。
