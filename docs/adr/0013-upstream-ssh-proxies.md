# 0013 — SSH 上游网络代理

日期：2026-10-03。状态：已实施；本机门禁与 macOS 原生受控验收通过，见[专项记录](../testing/records/2026-10-03-upstream-proxies.md)。

## 连接方式与配置

连接配置可以选择 SOCKS5 或 HTTP CONNECT 上游代理。代理属于单个 SSH 配置；每一跳可以使用不同代理，也可以不使用代理。代理端点从当前跳的出发位置访问：第一跳从本机拨号，后续跳通过已经认证的前一跳 SSH 的 `direct-tcpip` 通道访问。

```text
本机 → 首跳代理 → SSH 跳板 → 目标代理 → SSH 目标
```

代理握手的目标始终是当前 SSH 配置的主机与端口。SOCKS5 的域名形式交给代理解析，HTTP CONNECT 的 authority 保留目标域名；应用不为了目标 SSH 额外进行本机 DNS 查询。没有代理时保留原有 TCP / SSH 跳板行为。代理拒绝、协议错误或超时不会触发直连回退，也不会读取环境中的系统 HTTP 代理。连接代理与终端内提供本地监听的动态 SOCKS5 转发是两个独立功能。

`Connection.proxy: Option<ConnectionProxy>` 只保存协议、代理主机、端口和可选认证用户名。匿名和用户名/密码认证有独立类型，严格反序列化拒绝未知字段，包括伪装在匿名认证中的密码。代理密码没有配置字段、凭据引用或导出表示。旧配置缺省代理字段时保持无代理行为，空值不输出；旧版严格读取器可能拒绝带代理字段的新配置，不能承诺安全降级。

## 协议与秘密

SOCKS5 支持 CONNECT、IPv4、IPv6、域名、匿名和 RFC 1929 用户名/密码认证。用户名与密码各为 1–255 个 UTF-8 字节，长度按编码后的字节验证。HTTP CONNECT 使用 HTTP/1.1，IPv6 authority 加方括号，认证使用 Basic；用户名为 1–255 个 UTF-8 字节且拒绝冒号，密码允许空值、最多 4096 字节，二者拒绝控制字符。两种协议的用户名都拒绝控制字符及首尾空白。SOCKS5 密码按上述字节长度验证，可以包含有效 UTF-8 中的控制字符；HTTP 密码遵守更严格的控制字符限制。密码不做 trim 或规范化，输入不能注入请求行或请求头。

代理端点及带代理的 SSH 目标使用 ASCII 域名或 IP，域名最多 253 字节；国际化域名需要使用 Punycode A-label。配置保存阶段与传输阶段分别验证，不进行隐式 IDNA 转换。未使用代理的既有连接保持原来的主机输入规则。

所有认证信息只用于配置明确指定的代理。运行时秘密采用独立的 `Zeroizing` 容器，调试输出遮盖凭据；这不等于能擦除操作系统或第三方组件产生的全部副本。协议响应只转换为有限错误类别和数值状态，不能把代理响应头、正文或反射的凭据放入错误消息。HTTP 响应头累计最多 16 KiB，每个响应最多 100 个字段、最多 4 次信息性响应，101 不支持。接受最终 2xx，忽略成功 CONNECT 的 Content-Length 和 Transfer-Encoding；支持响应头跨多次读取到达，头后的 SSH banner 保留给 SSH 握手；不再按 HTTP body 或 chunked 格式解析隧道字节。拒绝不支持的认证、重定向和异常响应。

HTTP CONNECT 在此处指普通 HTTP 代理，不表示 HTTPS 代理。SOCKS5 用户名/密码与 HTTP Basic 本身不加密本机到代理的认证流量；使用可信网络或已有加密通道。通过 SSH 跳板访问代理时，前一段 SSH 通道被加密，但代理与下一跳仍遵循各自协议。SSH 主机密钥验证独立存在，代理成功不等于 SSH 身份可信。

## 路线身份、主机指纹与凭据

规范化路线端点增加代理协议、规范化主机、端口及认证用户名。无代理路线继续使用版本 1，序列化键保持原样；含代理的路线使用版本 2，每个前缀按实际内容选择版本。版本 1 不能包含代理，版本 2 不能表示完全无代理的路线，避免同一身份产生多个规范键。

单跳且无代理继续使用旧 `known_hosts` 键。单跳带代理以及其他路线使用完整前缀的 `route_known_hosts`，不回退直连指纹。修改代理协议、端点或认证用户名会改变路线身份；同一路线上游改变时，下游凭据引用和最近记录一起失效，包括回收站中的关联。显示名称、标签和等价 DNS 写法不改变身份。

版本 2 SSH 加密 payload 已绑定完整 `RouteIdentity`，无需增加代理密码或修改容器格式。历史版本 1 payload 只允许真正无跳板、无代理的直连。代理密码永不进入 SSH vault payload，保存 SSH 凭据也不保存代理认证。

## 界面与生命周期

连接编辑器提供可折叠的“网络代理”，保存端点和认证用户名，显示完整路线。既有代理配置重新编辑时可见；语言切换保留草稿。认证窗口分开显示 SSH 认证和代理认证。即使 SSH 使用 Agent，只要代理需要密码也必须提示。保存 SSH 凭据模式不收集代理密码，保存后解锁并连接时重新输入。

取消、认证模式切换、当前路线编辑或路线失效会清理临时输入。每次网络操作继续受请求 UUID、步骤和路线快照约束；凭据解锁的迟到结果不能跨路线使用。代理密码只交给当前跳的连接尝试，不自动用于下一跳或其他标签。

TCP / `direct-tcpip` 打开、代理握手、SSH 握手与 SSH 认证共享一次尝试的绝对截止时间。取消沿用现有传输控制器与通道 owner，正常清理保留仍使用中的父 SSH。应用为每条路线创建专属父链，因此异常清理局限于该路线；直接调用 session API 并复用父会话的调用者不能依赖这种隔离，未确认 OPEN 或阻塞 CLOSE 的清理超时可能关闭父会话并影响其全部引用。连接截止时间限制调用返回的等待，通道 owner 清理可能在后台继续至原 OPEN 截止时间及有限 CLOSE 预算。明确认证/协议拒绝不进行瞬态重试，不为代理阶段另加无界重试。

## 验证范围

验证分为严格配置与路线身份测试、真实字节协议测试、代理转发实际 SSH 的集成测试，以及 GPUI 连接/认证/取消回归。恶意或畸形代理响应、分段响应、头与 SSH banner 同包、超时、取消、跳板后代理、凭据串用、旧信任和旧 vault 的隔离都属于必要回归。

原生 macOS、各平台自动测试、真实服务互通分别记录，不互相替代。当前设计不包含 HTTPS 代理、SOCKS4、NTLM、Kerberos、PAC、外部 ProxyCommand 或代理密码持久化。

协议依据：[SOCKS5 / RFC 1928](https://www.rfc-editor.org/rfc/rfc1928)、[用户名密码认证 / RFC 1929](https://www.rfc-editor.org/rfc/rfc1929)、[CONNECT / RFC 9110 §9.3.6](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.6)、[HTTP 消息语法 / RFC 9112](https://www.rfc-editor.org/rfc/rfc9112)、[Basic / RFC 7617](https://www.rfc-editor.org/rfc/rfc7617)。
