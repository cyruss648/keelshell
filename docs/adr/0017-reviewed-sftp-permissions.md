# ADR 0017：审核式 SFTP POSIX 权限修改

- 状态：已实现
- 日期：2026-10-03

## 背景

远程文件列表已经显示服务器返回的 POSIX mode，但文件面板缺少修改入口。直接把输入转成 shell 命令会引入 shell 解释、目标漂移和符号链接跟随风险，也无法清楚地向用户说明实际修改范围。

## 决策

文件面板增加独立的八进制权限输入和“改权限”操作。点击后先校验三位或四位八进制数字，再保存所选远程条目的不可变路径与 mode，显示包含路径、mode 和属性边界的双语确认条。确认后，后台 SFTP 层只发送 `SETSTAT` 的 `permissions` 字段；不会发送 owner、group、size 或时间字段。worker 在执行前再次拒绝符号链接，避免跟随链接修改目标。完成后显示待刷新状态，不自动把新的目录快照绑定到用户正在编辑的路径。

允许的 mode 范围是 `0000` 到 `7777`，包含 POSIX special bits。ACL、扩展属性、所有权、组和服务器自身的继承策略不在本操作范围内；服务器拒绝或超时遵循现有 SFTP 未知结果提示，用户必须检查后再重试。

## 验证

- session 回环 SSH/SFTP 测试确认文件内容大小不变、mode `0644 → 0640`，并拒绝 `10000`。
- GPUI 文件面板测试确认真实“改权限”按钮生成确认条、执行后实际 mode 为 `0640`，状态要求刷新。
- 纯单元测试覆盖三位 shorthand、四位 mode、非法数字、符号模式和 shell 字符串。

证据见 [SFTP 权限验收记录](../testing/records/2026-10-03-sftp-permissions.md)。

## 未覆盖边界

本决策不提供递归批量权限、ACL 编辑、owner/group 修改、Windows 原生权限映射、符号链接目标权限或文件差异预览；这些能力仍需独立设计和验证。
