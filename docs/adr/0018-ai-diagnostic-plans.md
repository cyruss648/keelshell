# ADR 0018 — 可追溯的 AI 诊断计划

日期：2026-10-03。状态：接受；实现与验证见[专项记录](../testing/records/2026-10-03-ai-diagnostic-plans.md)。

## 决策

助手回复可以由用户明确点击“整理为诊断计划”。应用只从回复中提取已经闭合的 `sh`、`bash`、`zsh`、`shell`、PowerShell 或 `cmd` 代码块；普通正文、JSON 代码块和未闭合代码块不会进入计划。计划最多包含 8 步，每步最多 16 KiB，超过边界时整个计划被拒绝。

计划绑定创建时的主机标签、活动 SSH 会话标识、用户主动选择的上下文摘要和模型回复摘要。摘要使用 SHA-256 指纹保存，计划不保留原始终端内容或完整模型回复。每步记录回复中的起始行和精确命令字节，供用户核对来源。

应用根据有限的只读命令白名单给出“只读候选”标签。遇到 shell 运算符、重定向、未知程序或可能改变状态的选项时标为“需要重点审核”。标签只是提示，不是安全结论；所有步骤都要送入现有命令审阅流程，审阅票据再次绑定计划、目标会话和有效期。

## 安全边界

`keelshell-ai` 不执行计划、不打开 SSH 通道、不发起新的模型请求，也不把计划当作批量执行授权。送入命令审阅区只填入可编辑的命令草稿，最终执行仍由原有工作区流程和用户明确操作决定。会话重连、主机切换、上下文变化或计划修改都会使旧计划失效；没有闭合 shell 步骤的回复不会生成空计划。

模型输出和风险标签都不代表远端事实。摘要只证明计划来自某次本地快照，不能证明命令已执行、输出正确或远端状态未被其他进程改变。

## 取舍与后续

选择本地结构化解析，是为了先提供可验证的审阅链而不增加新的远程执行协议。当前计划按回复中的代码块分步，尚未提供依赖图、跨主机编排、逐目标参数映射、定时运行或持久化审计；这些能力需要独立的任务模型和更严格的用户界面审核。
