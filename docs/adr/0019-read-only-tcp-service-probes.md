# ADR 0019：审核式只读 TCP 服务探测

日期：2026-10-03

状态：已实现，等待整合门禁

## 背景

监控面板可以读取 Linux 的监听 TCP/UDP 行，但监听行只能说明内核存在绑定，不能说明服务当前接受连接。远程运维需要一个可审核的最小连通性检查，同时必须继续保持 SSH-only：网络动作由已认证的远程主机发起，桌面端不直接访问目标服务。

## 决策

在 Linux 监控面板中为每个 TCP 监听行增加显式“探测”动作。动作只使用刚读取的监听地址和端口，并在 SSH 连接上执行固定的 `nc -z -w 2` 检查：

- 只允许 `tcp` 行；UDP 行没有等价的无副作用健康语义，因此不提供按钮。
- 地址只接受数字/主机名、IPv4/IPv6、接口 scope、点号、冒号、下划线和连字符；端口必须是 `u16`。通配地址映射到远程回环地址。
- 远程命令只检查 TCP 握手，不发送应用层 payload；`nc` 缺失、目标系统不是 Linux、输出格式异常或 SSH 超时都显示为失败。
- 探测前重新读取监听表并要求选中的完整行仍然存在；端口被复用、地址或进程信息发生变化时拒绝探测，要求用户刷新审核。
- 命令设置两秒连接等待并由 SSH 会话总 deadline 再次限制。`nc` 的非零状态保留为可审核结果，不自动重试、不改变服务状态。
- UI 将结果绑定到原始 socket 行和当前 SSH 会话。刷新监听列表会清除旧结果；切换/关闭会话不会把结果转移到另一主机。

## 取舍与边界

成功只证明远程主机完成了 TCP handshake，不能证明协议、认证、应用就绪、TLS、UDP 或外部网络可达性。`nc` 的实现差异由能力检查显式报告；不会静默退化为本地探测或执行用户命令。

## 验证

解析器覆盖成功/拒绝状态、IPv4/IPv6/通配地址和 shell 元字符拒绝。Session 回环夹具验证固定命令、状态解析和零 payload；GPUI 回归通过真实“端口 → 探测”按钮检查结果只显示在当前面板。完整整仓与跨平台 Quality 仍由整合提交记录。
