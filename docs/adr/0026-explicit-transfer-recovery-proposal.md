# ADR 0026：失败传输的显式恢复建议

日期：2026-10-04

状态：已接受

## 背景

SFTP 传输已经支持有界暂停、取消、内容校验和人工续传。传输失败后，用户还需要重新填写源与目标才能检查部分结果，容易丢失上下文。与此同时，网络失败、超时和取消都可能留下远端或本地的部分输出，应用不能把“失败”解释为“可以安全重放”。

## 决策

失败的实际传输在当前文件面板中保留一个内存恢复候选。候选只包含已审核传输的源、目标、方向和文件/目录类型，并带有当前已认证 SSH 会话令牌。用户点击“检查并续传”后，应用只启动一次新的只读续传计划：

1. 重新读取源和已有目标，校验路径、大小及内容前缀；
2. 在确认栏展示新的计划，等待用户再次确认；
3. 仅确认后的计划才进入传输队列。

恢复候选不会持久化，不保存命令、输出、凭据或主机密钥。面板挂起、断开或跨越会话令牌后候选立即失效。取消和失败保留候选，便于用户先检查远端结果；成功完成后删除候选。

## 取舍与边界

- 当前实现是显式恢复建议，不是自动恢复；没有后台重试，也不会在连接重建后自动重放旧写入。
- 传输队列仍是单工作线程 FIFO。并行队列需要独立的 SFTP 通道隔离、带宽和失败策略，不能通过复用当前句柄实现。
- 续传计划使用现有的源/目标内容校验和会话绑定能力，无法恢复已被用户删除或被其他程序修改的部分目标。
- 恢复建议只在当前活动文件面板中存在；应用重启后必须重新选择源和目标并重新审核。

## 验证

- `cargo check -p keelshell-app --locked`
- `cargo test -p keelshell-app --locked -- --test-threads=4`
- 单元测试确认：已开始的上传/下载可产生恢复候选，纯计划操作不会产生候选；当前应用测试共 260 项通过。
