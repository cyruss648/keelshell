# ADR 0031：有界内容校验与审核式目录同步计划

日期：2026-10-04

## 背景

元数据比较可以发现大小或修改时间变化，但跨主机时间精度、时区和传输过程可能让结果保持待复核。目录同步还需要明确记录复制与删除动作，并保证任何执行前都经过用户审核。

## 决策

- `keelshell-core` 为调用方已读取的文件字节提供 SHA-256 摘要函数，单文件最多 64 MiB。核心层不读本地或远程文件；本地与 SFTP worker 必须自行执行有界读取并把摘要附加到 `DirectoryEntrySnapshot`。
- 两侧都提供相同摘要时，摘要相等可以证明文件内容相同，即使修改时间不同；摘要不同时报告 `Changed`。只有一侧提供摘要时报告 `Uncertain`。旧的纯元数据快照仍按原有规则比较。
- `plan_directory_sync` 只把比较报告转换为稳定排序的复制/删除操作，不执行任何写入。复制操作同时绑定规划时的源和已有目标类型、大小、摘要；删除操作绑定规划时的目标类型、大小、摘要，未来执行器必须重新读取并拒绝被替换的路径。`Uncertain` 行必须先补充有界内容校验；计划不会猜测应同步的内容。
- 计划显式区分左到右/右到左和保留/包含删除。删除操作默认关闭，启用后会作为单独的可审阅操作出现。
- 计划计算不透明 SHA-256 审阅指纹。用户确认指纹后才能得到 `ConfirmedDirectorySync` 执行回执；回执仍不携带写入能力，实际传输 worker 必须重新扫描、验证来源摘要和目标类型，并在 UI 中再次获得确认。

## 安全边界

- 路径继续使用比较引擎的相对路径边界；核心 API 不接收根目录或可执行命令。
- 摘要和计划均受固定的字节、条目和路径上限约束，不把整个文件内容保存在计划中。
- 网络中断、远端并发修改、权限、符号链接和跨平台原子替换仍由未来的 SFTP 执行器处理；本 ADR 不把计划视为已完成同步。
