# ADR 0046：短窗口的完整工作区终端预算

状态：已实现；本机专项结果与原生验收边界由整合记录追踪。

## 背景

完整工作区在 900×580 客户区同时呈现终端、多行命令、补全控件、四个命令动作与文件面板。英文动作换行后，常驻的双行补全区会挤压终端。原生截图暴露了这一问题；新增回归通过实际文件按钮加载生产 `FilesPanel`，经真实 TCP SSH/SFTP 创建目录及中文文件，并挂载生产监控组件，在修复前首先测得中文、AI 关闭场景的终端只有 72.5px。原来的命令入口矩阵使用命令库，未覆盖这一完整组合。

## 决定

- 客户区高度小于 700px 时，将补全基准目录、显式远端补全、取当前文件目录、读取 SFTP 起点置于单行。两个次要目录动作使用图标，保留中英文可访问名称与随语言即时更新的说明；目录输入也解释其独立于终端 cwd 的含义。
- 保留 64px 多行命令输入。短窗口移除命令条额外垂直留白，并使用 4px 间距与适量留白排列可换行命令动作；四个动作和执行按钮都完整可达。
- 文件工具区仍使用原有 `min(340px, 客户区高度×40%)` 预算，不缩小窗口下限，不修改 `FilesPanel` 内部布局、64px 浏览区或工具滚动机制。高度充足时继续呈现完整文字的双行补全区。
- 两种布局共用原有命令及目录输入实体、审核目标、revision 和相同查询回调。窗口、语言、主题及 AI 显示变化只改变排版，不创建查询、不填入或执行建议，不重建文件面板。

## 验证与边界

完整工作区回归覆盖 900×580、1440×900，中英文、明暗主题、AI 开关以及两种历史标签，共 32 个量测场景。每个场景同时要求终端至少 80px、浏览区至少 64px、真实 SFTP 首行完整垂直可见、工具视口至少 50px、命令输入至少 60px，并核对四个动作和所有补全控件位于各自可见区域内。

每个布局组合实际点击“文件目录”“SFTP 起点”和“远端补全”，完成受控协议读取、显示实际候选及关闭后恢复同一文件面板，核对命令正文、审核绑定和输入实体均保留。监控组件使用受控服务器的真实响应状态，不把该夹具的协议响应视为真实主机监控采样。布局检查不向任何终端注入命令。

候选显示沿用既有工具区域替换规则：临时折起文件面板，保留工具选择、输入和实体，关闭查询再恢复。另有 16 个实际结果场景使用 13 个真实文件候选，列表达到 144px，量测结果面板、终端、取消按钮并以平台滚轮验证最后一个候选可达；不声称候选与文件表格同时绘制。32 个文件场景终端实际为 89.5–284.5px，文件浏览/工具各为 85–139px，首行 28px、命令输入 64px；16 个结果场景终端为 100.5–403.5px。

该增量未改变独立文件面板的 176 个状态矩阵预算。根整仓门禁与新独立复审已通过；另建标准双程序 macOS 开发包，在真实 900×580 工作区完成中英文、明暗主题和 AI 开关八个组合，以及实际 SFTP 补全、末项滚动和关闭后恢复文件面板。源码、程序、原始截图与清理归属见[原生记录](../testing/records/2026-10-05-compact-workspace-native.md)和[整合记录](../testing/records/2026-10-05-workspace-workflows-integration.md)。这些证据仍不表示完整操作系统可访问性、Windows/Linux 桌面、真实主机业务或正式 Release 已通过。
