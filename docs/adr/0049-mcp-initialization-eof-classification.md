# ADR 0049：按成功初始化回复判定 MCP 输入结束

状态：已实现并通过新非作者独立复审，已整合至主工作区；根整合门禁与新源码 CI 尚待完成。

## 问题

stdio 的读写 actor 与 SDK 的启动 future 独立运行。客户端收到已成功 flush 的 `InitializeResult` 后可以立即关闭 stdin；此时 SDK 可能尚未重新消费写 actor 的完成通知。先响应关闭信号的启动选择会误报 `Startup`，虽然客户端已经收到有效初始化回复。

新确定性回归暂缓 SDK future 的再次 poll，观察真实 `InitializeResult` 成功写出，再关闭输入并等待读 actor 发布 EOF。修复前实际返回 `Err(Startup)`。Linux CI 的未读 stdout 退出断言也失败，但旧日志未记录子进程 stderr，不能将新探针的具体错误追溯为旧失败的已证实原因。

## 决策

写 actor 仅在官方 typed `InitializeResult` 完整写入并成功 flush 后记录连接内的完成位。启动被中断时，先停止并等待自有 I/O actor，再读取该位和终态；已经确认的初始化回复加正常输入 EOF 可以正常退出。先 join 防止仍在同步 `poll_flush` 内的 writer 尚未发布完成位时误判。

不改变共享关闭信号的优先级、认证策略、队列与帧预算，也不排空或执行客户端关闭后剩余的工具请求。初始化前 EOF、预初始化 ping、元数据错误回复及 I/O 错误、帧预算耗尽继续失败。只有成功回复写出不会隐含任何桌面授权。

所有停止与 join 仍遵循既有两秒截止；进程测试保持 stdout 开启且未读取，在既有三秒范围内等待退出，并在失败时附带静态诊断以便后续 CI 定位。

## 验证边界

回归使用真实锁定 SDK 与受控内存流，另有实际 stdio 子进程套件。源码行为验证与目标 Linux CI、桌面 GUI、供应商客户端互通分别记录，不相互替代。
