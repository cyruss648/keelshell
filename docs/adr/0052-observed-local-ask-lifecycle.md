# ADR 0052: 单次本地 Ask 的有界生命周期观察

- 日期：2026-10-06
- 状态：已实现并通过独立复审与主树完整工程检查；新版原生窗口验收待完成

## 问题

本地 Ask 的版本与能力检查、启动、输入交付、协议读取和进程清理此前只有最终答复。等待期间用户无法判断当前已经发生了什么。将供应商的原始流直接显示成步骤，会泄漏内容、误认工具操作或把结束回执当作成功。

## 决策

AI 库新增 `LocalAskStage`、一次性 `LocalAskProgress` 和 `LocalAskProgressReceiver`，原 `ask` 保持兼容并且不分配观察通道；`ask_with_progress` 消费本次请求的生产者。每次最多八种静态事实：隔离工作区已创建、进入版本/能力检查、检查通过、推理进程实际启动、完整 stdin 写入并关闭、严格协议开始回执通过、结束回执通过、进入收尾。没有供应商字符串、路径、问题、回答、密钥或工具事件。

16 槽同步通道只使用 `try_send`，原子位图保证每种事实仅观察一次。容量大于全部合法事件，未读、慢读或关闭的接收端不会阻塞 Tokio、影响协议、改变结果或拖延取消。输入交付不证明服务已消费；协议事件仅在完整 JSONL 帧通过适配器校验后发出。收到结束回执仍可能遇到后续非法帧、非零退出、取消或清理失败。

写入、读取与 leader 退出并发，事实不是线性步骤、百分比或工具编排。leader 退出可能先触发收尾，随后才读到缓冲中的结束回执；界面不会补造未观察到的阶段，也不会从收尾回退为等待协议。没有成功事件。完整协议、成功退出、自有子进程清理和临时目录删除全部通过之后，最终 `Result` 才允许显示答复与命令候选。

前台桥使用 GPUI 自有计时器轮询有限进度和单槽结果，不在 Tokio 线程注册 GPUI waker。进度绑定 revision、主机与 SSH 会话，只有仍在等待的精确所有者可修改记录。修改问题、配置、上下文、会话或取消会撤销审核、清空历史并丢弃前台接收端；面板销毁保留取消令牌行为。迟到进度与结果不得覆盖新请求。取消提示只确认已经请求取消，不确认后台清理已完成。

界面固定进度摘要和取消按钮，默认折叠最多八条事实；展开记录独立滚动，使用明暗语义颜色并在渲染时读取中文/英文。最终答复仍留在正文滚动区，命令继续经过原来的人工审阅入口。

## 范围与验证

不改变空工作目录、环境隔离、固定 argv、显式凭据、单轮限制、协议工具拒绝和远程命令审阅。不新增订阅登录、工作目录/环境编辑、Agent 工具步骤或第三方 MCP 客户端；对外 MCP 服务方向保持。

正式回归覆盖两适配器自有 Rust 子进程：final gate 前进度可见但结果未完成、end receipt 后非零/取消/持管后代清理、未读/关闭接收端、版本/能力拒绝和乱序/畸形/工具/迟到帧。真实 GPUI 测试覆盖前台桥、过期 revision/session 拒绝、交错收尾、取消清空和 900×580 的 320px 助手列中英/明暗/记录滚动/命令审阅。工程门禁、独立审查和原生验收分别记录，不能将测试平台窗口布局当作供应商或原生验收。见[测试记录](../testing/records/2026-10-06-local-ask-stages.md)。
