# ADR 0056: AI 回复的命令审核目标与不可用入口

- 日期：2026-10-06
- 状态：已采纳；主线整合及完整门禁通过，新非作者代码与macOS限定原生证据复核通过

## 问题

没有 SSH 上下文的普通回复仍可能包含 shell 代码块。原助手将回复绑定到生成时的主机/会话，命令库也会拒绝缺少目标的提案，但“送入命令审阅区”按钮仍可点击。拒绝提示位于长回复上方，用户在按钮附近无法看出缺少什么。切换活动终端也不能成为将旧回复重新绑定到新会话的理由。

## 决策

在助手 UI 内根据 `response_target` 判断目标状态：未绑定、信息不完整/无效、与当前捕获上下文不一致、可审核。主机和会话必须非空白且没有 NUL；只检查可用性，不修剪、改写或替换捕获的值。回复及每个审核入口显示本回复捕获的 SSH 主机和会话；不可用原因以中文/英文贴近控件显示，并在渲染时跟随当前语言和主题。

普通建议、诊断计划构建与诊断步骤审核共用该状态。不可用或仍在等待时，按钮禁用；处理函数也再次拒绝直接调用或过期交互。诊断计划从回复捕获的目标建立，步骤计划的目标必须与该捕获目标相等。主动重新选择上下文仍走既有请求撤销流程，清空旧回复/建议/计划；迟到结果不能恢复它们。

有效入口仍要求一次明确的人工点击，并保留现有 `CommandProposal` 和单次审核票据。发出的事件携带原会话 ID。Workspace 的生产订阅者继续检查当前活动终端是否为该会话，拒绝其它会话并保留已有命令草稿。只有用户明确选择原终端并点击后，精确文本才进入可编辑命令栏；填入本身不执行命令。

固定的在途进度/取消栏保持既有布局，回复和候选继续在正文滚动区完整呈现。此修复不自动捕获上下文、发送请求、执行 shell、扩大模型授权或改变既有等待期限和验收断言。ProviderConfig 装配、核心/推理参数不属本切片。MCP 方向仍仅为 KeelShell 向外部智能体提供服务，不新增内部第三方 MCP 客户端。

## 验证边界

专用 GPUI 回归覆盖空白/部分目标、中英文禁用原因、程序性拒绝、精确人工提案及诊断步骤、陈旧捕获目标、上下文重新选择和迟到结果。Workspace 回归通过两个确定性终端传输实体，实际点击捕获/切换/审核控件，证明当前终端检查仍生效、拒绝不覆盖草稿且没有终端写入。最小布局测试覆盖 900×580、320px 助手列、中英/明暗/进度折叠与展开、长回复后的目标原因和审核按钮可达。

GPUI 测试平台的窗口与通道夹具不等于实际 SSH、原生桌面、供应商 CLI 或模型验收。作者门禁、原失败、独立复审及原生范围见[测试记录](../testing/records/2026-10-06-ai-command-review-target.md)。
