# ADR 0057 — Windows 小栈控制器的整体测试预算

日期：2026-10-06。状态：已采纳；新非作者审查及精确源码三平台 CI 通过。

## 依据

源码 `2f7ca1ee4a3abc248bc76e30eac1911110b5c76f` 的 [Quality 37377310693](https://github.com/cyruss648/keelshell/actions/runs/37377310693) 已结束：Linux、macOS 成功，Windows 额外小栈入口失败。Windows 默认控制器完成全部 626 条阶段记录，耗时 73.497253 秒；38 次原 TCP 探测中，26 次实际返回 `ConnectionRefused` / Winsock 10061，合计耗时 52.451005 秒。额外 2 MiB 入口采用同一完整控制器，却只有 45 秒整体预算，在第 371 条记录中确认期限到达。

仅关闭端口探测的已观察耗时就超过整个 45 秒预算，因此该预算不足以覆盖 Windows 上的这组完整行为检查。日志没有网络包捕获，不把两秒等待进一步归因于某个内核重试算法，也不追溯更改此前未记录阶段的失败根因。

## 决定

Windows 的额外小栈整体测试预算改为 90 秒；其他平台保留 45 秒。默认入口仍按原方式运行。所有 Ask、取消、协议、进程清理等具体用例的期限、断言、fixture 字节、TCP 调用和 2 MiB 栈保持不变；测试仍执行两种 CLI 适配器及完整控制器。没有增加产品等待期限、重试或修改供应商行为。

不把连接超时当作端口已经关闭的证据，不跳过 Windows 小栈入口，也不因其更慢而减少用例。无需更改系统 TCP 配置、引入 Windows FFI 或增加依赖。

## 验证与限制

候选的本机完整门禁、独立审查及新 Windows CI 分别记录在[测试记录](../testing/records/2026-10-06-windows-small-stack-budget.md)。精确5b6b7b4的新 Windows 默认与额外 2 MiB 控制器已实际完成全部626条记录、38次TCP及原覆盖，小栈耗时69.283210秒；本项测试预算修正通过。macOS编译或测试不替代该 Windows 结果。此次源码 CI 也不证明 Windows 桌面、供应商 CLI 或安装更新已验收。
