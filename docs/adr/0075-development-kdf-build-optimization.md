# ADR 0075：开发与测试构建的 Argon2 依赖优化

- 状态：作者及新的非作者限定复核通过；主线组合门禁、提交级 CI 和原生验收待完成
- 日期：2026-10-07

## 决策

仅为 `argon2` 依赖添加 `[profile.dev.package.argon2] opt-level = 3`。其余开发配置、锁定依赖、生产源码和 release 配置不变。Cargo 的 test profile 默认继承 dev，因此普通测试也使用这一依赖优化；debug assertions 和 overflow checks 是独立设置，不在本决策中关闭。配置语义以 [Cargo Profiles 官方文档](https://doc.rust-lang.org/cargo/reference/profiles.html) 为准。

凭据库和配置同步继续使用原 Argon2id、64 MiB、3 次迭代、单通道策略。密文格式、随机盐、认证与错误密码拒绝、乐观审核绑定及保存冲突规则不变。不会通过降低 KDF 成本、减少安全检查或放宽测试期限来获得收益。

## 实测依据

同一核心源码和锁定依赖在单 CPU、2 GiB、无网络、自有 Linux ARM64 容器中，分别运行原 debug 与仅 Argon2 依赖优化的成本探针。每组创建空 vault、读取已有共享密文和批准已有共享密文各三次，中位数分别从 1.150373、1.154786、2.313371 秒变为 0.487518、0.500097、0.998367 秒，约为原速度的 2.31–2.36 倍。探针检查批准结果实际保存，并检查 peer 本地元数据未写入固定测试明文密码。

这是开发构建体验的独立性能证据。历史 `e69575b` Linux CI 的 18 秒批准等待失败没有后台阶段记录，根因仍未知；上述 ARM64 容器测量不代表原 Linux x86 CI 或桌面环境。新的测试专用八阶段观察器用于下一次失败时区分排队、核心计算和前台交付，不改变运行行为。

## 验证与边界

回归必须包括 vault 的现有密文兼容、错误密码与篡改拒绝、保存冲突及权限检查，以及双客户端配置同步、取消、冲突和恢复。应用保留原 18 秒批准和 45 秒捕获定时流程、审核后的全文磁盘断言及既有认证 SSH 路由检查。格式、x.y 依赖策略和 workspace all-targets 严格 Clippy 另行记录。
