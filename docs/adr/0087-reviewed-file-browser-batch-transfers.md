# ADR 0087：按当前选区审核的批量 SFTP 传输

状态：候选实现，2026-10-08；工程、独立审查和目标平台原生验收分别记录，未提交。

## 决策

本地栏只服务远程 SSH 的 SFTP 来源／目的选择。两侧条目提供真实 checkbox，普通行单选，Ctrl／Cmd 切换，Shift 按当前可见排序选择范围；每侧最多32项。状态按原生路径保存，排序不改变对象身份。隐藏项目移出选区，导航或刷新清空选区，不自动选回隐藏或以前目录的项目。多选时单项改名、删除、权限、填框等动作失去唯一目标并停用；目录导航仍可用。

批量入口先准备只读计划，再复用原完整两轴审核正文和固定批准／取消。每目标展示完整来源、目的、确定字节数、是否覆盖及目录项数。拒绝项与原因完整保留；用户明确批准的只是同一审核中标为可传输的子集。没有可执行项时不能批准。准备上限32项、合计16 GiB、30秒协作预算；特殊文件、链接、越界、不可移植名称、重复或大小写别名拒绝。

计划绑定SSH session token、当前实际目录、完整本地／远程选区和浏览审核revision。绘制的批准回调还捕获不可变plan ID；取消后重新准备、旧绘制回调或改变会话／目录／选择均不能批准新计划。一次UI事务将全部批准的精确目标加入已有32项queue ledger；每目标各有原有后台owner、进度、暂停、取消、结果与隔离，不改变FIFO、并发或未知结果语义。关闭／重连撤销原owner；已经发出的写入保留实际结果。

目录继续用原绑定SSH handle的完整扫描计划及执行前重扫；整棵目录不是原子事务，逐项传输，失败或取消保留已完成项。总审核与每个目录行明确展示此区别。新增FileTransferPlan是session层的只读文件观察：上传持有原本地source descriptor，独立metadata descriptor允许在实际发布前异步复核，无UI阻塞；执行前、句柄打开后及原子发布前复核来源、命名对象和审核中的目的观察。普通文件上传只经独占临时文件和POSIX原子发布，无降级覆盖；下载先检查远端已打开句柄，再create_new，仅新建本地目的。metadata不伪称完整内容快照；本次准备不读取／hash整个文件。

## 已知协议与平台边界

SFTP v3不提供原子版本／NOFOLLOW验证，远端mtime和metadata观察不能阻止所有外部并发改写；保持该边界。本地实际opened descriptor保留来源对象，外部原地修改仍只能按size／mtime等观察拒绝，不能宣称内容锁。Windows明确拒绝reparse point；目录既有计划的平台边界不因此关闭。

拖放未纳入本次实现：没有跨平台原生drag事件完整验证，保持FILE-02拖放OPEN。原生最小窗口、辅助技术、三平台桌面、真实标准包和自有OpenSSH流程仍分别验收；受控GPUI/TCP夹具不替代它们。

## 验证

见[候选测试记录](../testing/records/2026-10-08-file-browser-batch-transfers.md)和[操作指南](../product/FILE_BROWSER_BATCH_TRANSFERS.md)。旧测试组生命周期、120秒准入、四线程、原测试正文与清理屏障保持；不继承父提交工程通过为本次增量通过。

根完整门禁发现发布前文件metadata复核的嵌套future使普通原子上传future达到18,112B，超过既有16KiB限制。将该复核future在共享writer边界Box::pin，保持原await顺序和全部校验；修后原子上传10,272B、原子写入9,008B。可选审核分支也影响不带审核参数的共享writer类型，不能以None调用推断没有布局成本。原阈值和测试保持，32项SFTP库、6项审核TCP、4项原子TCP及严格Clippy通过只作为限定结果，新的完整组合和独立复核仍OPEN。
