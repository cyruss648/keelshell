# ADR 0095 — 可扩展的原生主题族

- 日期：2026-11-04
- 状态：已采纳并实现，工程与限定原生验收见本轮测试记录
- 范围：UI 主题、设置兼容、原生组件适配与终端默认颜色

## 背景

用户接受霜白、曜石、雾紫三种设计，要求全部内置，并降低以后增加主题的耦合。原有 `Settings.theme` 仅表达 System、Light、Dark；业务视图已经使用语义 Palette，但部分组件圆角和 Kit 组件颜色仍固定。

## 决策

1. 保留 `Settings.theme` 表达明暗策略，新增 `theme_family: ThemeId`。旧配置缺字段默认 `frost`，不会改变旧明暗选择。`ThemeId` 为受约束的字符串，不枚举 UI 产品主题。
2. app 内集中注册 `ThemeDefinition`：稳定 ID、中英文名称/描述、推荐外观、完整浅深色 Palette、组件形状、终端默认色。业务视图只读取语义 token；核心模型不认识具体主题列表。
3. 内置预设按钮明确标注推荐外观：霜白/浅色、曜石/深色、雾紫/浅色。点击预设一起保存主题族和推荐明暗；之后明暗模式可单独调整，三族均支持 System/Light/Dark。
4. 有效但未知的 ID 原样保留；显示回退为霜白，选择器说明回退原因。只有用户选择另一个预设才替换 ID。此行为支持未来主题和版本差异，不表示支持加载任意主题文件。
5. 单一 Kit adapter 映射按钮、输入、表格、列表、弹出层、侧栏、标签、状态色和焦点环。自定义面板使用同一 Palette/ComponentTokens。新增主题主要改定义与目录，统一测试自动覆盖新目录成员。
6. 复用 Workspace 串行后台 StateStore 保存。成功后安装整个主题快照；Conflict、Unknown 或写入失败不切换成未保存外观。启动、知识重载和配置恢复都应用完整设置。系统外观通知只更新视觉，不写配置。
7. 主题不拥有分栏宽度、显示哪些面板或密度。这些属于工作区布局；主题切换不得重建会话、输入/审核实体或重置草稿。
8. 终端的默认前景、背景、光标与选区可随主题变化。现有 ANSI、索引色、truecolor 和远端 OSC 覆盖继续优先；OSC reset 回到当前主题默认值，查询与渲染读取同一默认色。主题操作本身不发送远程命令。

## 扩展方法与边界

添加主题时在 `crates/keelshell-app/src/design/registry.rs` 定义两种完整 Palette 和形状，再加入 `registry()`。不向业务视图添加主题 ID 分支，不向 core 增加主题枚举。运行目录有效性/唯一性、六类颜色组合、Kit 适配、持久化与切换回归；在真实原生窗口检查主要工作流。

目前只提供内置主题，没有用户主题文件、主题市场、远程主题下载或主题脚本。文字对比度测试只验证自有颜色配对，不能证明所有远端自定义颜色、语法色、屏幕像素或辅助技术都通过。
