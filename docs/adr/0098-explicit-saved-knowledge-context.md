# ADR 0098：显式保存知识接入 Ask 请求审核

- 日期：2026-11-05（Asia/Shanghai）
- 状态：已实现；v2 源码再审、r2 组合门禁、限定 macOS 原生与最终证据复核通过，提交和精确 CI 另验
- 范围：保存知识选择 → `ContextDraft` → API / 本地 Ask 预览 → 明确发送

## 问题

知识库支持本地列表、搜索和审核修改，但保存条目尚无显式进入模型上下文的路径。原来源会话可能已经结束，历史身份不能被解析为当前 SSH 授权。已保存内容也可能在后来成为某个新配置的凭据匹配值，不能跳过发送时脱敏。

## 决定

1. 在 `keelshell-core` 增加纯内存 `SavedKnowledgeContext`。按完整条目相等性校验选择，不按主机名称匹配；最多 8 条，序列化后的记录合计最多 32 KiB。所有失败返回不包含正文的 typed error，拒绝时不部分修改选择。保留所有历史元数据，选择本身不可序列化，不隐式跨启动恢复。
2. 由现有知识库实体持有选择和独立的 UUID 版本。标题入口保留编辑行为，额外“加入/移出 Ask”操作明确表示附加。助手内的摘要、移除和清空控制位于现有滚动正文内；完整请求沿用现有可双向滚动预览与固定发送栏。继续使用 Frost / Graphite / Lavender 语义 token 和双语文案。
3. 每条记录作为带固定历史/不可信标签的 JSON 数据加入 `ContextDraft` 的用户选择区，不进入系统指令、不成为工具调用。使用现有 `SavedKnowledgeEntry` 准入敏感标记检查及当前凭据的请求脱敏链路；不改变原保存内容。
   独立审查 AKC-SR-001 发现结构化字段中的引号/反斜杠会先被 JSON 转义而避开字面替换。修正为 `ContextDraft` 在所有推理选项下均执行既有嵌套载荷凭据检查，再返回准备结果；原先该检查只在设置推理选项时执行。扫描使用全部已知凭据，非当前配置也参与。可还原的凭据仍存在时返回 `AiError::CredentialInContext`，不生成 API 或本地可审核请求，也不重写原来源字段。
4. 选择边界上限独立于模型预算。Ask 仍使用现有 16 KiB 输入预算和 API 声明的上下文限制；含知识时，只要最终 redaction report 有截断就不产生可发送请求。这避免部分 JSON 或丢失时间、结果的摘要被发送。空选择不额外附加内容。
5. API 和两种现有本地 CLI 共用上述组合。所选本地工作目录的后台验证继续使用原 cancellation / profile / session / request revision 机制，接受准备结果时再检验知识版本。CLI 启动仍只发生在确认发送后。
6. 准备、确认发送和完成回调均检查知识版本和条目当前性。每次新预览另生成审核 ID，按钮捕获该 ID；失败的预览尝试先移除旧预览。旧绘制的确认不能发送后来生成的内容。知识选择事件以当前实体状态校验，避免迟到的旧通知错误撤销已重新审核的新请求。
7. 已选条目编辑、保存开始、删除或版本变化撤销旧审核；失败保存进入 reload 流程。重载和配置恢复明确清空选择。普通主题/语言保存只改变配置快照时，完整条目未变即可保留选择。配置恢复增加一行助手审核撤销挂钩，不改变 Files 或工作区布局。
8. 保存知识限定为 Ask 附件。非空选择下 Agent 准备会拒绝，不把历史内容悄悄加入有执行授权的 Agent 回合。未来扩展需要独立设计其回合预算、来源和授权合同。

## 结果与边界

不增加依赖、数据库迁移、模型客户端、MCP 客户端或持久化字段。所有新选择和组合均为有界内存操作；存储 I/O 仍由 Workspace 的既有后台 StateStore gate 承担。原始来源可在无 live SSH 的情况下用于问答，但命令送审仍要求独立的有效当前目标。

跨进程外部写入只有在应用接纳新状态或明确重新加载时可见；此切片不增加文件监视器，也不在每次 Ask 时做隐式磁盘读取。取消只能拒绝后续结果，不能宣称已发送数据从模型服务撤回。

测试覆盖核心选取合同、GPUI 状态/旧绘制按钮、各协议预览、合成凭据脱敏、预算拒绝和本机 HTTP 精确正文/取消。测试源码、实际执行、原生操作与真实供应商各自验收；见[验证记录](../testing/records/2026-11-05-ai-knowledge-context.md)。完整应用目标仍未完成。

AKC-SR-001 作者回归在原实现上实际暴露 84 种组合：三种转义形式、四个保存字符串字段、三种 API 以及两种本地适配器各自的隔离/所选目录准备。相同最终测试源码在修正后通过。另由现有自托管 CLI 测试程序证明六次准备拒绝先于子进程启动、两种本地适配器各完成一次无敏感内容的真实 stdin 传输；不代表供应商 CLI 或桌面原生验收。原 HOLD 及 v1 补丁保留，v2 非作者源码再审已关闭该项。组合门禁和受控 macOS loopback 原生观察另见验证记录，真实供应商、完整原生矩阵和发布安装仍开放。
