# ADR 0101：原生分屏与会话归属

- 日期：2026-11-05
- 状态：原生源码接入候选；工程检查与实机验收分别记录
- 需求：TERM-02 / UI-04

## 背景

领域布局已合入，但成对分屏无法表达多层工作区。新增分屏不能改变命令、
文件、监控和 AI 所使用的真实 SSH 会话，也不能把重连后的新实体误放入
当前活动面板。现有三主题共用语义 token，不为布局增加主题分支。

## 决定

`Workspace.tabs` 继续持有终端实体及会话顺序，`SessionPanes<EntityId>`
只管理临时归属、各叶标签顺序与选择。`PaneLayout` 管理几何和稳定节点 ID。
新会话加入活动叶；分屏复用已认证连接打开独立 Shell 通道，primary 保持
活动，peer 独占新叶。全局及每叶容量分别校验，失败不发布部分映射。
分屏保留 primary 已选择或收起的工具区和现有面板实体；只有新连接默认打开 Files。

关闭标签先原子更新布局，再退休运行实体与其授权。空叶收拢，最后空叶保留。
“合并”将该叶标签追加到相邻存活叶，保留所有会话和原活动 key；目标叶容量
不足时拒绝，不关闭会话。重连以新 EntityId 原位替换旧 key，保持布局 UUID、
选择和位置；现有 MCP、Agent、命令审核与归档撤权规则继续执行。

原生渲染按已验证的有界树递归，使用 GPUI Kit standalone resize handle。
拖动携带工作区实体、节点、结构代次和弹窗输入代次；跨工作区、旧结构、
已开始弹窗或连接流程的拖动均拒绝。比例只修改布局，不直接向 SSH 写入。
首个移动在 capture-phase 监听之后才建立 Kit drag，因此创建 payload 时先应用
该次实际鼠标位置；与后续移动使用同一身份/代次守卫，不要求再有第二次移动。
每个分隔条持有独立稳定的焦点句柄，并显式启用句柄自身的 Tab 停靠规则。
左右分屏使用左右方向键，上下分屏使用上下方向键，每次调整目标比例 5%。
所有层级的分隔条都可独立到达，包括两个子节点均已继续分屏的根节点。
AX 暴露 Splitter、方向、目标比例、10%–90% 范围、5% 步长和双语操作说明；
Increment/Decrement 与键盘、拖动共用结构及弹窗代次检查。
鼠标拖动保留当前 SSH 键盘焦点；Tab 显式进入分隔条，并显示语义强调色。
叶内大小按钮继续提供直接父节点的快捷比例操作。

每个叶有最小可用区域。空间足够时显示完整树，对实际显示比例作最小尺寸
约束而保留用户比例；空间不足时仅显示活动叶，上方会话栏仍可切换。
手动“聚焦”也保留原布局。缩窗和聚焦不关闭隐藏终端，也不修改其授权。
被隐藏分隔条的焦点回到惰性工作区，不转移到 SSH；从弹窗返回时重新检查
原分隔条是否仍在可见布局内，避免将缩窗前的焦点恢复到已隐藏控件。

布局显式保存复用现有后台 StateStore 提交，只保存窗口/面板/标签 UUID、
几何、选择和可选连接 UUID。不保存运行 EntityId、连接地址、凭据、终端
输出、命令草稿、AI 上下文或审核能力。当前窗口替换自己的保存记录，其它
窗口记录保留并对完整文档重新校验。该增量尚不提供重启恢复或多窗口入口。

## 验证

模型测试验证事务性变换、身份、容量与重连替换。工作区测试通过真实 GPUI
布局和输入事件检验几何、焦点、关闭、合并、缩窗、保存及 SSH 重连。
这些是受控工程检查，不能替代原生窗口、操作系统输入或其他桌面平台验收。
实际结果、失败及独立审查见[本轮记录](../testing/records/2026-11-05-native-pane-layout.md)。
