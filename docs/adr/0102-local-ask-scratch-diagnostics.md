# ADR 0102: 本地 Ask 临时目录失败的有界观测

- 日期：2026-11-05
- 状态：实现、完整本机门禁及独立源码/文档证据复审通过；精确提交与平台 CI 单独验收

## 问题

基线 `77aa69c` 的 Linux Quality `41967541069 / attempt 1` 在本地 Ask
目录夹具 readiness 等待期间返回 `ScratchFailed`。同一个公开错误可以来自
临时目录建立、owned executable 目标写入、父进程启动准备或临时目录关闭。
关闭失败还可能覆盖此前的请求错误。原日志没有具体操作、errno、关闭前结果，
连失败的 held-cwd / wait 两个等待点也无法唯一确认，历史根因仍为 UNKNOWN。

用户界面不应显示私有路径、进程输出或凭据；增加直接日志 I/O 也可能改变
管道排空、取消和清理行为。需要在保持公开失败语义的同时补齐最小观测。

## 决策

新增可选、只属于一次 Ask 的 `LocalAskDiagnostics`，通过
`LocalAskProgress::with_diagnostics` 绑定，并由 `ask_with_progress` 消费。
未启用的普通 `ask` 和现有进度调用保持原行为。诊断不写文件、不上传数据，
不授权请求或远程动作。

事件只保留类型化的静态操作、`io::ErrorKind`、底层提供时的数字 OS 错误码、worker
join 类别，以及关闭前请求结果和 scratch 关闭结果的静态类别。
上下文错误仅归为 Context，不展开原错误；不保存错误 Display、路径、argv、
stdin、供应商输出、响应或凭据。
第三方 I/O 包装可能保留 ErrorKind 而不再提供原 errno；此时明确保留为空，
不从错误正文解析或猜测数值。

每次请求使用固定容量通道和总事件预算，只调用非阻塞 `try_send`。
内部 worker 可共享同一预算，公开生产者不可克隆或再次用于其它请求。
未读、慢读、丢弃接收端和超出预算都只影响观测完整性，不能改变请求结果、
增加重试、延长期限或阻止清理。最终结果仍按原规则判定：scratch 关闭失败
继续优先于此前结果，诊断中的“关闭前成功”不能被解释成完整 Ask 成功。

父进程观测 scratch 建立/关闭、目标副本 I/O 和 bootstrap 私有目录准备。
launcher 子进程不继承观测通道，其固定退出码仍由现有流程解释；不能把
子进程退出 77 直接称作父进程 ScratchFailed。平台专属操作按实际编译路径
分别验证。

## 夹具与证据

目录进程夹具为每个 readiness 等待点提供静态 case/kind，并为 held-cwd、
取消及启动 gate 使用各自请求的进度/诊断通道。输出推迟到原 Ask 已返回后；
写入失败不能替换原结果。目录计数和子进程 phase 读取有固定上界，不输出
目录项名称或完整事件正文。

回归应覆盖实际缺失 scratch 父目录、请求隔离、接收端丢弃/未读、并发预算、
错误正文脱敏以及关闭前结果保留与原失败优先级。测试日志、门禁、独立审查、
Linux 对照和精确 CI 分别记录。新成功不解释历史失败，也不关闭桌面或真实
供应商验收。

实现结果见[测试记录](../testing/records/2026-11-05-local-ask-scratch-diagnostics.md)。
