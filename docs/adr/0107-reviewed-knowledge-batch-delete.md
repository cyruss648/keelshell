# ADR 0107：本地知识库的审核式批量删除

- 日期：2026-11-06
- 状态：当前切片实现候选；定向测试通过，完整工程门禁和独立复核另记
- 关联：AI-04 本地知识领域边界、显式知识上下文

## 背景

本地知识库已经支持搜索、单条编辑和单条删除。条目是用户明确保存的事实
记录，包含正文、来源绑定、来源版本、会话身份、捕获类型、时间和原结果。
用户需要整理过期或重复的多条记录，但批量删除不能把条目 ID 当作唯一授权，
也不能误改 Ask 的上下文选择或当前编辑器草稿。

## 决定

列表增加独立的临时管理选择。每条记录的 checkbox 只表示待删除意图，
不加入或移除 Ask 附件，也不改变编辑器当前条目。选择最多 32 条；超过上限
后新增选择被拒绝并保留已有选择。搜索只影响可见列表，已选但被过滤的条目
继续保留，管理栏显示隐藏数量。

点击“审核删除”会捕获管理选择版本、配置快照、完整
`SavedKnowledgeEntry` 原件集合和一次审核 UUID。审核正文逐条显示 UUID、标题、
完整摘要、来源标签与 UUID、来源版本、原会话、捕获类型、时间和原结果。审核
正文可滚动，确认与取消固定在正文之外。每个操作回调都携带审核或选择版本；
选择发生 A→B→A 变化时仍生成新版本，旧绘制的 checkbox、审核、确认和取消
不能重新取得权限。

`keelshell-core` 提供无 I/O 的
`AppState::remove_knowledge_entries`。它拒绝空集合、超过 32 条、重复 ID，
逐条比较完整原件并拒绝缺失或变更，全部通过后才构造候选状态。候选保留剩余
条目的完整字节和相对顺序，保留原 snapshot revision，并再次进行完整配置校验；
任何错误都保持原状态不变。

Workspace 继续使用统一的后台 `StateStore` 保存队列。批量候选只产生一次保存，
保存成功后刷新配置消费者并清除已删除的管理选择；候选校验失败、保存冲突、
耐久性错误或普通 I/O 错误都清除审核并要求显式重新加载。不会自动重试、重放
旧集合或把配置备份当作安全擦除。

管理选择、Ask context 和编辑器使用不同的状态与 revision。批量删除开始保存时，
被删除条目会从 Ask context 移除并同步撤销过期请求；迟到的发送或模型回复必须
重新通过当前 context revision。主机、终端、SSH 会话和原始来源都不会因删除
而重建或执行远端动作。

## 取舍

32 条上限把一次审核正文、内存候选和单次配置写入控制在可检查范围内，同时保留
“全选后一次确认”的整理效率。删除前展示完整正文会增加审核长度，但能让用户
确认实际删除范围，避免只看标题或截断摘要。选择版本使用内存 UUID 而不是对
集合排序后比较，专门防止旧 UI 事件在 ABA 变化后复用权限。

配置备份继续由 `StateStore` 保留，因此当前记录删除不等于安全擦除；产品文案
明确这一边界。分类、跨设备同步、原 SSH 会话恢复和自动 runbook 仍属于后续
能力，不能由本切片隐式扩展。

## 验证和边界

核心定向测试覆盖 8 项：空/重复/超限的原子拒绝、缺失条目、每个可变字段变化、
重复身份、无效剩余配置、32 条删除后的顺序和磁盘读回、竞争 StateStore 冲突及
敏感字段反序列化边界。应用定向测试覆盖独立且有界的管理选择、过滤隐藏条目、
旧绘制动作、ABA、刷新/重载、保存失败、Ask 请求撤销、键盘入口、固定审核操作
区和三主题×明暗×双语显示矩阵；Workspace 测试覆盖取消零写入、一次批量保存、
重启读回、外部冲突和紧凑/宽窗口矩阵。

这些测试证明本地实现和受控 GPUI 行为，不证明已安装发行包、macOS 完整原生
辅助技术、Windows/Linux 桌面、远端同步或安全擦除。完整工程门禁、独立非作者
复核和后续提交归属以对应测试记录为准。
