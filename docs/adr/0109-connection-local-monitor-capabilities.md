# ADR 0109：连接内监控能力与可选项降级

日期：2026-11-06。状态：实施中，验收尚未完成。

## 背景

原资源采集把`df -Pk`与核心`/proc`数据放在一次失败链中：
可选容量命令失败会让有效CPU、内存和网络数据一并丢失。
进程与监听端口有各自的工具依赖，通用失败也不能可靠说明其原因。

## 决定

为核心资源、文件系统容量、进程列表和监听端口分别记录类型化能力。
状态由实际命令及固定解析器建立；命令缺失、选项不支持、权限不足、
格式异常、原因未知和SSH传输失败分别表示，不保存原始诊断文本。
无足够证据时不推断更具体原因。

容量采集仍位于固定资源脚本中，独立记录退出状态；
其失败不使有效核心样本失效。已确认不可用的可选命令在后续轮询中跳过，
用户显式重新检测后才重新尝试。传输故障不作为“命令不存在”缓存。
保留既有`Snapshot`构造形状，避免迫使无关消费者和历史模型同时迁移。

缓存由持有认证SSH连接的`LinuxMonitor`拥有，克隆共享该连接内状态；
新连接拥有新缓存。异步互斥保护观测，代次阻止暂停/重置前的任务更新新缓存。
能力报告携带不可由UI伪造的缓存身份、失效代次及修改版本；
外来连接、缓存变化或暂停撤权会使旧报告失效。
采样与完成投递仍受原十秒期限约束，当前报告可包含更早确认且仍有效的负缓存。
因此首次投递过期后，下一次新鲜刷新可以收敛到实际缓存状态，而不重跑已确认
不可用的命令，也不重写原检查时间。渲染只读取本地观测和实际年龄。

重新检测使用已有后台任务及取消/回收路径。
能力本身不安装工具、不提权、不授予网络诊断或进程控制的额外权限。
固定命令、输出上限和现有审核边界保留。

## 后果与验证

用户能区分零值、未检测、不可用及旧数据，可用项不受可选工具失败拖累。
能力只表示该次认证连接中观察到的接口，不能保证未来所有命令都成功。
缓存可能落后于远端安装变化，显式重新检测提供恢复路径。

专项应覆盖部分成功、原因分类、缓存及恢复、代次/过期、暂停零自动采集。
真实Linux、开发包原生及其他平台桌面分别验收；
当前结果从[本片记录](../testing/records/2026-11-06-monitor-knowledge-categories.md)接续。
