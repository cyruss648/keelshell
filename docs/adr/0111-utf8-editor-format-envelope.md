# ADR 0111：UTF-8编辑正文、格式外壳与精确保存字节

日期：2026-11-06。状态：已接受的源码候选设计；r3必要差分复审关闭三项P2，新的完整工程门禁通过；
原生验收未运行。2026-11-06 03:26 UTC父已导入r3；03:34 UTC与获批traceroute r2
装配为543项工程输入、21个源码路径。组合门禁与原生验收分别记录。

## 背景

远程编辑已具备完整常规文件 snapshot、草稿、合并、patch、完整保存审核、
保存前备份和目标读回。直接将带 BOM 的原始字节作为编辑正文，会影响查找和
patch 偏移；编辑器新输入的 LF 也需要按原均匀换行策略形成最终保存字节。
格式整理不得改变基线授权、原始备份、未知结果隔离或现有预算。

## 决定

core 新增纯类型 `Utf8TextDocument` / `Utf8TextFormat` / `TextLineEnding`，
正文与恰好一个文件头 BOM 分离，原始 snapshot 仍由调用方保留。
解码不丢失字节，不猜测编码；错误有类型且不包含正文。
公开 API 具有 rustdoc，不引入依赖或持久化格式设置。

`prepare_save` 唯一生成精确出站字节：单一 LF/CRLF 使用原策略，无换行使用 LF，
混合或 standalone CR 保持草稿原样；不强制 EOF 换行。dirty、完整审核、确认、
合并比较及读回使用相同的编码含义。查找和 patch 作用于不含 signature 的正文。
最终1 MiB预算包含 BOM 和 CRLF 扩张，4096行保存上限不变；只读观察不因行数
超限把未变动文件标脏。

正文与其格式解释必须成对采用。保存成功但有较新草稿时，更新raw基线并保留原草稿
及其原格式，不把已保存版本新探测到的BOM套到旧正文上。无后续变动时，可采用
新观察的规范正文与BOM。`retain_insertion_policy`在观察没有换行时保留已知插入
策略；显式重新打开仍直接使用新解码结果。合并采用只在所属远端外壳有BOM时
剥离一个signature，无BOM基线草稿中新加入的头部U+FEFF仍是正文数据。

app 保存 transient 格式外壳与重读闸门。后台 worker 执行读取、解码、合并和
远端 I/O，UI只管理状态与审核。BOM或保存策略不兼容时拒绝普通合并/保存，
必须显式成功重读再审；远端恢复原格式不撤销该要求。无换行与 LF 策略兼容。
采用普通合并只改变草稿及新观察基线，不能产生写权限。

## 写入确认的分层

沿用 session 既有备份与审核式原子替换，不修改生产 transport 协议。
原始 snapshot 完整字节及 size/mode/mtime 在备份与发布边界复核。
备份和目标顺序预留，避免把二者合并成一次占用而产生 `MutationBusy`。

备份写入成功 ACK 是继续目标替换的前提；运行时没有为备份增加独立完整读回。
目标发布 ACK 后，app 另外读取完整目标，以 `Vec<u8>` 全量相等判断是否可采用
保存基线；只核对长度、前缀或格式不足以成功。回读失败/末字节不同保留旧基线
与当前草稿，已完成备份保留，不自动重试、回滚或解除未知结果隔离。
loopback 中对备份的实际读回断言只是测试证据，不是新增生产保证。

SFTP观察不是CAS；普通rwx保留不代表 owner/ACL/特殊mode 或崩溃耐久性。
取消审核零写与发送后取消不保证回滚分别保留。

## 后果与验证

本方案只覆盖 UTF-8 BOM 和既有均匀 LF/CRLF 策略，避免编码猜测、格式目录、
独立设置菜单或备份管理框架。较新草稿、审核身份、完整基线及重读闸门继续
拒绝 stale/迟到授权。MCP预算仍为64 KiB，本片不扩大其权限。

r2新增 core7、app11、session3，共21个用例；专项去重42通过，历史不回写。

为3过；另增core插入策略矩阵回归。r3累计新增源码25条，受影响core8/app去重29，
共37条通过。r2完整门禁历史保留；r3另跑一次完整门禁，
