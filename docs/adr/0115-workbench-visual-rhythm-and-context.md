# ADR 0115：工作区视觉节奏与审核上下文

- 日期：2026-11-07
- 状态：已实现，工程门禁与原生桌面观察分开记录
- 关联：`docs/design/HALLMARK_NATIVE.md`、`docs/design/NATIVE_THEMES.md`、
  `crates/keelshell-app/src/design.rs`

## 背景

工作区的功能分区已经完整，但顶部工具栏、会话标签和命令审核区的视觉重量
不足。用户需要在很短的视线移动中确认三件事：当前应用工作区、当前 SSH
上下文，以及准备执行的命令目标。只有颜色和边框变化会让这些信息依赖记忆，
也会让空工作区与已连接工作区的层级不够清楚。

此前主题注册表只拥有颜色、终端默认色和圆角。新增主题如果要调整工作区
chrome 的几何节奏，视图必须重新加入字面尺寸，降低了主题扩展的独立性。

## 决定

1. 主题定义增加 `ChromeTokens`，集中承载工具栏、会话条、会话标签、底部
   工具条、命令输入、状态栏和分屏叶标题的高度。当前三个主题保持相同尺寸，
   以保留跨主题的肌肉记忆和紧凑窗口行为；未来主题只扩展注册表定义，不在
   工作区视图按主题 ID 分支。
2. 宽窗口工具栏显示 KeelShell 品牌标记和“远程工作台”副标题。宽度低于
   1280px 时自动隐藏品牌区，把空间留给操作控件；1280px 仍保留品牌区，但
   使用紧凑动作标签，避免设置组被推出工具栏。这只改变呈现，不改变任何
   action 或焦点顺序。
3. 工具栏中部显示“远程工作区”以及当前活动主机上下文。无活动连接时显示
   选择连接的真实空状态，不制造示例主机。紧凑工具栏为上下文保留有界最小宽度，
   标题和主机值使用单行省略，避免窄窗口逐字换行。
4. 命令输入左侧显示带边界的“审核目标”徽章。目标过期或属于旧会话时使用
   warning 语义色，其他情况使用 accent 语义色；执行按钮使用主题 primary
   变体，让唯一的主要动作具有稳定视觉入口。
5. 会话标签分别使用 `surface_active`、`surface_hover` 和 `surface_active`
   表达当前、悬停和按下状态，保留现有活动底边、关闭按钮和会话实体身份。

## 取舍

品牌区只在宽窗口出现，避免紧凑窗口通过缩小终端或命令输入换取装饰空间。
工作区几何 token 目前不随主题改变，先建立扩展边界，再由后续原生观察决定
是否需要主题专属密度。目标徽章复用现有审核目标和状态，不引入新的执行路径。

## 验证

`design::tests` 验证所有注册主题的 chrome token 合法，并验证 Kit 安装后
可以读取同一主题快照。`workbench_layout` 在 900×580、1280×840 和
1440×900 的三主题、双明暗、双语矩阵中测量品牌区、审核目标、会话条、终端
和工具区均在窗口内；会话标签与紧凑工具栏专项回归另记于测试记录。

这些测试证明受控 GPUI 布局和主题映射，不代表 macOS、Windows 或 Linux
桌面截图、输入法或辅助技术验收。原生边界必须使用实际安装/启动的应用另行
记录。
