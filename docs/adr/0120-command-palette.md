## 背景

工作台已经拥有连接、会话、分屏、文件、命令片段、批量任务、依赖工作流、隧道、
AI 和设置等多个入口。动作分散在顶部工具栏、底部工具栏、连接库和设置面板中，
窗口紧凑或用户主要使用键盘时，发现路径会变长。

需要一个统一入口来发现已有能力，同时保持远程操作和 AI 操作的审核边界。

## 决策

### 1. 动作目录与执行分离

快速操作中心只维护不可变的动作元数据和搜索结果。它不持有 Workspace 的实体、
SSH session、凭据或异步任务。选择结果交回 Workspace，由现有方法执行。

这样搜索层不会绕过连接、命令、文件、AI 或配置审核，也不会因为弹层生命周期
变化而保留远端权限。

### 2. 用上下文声明控制可见性

每项动作声明是否需要 SSH 会话和是否需要可操作的当前会话。Workspace 每次打开
或查询时生成最小上下文快照，过滤不可用动作并保留用户能理解的入口。

无会话时仍显示连接管理器、快速连接、主题和设置；需要远端目标的动作不会显示
为可执行选项。前一个/后一个会话动作还需要对应方向的真实标签边界，首个、末个
和唯一会话不会显示无效的切换入口。

### 3. 目标路由继续复用既有审核入口

快速连接动作打开一次性 SSH 连接表单，用户可以明确选择保存为连接配置；它不会
自动写入连接库。主机监控动作会同时打开导航区并选择 Monitor 面板。其余动作也
只调用现有 Workspace 入口，由目标面板继续负责连接、文件、AI、配置和更新审核。

### 4. 使用稳定的本地排序

搜索排序只使用本地动作元数据，标题前缀优先于标题包含，标题匹配优先于关键词和
说明匹配。同等级保持注册顺序，结果数量固定上限。

排序不联网、不读取远程终端、不调用 AI provider，也不把用户输入写入持久化配置。

### 5. 复用主题 registry 和焦点契约

快速操作中心只消费语义 Palette、组件 token 和当前语言。它作为
`ModalKind::CommandPalette` 纳入现有 modal focus/return-focus 机制，避免背景终端、
连接树或其他工具面板接收输入。

## 取舍与限制

第一片只发现和触发现有动作，不在快速操作中心内新增复杂编辑器、连接表单或命令
执行器。新建窗口、分屏和布局保存暂时继续使用工具栏入口，后续只扩展动作注册和
Workspace 映射。真实 SSH、文件写入、AI 请求和设置写入仍由原有审核路径负责。

headless GPUI 测试可以验证焦点、动作标签、布局边界和执行路由，但不能替代原生
macOS/Windows/Linux 的完整键盘、IME、VoiceOver 和像素验收。
