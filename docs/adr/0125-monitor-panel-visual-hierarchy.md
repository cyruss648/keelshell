# ADR 0125：监控面板视觉层级与紧凑几何

- 日期：2026-11-14
- 状态：已实现；本地定向 GPUI 回归、完整工程门禁和固定源码独立复核通过
- 范围：主机监控 panel 的控制区、资源卡片、网络/端口行、能力状态和磁盘设备选择器
- 关联：[响应式工作台](0124-responsive-workbench-polish.md)、[测试记录](../testing/records/2026-11-14-monitor-panel-visual-polish.md)

## 背景

主机监控已经提供资源、进程、网络、监听端口、文件系统容量、磁盘 I/O 和 Linux
能力状态，但各区的视觉层级较弱。控制状态、采样对象和诊断动作混在同一条窄栏
中，长英文能力文案和末条磁盘设备在 260px rail 中还容易破坏可读 bounds。

本片只调整监控面板的呈现、无障碍语义和受控布局。采样命令、缓存、暂停/恢复、
进程审核、端口探测和磁盘选择的业务状态机保持原有实现。

## 决定

### 使用语义 token 建立面板层级

- 控制区显示主机、当前采样状态和操作组；状态颜色只读取当前 `Palette` 的
  `success`、`accent` 或 `warning`。
- 资源指标使用 `surface`、`border`、组件圆角和主题资源色；容量条继续使用
  `Palette::resource`，不写入主题 ID 分支。
- 网络接口、监听端口和能力行使用卡片或分组层级；每个分区通过现有主题
  registry、Palette 和组件 token 渲染。

### 保持窄 rail 中的真实可达性

- 监控根布局继续固定为 260px，外层内容使用既有 `monitor-scroll`。
- 磁盘设备选择器固定为 160px 高度并保留独立滚动；设备按钮采用紧凑连续列表，
  让最后一行可以完整进入选择器视口并实际点击。列表布局不使用会使 GPUI 内层
  滚动最大位置留下半行裁剪的额外 gap。
- Linux 能力行把状态徽章和检测年龄放到详情列的元信息行。长英文状态在窄栏中
  继续保持单行徽章，能力名称在自己的可伸缩区域换行，避免 flex 宽度争用把
  单行撑成不可滚动的超高卡片。

### 保留辅助技术语义

控制区、操作组、各监控分区和网络接口公开 `Group`；指标、状态、探测结果和能力
行公开 `Label`；动作继续使用 `Button`。可见短文案与双语 AX label 分开维护，
操作不会依赖颜色单独表达状态。

## 后果和边界

监控面板在窄窗口中更容易扫描，采样状态和诊断动作的关系更清楚，末条设备和
长英文能力状态仍可通过受控 GPUI 滚动到达。磁盘设备列表的行间距更紧凑，以保证
设备选择优先级和点击命中区域。

本片没有新增依赖，也没有改变远端命令或凭据边界。headless GPUI bounds、事件和
AccessKit 结果不代替 macOS、Windows、Linux 原生窗口、IME、VoiceOver/NVDA、
真实远端采样、Podman 联调或像素级验收。
