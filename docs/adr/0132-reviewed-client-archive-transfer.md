# ADR 0132：审核式客户端归档传输

- 日期：2026-11-15
- 状态：已接受；客户端实现和独立源码复核完成，工程及原生验收见测试记录
- 对应需求：FILE-05 的客户端归档增量

## 决策

文件面板提供两个真实流程：将本地多选文件、目录打包为 ZIP 或 tar.gz 后上传；
下载一个远端归档并解包到新的本地目录。客户端编解码不依赖远端 shell 工具。
服务器端打包、能力探测、Zmodem 和中继测速仍是独立开放需求。

`keelshell-core` 负责纯内存、有界归档编解码与可移植成员校验；
`keelshell-session` 负责源快照、SFTP、资源预留和新目标发布；
`keelshell-app` 负责选择、草稿、只读准备、完整审核及显式确认。
文件系统、压缩与网络工作均在现有后台 worker。

准备阶段最多读取 32 个本地选择，归档最多 64 MiB，展开内容最多 128 MiB，
最多 2048 项、32 层、单路径 4096 字节，完整成员名累计最多 48 KiB。
源路径、每个成员的类型、完整路径和字节数、压缩及展开字节数、准确目标
全部进入审核；不截断清单后继续执行。

归档只接纳普通文件和目录。拒绝链接、reparse point、特殊文件、加密条目、
非 UTF-8 名称、绝对路径、路径穿越、Windows 不可移植名、重复、
大小写别名及文件与祖先冲突。解码贯穿实际展开量限制与完整性校验，
不恢复可执行权限、所有者或归档中的特殊权限。

审核计划绑定当前 SSH 连接、浏览目录、选择、格式和目标草稿。
导航、选择或连接变化使旧审核失效；确认前还会重新读取源并比较完整快照。
准备、取消和主题切换均不发布目标。执行沿用 mutation reservation、
当前授权和未知结果隔离，不能将取消或连接丢失解释为没有写入。
目标必须是新归档文件或新目录，发布不静默覆盖已有目标。
本地解包使用同父私有 staging 与新目录发布；远端上传使用独占临时文件，
并完整读回发布结果。协议及操作系统的竞争边界必须随实现和测试如实记录。
本批本地解包依赖 macOS/Linux 的原子 no-replace 目录发布；Windows 的安全
发布后端尚待实现，界面明确停用解包并说明原因，打包上传仍可用。

临时归档仅用于当前审核，不加入持久恢复日志；重启后需要重新准备和审核。
未知发布结果不自动重放，不自动删除无法确认归属的文件。

## 原生设计

使用现有传输披露区承载归档设置，保留双列文件浏览的主要空间。
格式选择、远端归档名称和本地新目录均有明确双语标签及可访问名称。
审核正文独立滚动，确认和取消仍在固定动作区。
三套主题共用 registry、Palette 和组件 token，不增加主题 ID 业务分支。

## 验证与交付

实现按 core、session、app 的独立写集并行；开发中做必要编译和安全专项。
集成后集中执行完整门禁、协议联调，再由新的非作者 agent 复核。
实际执行、两项 P2 的修复及复核闭环见
[测试记录](../testing/records/2026-11-15-reviewed-archive-transfer.md)。
本机原生、Windows/Linux、IME、辅助技术、外部服务及发行安装分别验收，
不能以 headless GPUI 或受控 SFTP 代签。当前只做本地提交，不 push。
