# ADR 0134：有界 PAX 归档元数据兼容

- 日期：2026-11-15
- 状态：已实现，集中门禁与非作者差分复核通过；完整平台验收开放
- 对应需求：FILE-05 的 tar.gz 客户端互通

## 决策

在现有严格 tar.gz 解码器中接纳有限的 POSIX PAX 元数据。`path`、`size` 影响
有效成员，其余允许的 `mtime`、`atime`、`ctime`、`uid`、`gid`、`uname`、`gname`
验证后丢弃。解包始终使用项目自己的私有权限，不恢复归档权限、所有者或时间。
局部属性优先于全局默认属性，然后才使用普通头；局部属性只消费一次。
后续全局头只更新其提供的属性。

整个 tar 流沿用既有大小上限，另外限制单个元数据头为 8 KiB、元数据累计为
2 MiB + 48 KiB、元数据头数量为 4096。元数据不进入用户成员清单，但不能
通过大量小头绕过资源限制。原始和有效路径、声明大小分别检查；有效成员
继续执行既有 UTF-8、跨平台路径、大小写冲突、祖先冲突和完整清单限制。

未知键、厂商扩展、字符集切换、稀疏映射、linkpath、链接及特殊成员全部拒绝。
同头重复键、空值删除、非法或溢出的数字、孤立或堆叠局部头、歧义 GNU/PAX
链也拒绝。不能只读最后一个值后忽略先前恶意值。

所有允许头的原始 size 由本项目完整解析，不依赖可能丢弃高位的底层数值转换。
二进制编码只接纳带标记的非负 u64，拒绝负值和非零溢出高位；八进制只允许
数字及明确的空格/NUL 填充，不能在终止符后隐藏另一个数值。完整原始声明
先验证，再进入 PAX、普通成员、目录或 GNU 长名各自的预算与覆盖流程。

## 兼容边界

这是一项保守子集，不承诺接受所有 PAX 文件。普通备用路径仍须满足项目的
可移植路径规则。因此 Python 将 Unicode 普通头替换为 `?` 的文件即便另有
合法 UTF-8 PAX path 仍会被拒绝；合法 PAX UTF-8 path 配合安全备用路径可以
接受。用户需重新打包为本项目接纳的成员布局，不通过跳过路径检查“修复”归档。
厂商元数据如扩展属性也需要在来源端去除。

## 验证

将实际 Python tarfile 和系统 tar 生成的归档字节作为可重复夹具，覆盖普通文件、
空目录、长名称和元数据丢弃。恶意输入覆盖优先级、长度、资源上限、隐藏路径、
重复成员、链接、稀疏及截断。传输及原生层复用现有完整准备、审核、源重验与
新目标发布流程；单独解码通过不能代表原生操作或跨平台验收完成。

独立复核发现底层 base-256 size 可能截去高位的 P2；两项实际 Rust 红回归确认
问题后，改用上述完整原始数值解析。最终 40 项 PAX 与 40 项既有归档回归通过，
非作者使用已核对的父预构建 binary 独立执行相同 80 项，关闭 P2、零开放
P0–P3，没有独立重编译。最终 r4 全仓门禁退出 `0`；原阻塞报告、红回归及每轮
冻结均保留，详见
[集中验证记录](../testing/records/2026-11-15-archive-tools-pax-integration.md)。
