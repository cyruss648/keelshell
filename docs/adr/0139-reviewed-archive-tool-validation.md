# ADR 0139：审核式工具版本与流式归档自测

- 日期：2026-11-15
- 状态：已实现，集中工程门禁和限定非作者复核通过；本批原生桌面验收开放
- 对应需求：FILE-05 的工具版本和有界功能验证

## 决策

保留原来的 PATH 观察，另加「版本与自测」。用户审核当前主机、全部固定命令和
检查边界后确认一次。两种操作的审核类型不同；发现路径不授予运行工具的权限，
版本和样本检查也不授权打包、解包、Zmodem 或其它操作。

固定 Python 辅助程序通过当前已认证 SSH 的独立 exec 通道执行，需要 POSIX 和
Python 3.8+。程序在内存运行，不上传或保存脚本，不创建临时文件，不读取用户
归档，不安装程序，不联系外部服务。只接纳七项固定工具和参数：

- tar、gzip、zip、unzip、python3、rz、sz 的版本输出。
- tar 从固定微小 TAR 的标准输入向标准输出读取唯一指定成员。
- gzip 从固定微小 gzip 标准输入解压并核对内容。
- Python 标准库对内存 ZIP/tar.gz 进行完整内容往返核对。

zip、unzip、rz、sz 的功能自测明确为「未测试」。版本输出是远端程序自行提供的
观察值，不是真实性认证；固定样本通过也不代表所有格式、真实归档或 peer 互通。
测试不使用用户当前交互 shell 的临时目录、变量或输入，不开始 Zmodem 会话。

子进程使用固定 argv 和字节输入，不通过 shell 拼接工具路径。移除会注入额外
工具选项的环境变量；单次程序、累计时间和输出都有边界。程序失败、超时、
输出超限、未找到和未测试分别呈现。辅助程序或协议整体失败时，不能拼成七个
「未找到」或采用截断后的成功报告。取消或关闭 SSH 通道不证明远端进程已经停止。

每次调用由独立 Python supervisor 保持进程组 leader 存活，通过不传给工具的
有界状态管道报告真实工具退出码。正常退出和失败均先清理仍由自己拥有的组，再
回收 leader；不在 leader 已回收、PGID 可能复用后发送破坏性信号。关闭标准流
的普通后台后代同样收尾，清理无法确认时不出具报告。supervisor 有独立看门狗，
不要求旧版 macOS Python 缺失的 `os.waitid`。逃离进程组的恶意行为仍不属于该
诊断的隔离保证；操作系统进程创建也不提供硬实时保证。

2026-11-16 的真实 macOS CI 在回收 leader 后组查询 OSError 分支失败，
具体 errno 未保留；不能从堆栈断定为期限耗尽。清理改用一份一秒的绝对
截止，leader 等待与回收后的非破坏性组观察共用剩余时间，不能分阶段续期。
共享六秒工作期限已经包含前面命令的清理，最终清理最多再使用一秒；
transport 仍为十秒。保持先发送一次自有组 SIGKILL、再回收 leader、之后只作
signal 0 观察。post-reap EPERM 只表示尚不能确认，可在同一截止内继续观察；
只有 ESRCH 确认 absent，持续 EPERM 或存在、其他查询错误、首次 kill 拒绝
及 wait 失败均不出具可采用报告。异常保留固定阶段和数字 errno，不带路径或
工具输出，远端 main 仍抑制异常并拒绝输出报告。

## 分层和审核身份

`keelshell-session` 提供固定命令、类型化报告、严格协议验证和有界后台执行。
`keelshell-app` 负责审核、会话绑定、状态与展示；不向 core 或持久配置加入工具
可用性缓存。确认、worker 入场及结果采纳均核对实际 SSH 连接身份。

复用原来的工具操作调度，但在审核快照和回复类型中显式区分 PATH 与版本自测。
不能把同一主机名、复用 token、旧的 PATH 审核或迟到的版本结果移植到新连接。
重新核验开始后撤下该类型旧结果；失败保留失败状态，另一个类型的旧观察仍以其
原来源和时间展示。取消后重新执行必须重新审核。

## 原生界面

沿用「传输设置 → 归档传输 → 服务端工具」，增加一行版本/自测动作与摘要。
详情默认折叠，七项结果使用独立有界滚动区；完整命令复用固定确认/取消和正文
滚动。不增加主题 ID 分支、字体、装饰动画或硬编码状态色。

霜白、曜石、雾紫继续通过注册表、语义 Palette 和组件 token 扩展；三主题的明暗、
中英文、窄窗、失败与未测试状态共同覆盖。绘制、切换主题/语言和展开详情均不
启动远端操作。GPUI 控制器、正常程序构建及实际原生桌面观察分别验收。

## 集中验证

后端/helper 与原生界面并行开发，新增测试与功能一起编写；集成后集中运行解析、
子进程边界、SSH、原生控制器、全仓门禁和真实 disposable OpenSSH，再由非作者
复核最终输入。修复先重跑相关回归，最终源码需要一次完整成功门禁。

Windows/Linux 桌面、IME/辅助技术、严格 Zmodem peer、用户中继及性能收益不由
本批样本或本机编译代签。最终 607 项工程输入的完整门禁退出 0，真实 OpenSSH
16/16、Linux arm64 helper 和 Python 25/25 通过。两个非作者范围均批准、零开放
P0–P3，两个 P2 已修复；Rust 复核使用已核对来源和完整库存的父预构建副本，
没有独立重编译。实际计数、原始失败和平台边界见
[集中记录](../testing/records/2026-11-15-archive-tool-validation.md)。
