# ADR 0140：显式选择旧文本编码

- 日期：2026-11-15
- 状态：采用；集中工程门禁通过，非作者与原生边界单独记录
- 需求：FILE-04 的远程文本编码选择与无损保存

## 决策

保留默认 Unicode 读取：UTF-8，以及带明确 BOM 的 UTF-16 LE/BE，不猜测编码。
另提供 GBK、GB18030、Big5、Shift_JIS 和 Windows-1252 的显式读取选项。
所选项只决定下一次明确读取；切换选项不联网，不改当前正文、原始字节、
已观察格式或保存权限。编码随本次打开文档保持，不写入连接配置。

用户重新读取已有脏草稿时，沿用放弃草稿审核；取消保留完整草稿和原格式。
尚未确认的读取、保存和合并都绑定实际会话、当前文档和准确候选。
新的读取选项不能被迟到回复或旧审核隐式替换。

旧编码使用 `encoding_rs` 的 WHATWG 映射，不承诺每个历史厂商扩展或国家标准
修订版本。Unicode BOM 不能被旧编码选项重解释。解码严格拒绝替换；
输入完整解码后按相同编码重编码，必须与原始字节完全相同，才允许作为编辑基线。
保存时也核对解码后的文本与规范化草稿完全一致，拒绝不可表示、替换、数字字符
引用和有损 best-fit（例如 Shift_JIS 的日元/反斜杠映射）。错误不含正文。

`keelshell-core` 管理编解码、格式、换行及预算。`keelshell-session` 增加接受明确
`TextFormat` 的审核式编辑保存入口；原 Unicode 入口继续拒绝旧编码，不扩大 MCP
的 64 KiB 文件修改合同。备份、基线复核、目标隔离、原子替换和完整目标读回不变。
`keelshell-app` 负责读取选项、草稿/审核身份和双语主题界面。

1 MiB 的原始字节、Unicode 正文、最终字节和 4096 行保存限制不扩大；BOM、CRLF、
UTF-16 和旧编码扩张均计入。没有有损保存、自动转码、自动重试或猜测编码。
查找/替换、diff、patch、冲突合并在 Unicode 正文上工作；最终保存仍核对精确字节。

## 原生界面

读取选项使用现有 Kit Popover/按钮、三主题 registry、Palette 和组件 token。
说明它是「读取编码」，与已打开文档的实际编码分开展示；浮层限制在窗口内，避免占用紧凑文件区的滚动高度，
不让选择器挤出文件列表、正文或固定确认/取消。主题、语言和选择器绘制不启动 I/O。
原生桌面、键盘、IME 和辅助技术与 headless 控制器分别验收。
