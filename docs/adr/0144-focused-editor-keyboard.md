# 0144 — 限定编辑器焦点的键盘工作流

日期：2026-11-16。状态：已实现，完整工程门禁与限定原生复核通过。

原生远程文件编辑器需要可预期的保存与查找快捷键。使用 GPUI 的 action 与
key context 路由，在 macOS 提供 Cmd+S/Cmd+F，Windows/Linux 提供
Ctrl+S/Ctrl+F。只有当前可见编辑器的焦点路径可以处理这些动作，不能截取
终端输入、路径框或其他工具输入。

保存仍进入既有完整审核；快捷键不能确认，也不能授予远端写入权限。
已有审核、忙碌、上一会话快照或没有打开文档时，动作不得替换审核或发起操作。
查找需保证搜索输入可见，并将原生焦点交给它。提示使用双语和已有组件；
霜白、曜石、雾紫继续共用主题注册与语义 token。

实际键盘分发、审核取消/确认、焦点与旧会话边界通过有意义 GPUI 回归核验。
macOS 暂存包和 disposable OpenSSH 流程单独核验键盘输入及出站格式、
原始备份和完整读回。三平台桌面、IME 与完整辅助技术仍分别验收。

最终工程门禁覆盖 715 项冻结输入，普通 Rust 3168 项与 rustdoc 14 项通过，
11 个新增默认用例逐名匹配。非作者源码复核与限定 Frost UTF-16/GBK 原生证据
分别批准；旧失败、其他主题 HOLD/NOT_RUN 和辅助技术边界保留。实际回执见
[批次记录](../testing/records/2026-11-16-editor-keyboard-native.md)。
