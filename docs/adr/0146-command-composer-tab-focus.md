# ADR 0146：命令输入框的双向 Tab 导航

- 日期：2026-11-16
- 状态：已实现，验证与交付以批次记录为准

## 问题

命令输入框沿用 Kit 的多行纯文本组件。该组件默认把 Tab 和 Shift+Tab
处理为缩进与反缩进，即使没有可修改的文字也会消费动作。实际桌面曾在反向
遍历时停留于命令框，无法到达文件列表；历史原生失败仍保留。

## 决定

只在命令栏捕获 Kit 的 `IndentInline` / `OutdentInline`。动作发生时再次检查：
命令框自身持有焦点、没有活动模态、没有输入法 marked text。满足条件后使用
窗口实际绘制的前后焦点顺序，并停止传播；其余情况继续原组件处理。

不增加全局按键绑定，不修改草稿文字，不请求补全或执行命令。运行按钮、其他
输入框、编辑器和终端保留自己的动作作用域。弹窗在绘制前进入活动状态时，
旧命令框节点也不能移动焦点。输入法组合继续由原组件处理，本决策没有定义
新的输入法编辑策略。

## 工程与设计

实现只在 `keelshell-app` 的命令栏内，复用既有 Window、Kit 动作与组件。
三主题继续通过 registry、Palette 和语义 token 扩展，没有按主题 ID 分支。
UI 布局、字体与配色不需要新增规则。

八项 GPUI 回归覆盖空草稿、含缩进的中文多行草稿及不同选区、marked text、
已挂载及绘制前模态、运行按钮与其他输入/编辑器/终端作用域。每项检查隔离
transport 没有写入；这些检查不能代签真实输入法、桌面或辅助技术。
