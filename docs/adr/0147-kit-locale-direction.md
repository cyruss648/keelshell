# ADR 0147：组件方向跟随应用语言

- 日期：2026-11-16
- 状态：已实现，集中门禁与平台验收分别记录

## 问题

实时依赖检查发现 GPUI Kit 稳定版本已更新为 0.10.0。新版本原生初始化会从
系统语言决定布局方向，组件 locale setter 不同时更新该方向。KeelShell 目前
提供中文和英文；系统为 RTL 语言时，仅更新应用文案会留下相反的组件布局和
普通输入框左右键行为。测试环境默认 LTR，原测试不能自然覆盖该系统初态。

## 决定

保持直接依赖要求为 `0.10`，由 Cargo 解析并保留 patch/checksum。统一语言入口
`i18n::set_language` 在更新应用与组件 locale 后，使用相同的应用语言 code
更新 Kit `LayoutDirection`，再刷新全部窗口。未来新增语言继续使用相同入口，
由语言 code 确定方向，不在业务控件中散布 LTR/RTL 分支。

方向不依赖主题。霜白、曜石、雾紫继续通过 registry、Palette 和语义 token
扩展；本片不重新定义主题、终端协议文本或远端文件内容。
默认后端继续使用 gpui-pre；锁文件包含可选 Fast 包不表示应用已启用 Fast。

## 验证与边界

新增真实 GPUI Input、绘制、焦点和按键派发回归：显式种下 RTL，在中英文选择
下输入 `ab`、Left、`X`，要求得到 `aXb`。父实际编译通过；仅删除方向同步
一行后的重新编译产生 `abX` 并失败，精确恢复后重新编译通过。
这建立该具体键盘行为的 red/green，不证明系统 RTL 初始化或原生输入法完整矩阵。

上游 0.10 的输入、grapheme、IME、辅助技术和手势处理还有其他变化。
现有工程测试随组合门禁重新执行；三平台真实桌面、IME、辅助技术、正常包、
安装和发行不继承旧 0.9 的限定观察。来源、精确依赖图、库存、失败和验证结果
见[本批记录](../testing/records/2026-11-16-windows-directory-rename.md)。
