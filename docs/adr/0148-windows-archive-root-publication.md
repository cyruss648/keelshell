# ADR 0148：Windows 归档根目录发布的观察生命周期

- 日期：2026-11-16
- 状态：实现候选，宿主专项与非作者静态复核通过；精确 Windows 执行待验证
- 范围：已确认解包后创建的私有 staging 树；不改变已审核来源和祖先的保留契约

## 背景

源码 `8527cf2af581e50ac0e1f795176ab69737730e18` 的真实 Windows 归档预检
列出 29 名，实际 `25 passed / 3 failed / 1 ignored`。嵌套树明确在
`publish-stage` 返回 typed `Io / PermissionDenied / raw OS 5`；空树发布成功。
源 manifest 的克隆测试也在重命名含已打开后代的外层目录时被拒绝。
完整 Windows 门禁未运行，不能从这些结果签署解包修复成功。

Microsoft MS-FSA 2.1.5.15.12 在目录改名时检查后代打开状态；
2.1.4.2 遍历其目录树及相关 link 上的现存 open。分享 DELETE 并不免除
该检查。以前为了比较完整 staging 树而保留的后代观察句柄，与该发布规则冲突。
根目录短期 DELETE lease 和无覆盖原语保持其独立作用，不能因此放宽权限。

## 决策

只调整**新建 staging 的内部观察**。所有内容写入和 flush 完成后，仍先保留完整
树句柄，重新检查全部祖先、私有 DACL、成员清单、每项身份、元数据和完整内容。
发布前的两份树必须相等，原树句柄的实际元数据也必须匹配。

通过这些检查后，消费内部 `Tree`，保存每项 `FileInfo`、digest 和精确 children
清单，关闭其观察句柄。根 `PrivateEntry` 从创建到发布始终保留，
全部已审核祖先也始终保留；来源扫描/review 的 `Manifest` 不参与该转换。
转换后不再写入任何后代，只通过确切根对象执行原无覆盖改名。
取消标志在转换之后、改名之前再检查一次。

改名后重新核对祖先，通过保留根对象与目标名字的相等检查打开发布目录，
完整重新遍历每项并读取全部文件字节。新观察必须与保存的原身份、元数据、
安全观察、digest 和清单逐项相等，内容还必须等于审核后的完整成员 bytes。
只有根目录的 modified/changed 继续使用原有改名归一规则；
后代的时间、身份、属性和权限比较不放宽。随后继续检查命名唯一、staging
缺席、所有链接以及最终取消/授权状态，全部成功后才解除未知结果 guard。

这不是跨改名持续固定每个 staging 子项的原生对象的保证。该瞬间的保证是：
根和审核祖先保持确切绑定；不再对子项执行写操作；原有界完整观测被保留，
发布后以全部身份、权限、清单和完整内容重验决定是否接受。不能仅凭 file ID、
路径或 hash 相同就报告成功，也不能把共享读 capability 当作排斥同账户修改的锁。
该限定不改变源文件和全部已审核祖先为防身份复用而持续保留句柄的契约。

## 失败与验证

原 `UnverifiedStage` guard、mutation pending、reservation 和异步所有者接收语义
保持。转换前后任何错误、取消、panic 或丢弃 await，均不能自动解除隔离或删除
可疑 staging/目标；根改名成功也不等于完整操作已被验证。

既有完整嵌套树和未观察成功发布用例作为已在 Windows 实际失败的回归。
补充相同字节但对象替换的拒绝用例；调整来源 clone 测试，避免将平台禁止的
外层目录改名当成必然成功，同时保留原祖先、旧对象及替换拒绝的证明。
不改访问权、分享参数、NT 调用、DACL、时间上限或 ignored 权限用例。

宿主编译和测试不能覆盖 Windows 条件代码；最终需要新精确 CI 的库存、真实
执行、完整应用文件回归及非作者复核。Windows/Linux 桌面和发行另行验收。
