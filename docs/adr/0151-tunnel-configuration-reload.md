# 0151：隧道面板内显式重新加载配置

- 日期：2026-11-16
- 状态：已实现，源码／功能独立复核及宿主工程门禁通过；原生边界见[测试记录](../testing/records/2026-11-16-tunnel-configuration-reload.md)

## 问题

命名规则的保存冲突或未知写入结果会阻止后续编辑和启动。阻断属于 Workspace，
不能通过关闭再打开面板绕过；但隧道面板此前没有取得新权威配置的专用入口，
用户需要寻找其他配置重新加载入口。另一窗口提交导致的失效也不应永久显示为
“正在保存”，因为没有实际保存任务可以解除这个状态。

## 决策

在命名规则动作区增加“重新加载”紧凑 Kit 按钮，使用现有主题 registry、
Palette、组件、焦点和双语无障碍名称。它读取本机配置，不执行 SSH 请求、
启动隧道、合并或重放草稿。所有主题共享该组件路径。

面板为每次显式请求生成独立 operation 与 epoch，绑定原 connection ID。
Workspace 同时验证精确 pending 请求、当前 live 面板及原连接映射；订阅、
归档面板或保留 worker owner 本身不构成配置加载权限。保存、重新加载、
配置维护、连接流程、关闭或其他模态操作期间拒绝新请求。

后台 executor 执行 StateStore.load。共享 ConfigurationGate 的 reload lease
从准入保持到前台采用，避免后台读取结束与 UI 采用之间被另一窗口写入。
读取期间同步现有面板的 busy，新开的面板继承它。租约不能取得时不遗留
busy 或 pending 请求。

成功读取后采用完整 AppState，并沿用所有配置重新加载所需的 AI 凭据、
知识审核、重连、MCP、Agent、片段和主题刷新边界，而不只替换隧道规则。
只有成功的权威采用才解除规则存储阻断；内容不变也撤销旧审核。草稿文字、
原快照及现有 SSH／隧道 owner 保留，用户取消旧草稿后基于最新配置重新编辑。
活动监听器不随元数据改变端点或身份。

失败继续阻止规则写入和命名启动，保留原始错误及草稿，允许用户修复配置后显式
重试。原面板挂起、归档、替换或绑定变化导致完成请求过期时，不采用迟到结果，
未完成 lease 按既有合同留下共享 uncertainty；当前面板可重新请求，不自动重试。
另一窗口提交产生“需重新加载”阻断，实际保存／读取才产生 busy。

## 验证边界

使用隔离 StateStore、真实回环 SSH、生产 GPUI 订阅和按钮覆盖冲突、失败后重试、
新面板 busy、同内容撤销审核、竞争租约、原 owner 失效与活动隧道保持。局部状态
测试覆盖旧绘制 epoch、重复请求和 pending 身份。最终工程门禁、非作者复核、
正常包及真实桌面证据分别记录；headless 不授予原生桌面验收。
