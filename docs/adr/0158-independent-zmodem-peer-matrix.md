# ADR 0158 — 独立 Zmodem peer 的直接 PTY 交叉验收

日期：2026-11-17。状态：有界实现已接受；完整peer矩阵仍PARTIAL。
基线：`ac7ec43e6a42329417a99b5933bc171faa19caf6`。
延续[审核式协议](0136-reviewed-pty-zmodem.md)与[有界收尾](0137-bounded-zmodem-farewell.md)。

## 目的

原 lrzsz 直接 PTY 缺少 OO 的失败继续保留。独立实现的交叉联调用于检验
应用协议、逐文件审核、取消和结束交还，不能从一种 peer 的成功推定另一种已修复。
原受控实验中的上游输出队列清空风险与每次实际失败原因分别记录。

## 测试接口

生产应用不捆绑、安装或运行新的 peer。仅扩展真实 OpenSSH 测试夹具：
`KEELSHELL_ZMODEM_RZ`、`KEELSHELL_ZMODEM_SZ`仍为调用者指定的现有可执行路径，
可选`KEELSHELL_ZMODEM_RZ_ARGS`、`KEELSHELL_ZMODEM_SZ_ARGS`为JSON字符串数组。
缺省参数严格保留`["-b","-vv"]`。

JSON原文最多16,384个UTF-8字节、32个参数、每项2,048字节、
参数内容合计8,192字节；拒绝C0和DEL。空参数、Unicode、普通引号和空格保留为
独立字面参数。夹具将本用例选项放在peer数组之前、精确文件名放在之后，
逐项引用，不执行参数中的shell语法。这样可支持含位置式`rz`／`sz`子命令的peer。
Python runner和直接执行Rust用例分别校验；runner另记录可执行内容摘要与实际参数。

peer替换已经建立的原始SSH PTY shell，不增加协议pipe、relay、interposer或替代exec通道。
上游来源固定到精确提交并记录构建／二进制摘要；版本输出和成功编译不属于传输验收。

## 验收

保留既有八项真实peer用例及严格`Finished`断言；只增加覆盖：

- 三文件下载：二进制、Unicode文本、空文件，每个offer分别产生新的单次审核，
  完整保存回执与最终内容分别核对。
- 首个文件已保存后取消：下一offer不产生新审核或发布，不增加完成事件，
  已保存文件保留，未审核文件和私有staging不出现在本地目标目录。

CRC16／CRC32、完整内容、逐文件保存、peer退出、实际OO、取消、普通终端尾部及
同一shell的新输入按实际证据分别判断。有界缺握手结果不补签严格完成。
原生文件选择、三平台桌面与发行继续独立验收；完整产品目标保持进行中。

## 七字段文件元数据

首次未修改SexyZ直接PTY实测3上传通过、7下载在首offer前因`InvalidMetadata`拒绝。
捕获的CRC32 ZFILE包含七个数值字段；旧core只允许六个，原报文已加入红回归。
公开lrzsz维护者协议文档`zmodem-wip-20261004.txt`的ZFILE数据段说明：
长度、mtime、mode、serial、剩余文件数、剩余字节后可有已废弃的十进制file type，
接收方忽略该字段含义。来源与整件摘要保存在本批协议参考回执。

core最多接受七字段，末字段仅作有界`u64`无符号十进制语法校验；
它不能覆盖第三字段的普通文件类型策略，也不能改变路径、声明长度或审核。
保留全部元数据／文件／会话预算，拒绝额外字段、非数字、符号、溢出和NUL后隐藏数据。
不采用外部peer实现源码，不在产品中捆绑其源码或可执行文件。
