# ADR 0160: 客户端配置模板与未知结果的独立核对

- 日期：2026-11-17
- 状态：已实现；限定非作者源码/功能复核及最终工程门禁通过。
  实际客户端、原生桌面和发行另验，见[本批记录](../testing/records/2026-11-17-mcp-client-history.md)
- 基线：`f4562ad17efc918976738b241352e7a4f8af434e`

## 问题

对外 MCP 已有受认证的桌面 IPC、八项固定工具和文件提案审核，但复制的是单个
服务对象，用户还需手动改成客户端配置。可保存的配置模板与当前授权的临时凭据
需要在界面上区分。

另一个实际缺口是批量清理历史只保留 PendingReview / Running，从而也会移除
OutcomeUnknown。窗口关闭门槛依赖未知记录的存在，普通历史清理因此可能隐式
解除尚未独立核对的远端风险。原来没有单独记录核对行为的入口。

## 决定

1. `keelshell-mcp` 提供纯函数 `client_configuration_template`，支持 Codex CLI 的
   TOML 和 Claude Code 的完整 JSON。只接收已由调用方验证的伴随程序路径；
   模板包含空参数和两项环境变量的名称或引用，不接收活动授权或读取环境值。
2. Codex 的路径使用 TOML 可接受的完整字符串转义，包括全部 C0 和 DEL。
   Claude Code 会在 command 中展开 `${...}`，遇到这类字面安装路径时静态失败，
   不静默改写目标。空或非 UTF-8 路径同样失败，不把路径放入错误。
3. 原生 MCP 面板提供客户端选择与显式“复制配置模板”。既有“复制临时启动配置”
   继续用于当前敏感能力，两种操作分别说明用途。没有全局配置写入、自动启动、
   新授权、SSH 登录或供应商请求。
4. 批量清理只删除 Rejected / Expired / Cancelled / Succeeded / Failed。
   PendingReview / Running / OutcomeUnknown 始终保留；按钮在没有可清理记录时禁用。
5. 每个未知动作可打开独立核对层，显示原目标、连接/会话/路线、动作 ID、digest
   和完整命令或文件 diff。取消、Escape、旧动作回调均不消费核对确认。
6. 用户在独立 SSH / 文件检查后明确确认，只设置该不可变动作的内存核对标记，
   解除此提案的窗口关闭限制。状态仍是 OutcomeUnknown；不运行、重试、回滚、
   改写结果或恢复旧权限。其他窗口关闭、文件 quarantine 和远端风险门槛仍各自适用。
7. 已确认未知记录仍保留于本次窗口内，不被批量清理。所有记录仍计入现有 32 项
   上限；达到上限时需先清理已知终态，未知记录不自动淘汰。退出不持久化这些内容。

## 原生设计

沿用 Frost、Graphite、Lavender registry、语义 Palette 和 Kit 按钮，不按主题 ID
分支。客户端动作在现有滚动正文内成组排列；授权/撤销保持原固定动作区。
未知核对层接入唯一活动模态、精确 challenge、焦点陷阱和 Escape，原 MCP 设置
不会同时挂载。完整正文独立滚动，确认与返回固定可达。

## 验证与边界

新增行为测试覆盖批量清理、真实受控 SSH exec 撤权、SFTP writer 暂停/撤权、
旧核对确认拒绝、原字节和未知状态保留、复制内容的实际能力值排除，以及三主题、
明暗、双语、两尺寸的绘制/焦点几何。纯 renderer 另覆盖恶意路径和平台路径。
集中工程门禁、独立非作者复核、精确提交 CI、实际客户端和原生桌面分别记录。
