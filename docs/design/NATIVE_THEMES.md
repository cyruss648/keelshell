# 原生主题设计 — 2026-11

用户已接受[三套 HTML 方向](prototypes/2026-11-workbench/index.html)，全部进入原生主题实现，不再等待单一方案选择。HTML 仅作为设计参考和离线交互样例，其截图不能作为 GPUI 原生验收。

本轮延续 Hallmark app-screen 设计方法，把视觉身份落实到可维护的语义颜色和组件形状：

- 霜白：冷中性色、清晰分隔线、6px 控件与 8px 面板圆角。
- 曜石：暖石墨底、琥珀色动作、小型 4px 控件与 6px 面板圆角。
- 雾紫：低饱和紫灰、12px 控件与 14px 面板圆角。
- 文字、次要文字、选择态、危险态、输入边界和焦点环都有语义角色。不能把某个主题的字面颜色复制到业务视图。
- 中性组件也使用独立的 `surface_hover`、`surface_active`、`focus` 和
  `toolbar` token：悬停、按下、键盘焦点和工具栏层次不再复用选择态或普通
  `chrome`。这些 token 在 Kit 适配层统一映射到按钮、列表、表格、标签栏、
  标题栏和状态栏，业务组件无需按主题 ID 分支。
- 每个主题提供浅深两种变体；主要按钮的前景色也由 token 定义，避免亮琥珀/浅紫按钮仍固定白字。
- 主题目录集中提供元数据，选择器用实际 token 绘制抽象配色预览，不显示伪造的在线主机或运行结果。

主题不规定连接导航宽度、终端高度、AI 面板显隐或工具密度。HTML 中的布局实验分阶段迁入原生实现并独立验收，不能随主题切换重建工作区。主题入口、状态持久化、组件 token 和终端默认色已统一；连接/主机导航、独立会话栏和紧凑补全已在[原生工作区](../product/NATIVE_WORKBENCH.md)中实现，完整文件工具区布局仍待继续。

本切片只调整主题 token 与 Kit 映射，不改变工作区布局、连接导航、会话栏或
主题设置的持久化字段。主题矩阵测试覆盖三套主题的浅深变体、文字对比度、
焦点环可见度，以及 hover/active 的分离。

输入使用 Kit 原生焦点与键盘机制，设置选择器纳入现有 modal scope；异步 SSH 认证仍优先于主题设置。保存通过现有后台串行流程，保持草稿实体。

架构与新增方法见 [ADR 0095](../adr/0095-extensible-native-theme-families.md)。测试与未验收项见[本轮记录](../testing/records/2026-11-04-native-themes.md)。
