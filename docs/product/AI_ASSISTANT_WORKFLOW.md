# AI 助手审核工作流

KeelShell 的 AI 助手把解释、请求准备、回复审核和本地知识整理放在同一工作区，
但每一步都保留用户的明确控制权。终端不会因为当前可见而自动进入请求，模型
回复也不会直接执行命令或修改远程文件。

## 使用流程

1. 在当前 SSH 会话中选择“所选文本”或“当前屏幕”，明确捕获要分享的内容。
   捕获记录绑定主机、会话、捕获类型和 revision。
2. 选择 AI 配置并编辑问题。配置变更、凭据变化、上下文变化或目标变化会撤销
   旧的预览和请求。
3. 点击“预览请求”，检查目的地、完整脱敏载荷、脱敏数量和省略字节数。
4. 点击固定在底部的“确认发送此请求”。该按钮只发送当前审核过的精确快照。
5. 收到回复后，先查看回复绑定的 SSH 主机和会话，再决定是否把命令建议送入
   既有命令审阅区。命令建议不会自动填入输入框。
6. 需要沉淀时，生成本地知识预览，确认结果为已完成或已失败，再审阅来源和
   Markdown，最后在助手底部固定审核栏保存到本机知识库。未知或不完整结果保持排除。

助手顶部的工作流轨道会显示“捕获、提问、预览、发送、审核回复、保存知识”六个
阶段。它帮助用户定位当前阶段，不提供绕过审核的快捷路径。回复到达后，面板会
自动把回复审核标题滚动到可视区域；长请求和完整上下文仍可在正文滚动区查看。

## AI 能做什么

- 解释用户明确捕获的日志、终端输出和配置片段；
- 根据已审核上下文提出排查方向；
- 提取受限的 shell 代码块，作为命令审阅区中的候选；
- 生成绑定当前目标和回复指纹的诊断计划，逐项返回现有审核入口；
- 将明确确认结果的终端快照整理为带来源的本地知识；
- 使用已保存知识作为 Ask 的显式上下文，仍需再次预览、脱敏和发送确认。

Agent 模式还要为每一回合和每一项 SSH/SFTP 操作单独审核。AI 助手不恢复历史
SSH 授权，不根据历史知识自动连接主机，也不把知识条目当作可执行 runbook。Agent
停止并编辑问题时，旧回合先被撤销，问题输入框按停止后的最新布局自动显露，便于
重新提问而不会沿用旧审核。

## 主题和扩展

工作流轨道、审核卡片、状态卡和危险提示使用语义颜色及组件 token。霜白、曜石、
雾紫三套主题共享同一套视图代码；未来增加主题时，只扩展主题注册表、Palette、
组件形状、Chrome token 和 Typography token。

## 验收边界

GPUI 测试覆盖状态派生、双语标签、回复审核可达性、请求快照不被语言切换替换、
长 MCP 审核、Agent 问题编辑和固定知识保存 footer。完整工程门禁已经退出 0；
真实供应商请求、完整 Agent 客户端流程、macOS/Windows/Linux 原生窗口和辅助技术
矩阵仍需单独验收。当前实现与回执见[测试记录](../testing/records/2026-11-07-session-library-ai-ui-polish.md)。
