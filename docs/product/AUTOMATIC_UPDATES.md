# 更新检查与下载策略

KeelShell 的“关于与更新”展示项目主页、当前版本、内置变更日志与匹配平台的稳定 Release。后台服务与面板显示独立：关闭面板只隐藏它；打开面板可以查看发现的版本、下载结果及设置。工具栏在有新版或已校验的包时显示提示。

## 设置与首次启动

设置提供“关闭／每天／每周”及可选“自动下载并校验”，默认每天检查、自动下载关闭。旧版本的设置没有 `updates` 对象时使用相同默认；已存在但格式非法的对象会拒绝加载，不改写为默认。应用遇到配置加载失败会暂停后台更新；修复并成功保存或重载后才恢复，仍可手动检查。所有偏好走本机已有的乐观状态事务，只有明确保存后才生效。保存失败保留草稿，不把设置按钮的选中当作落盘成功。

首次、逾期或未有成功记录的检查至少延迟启动 60 秒。最近一次完成的检查以 Unix 秒保存，本次运行使用单调时钟安排每日／每周期限；系统时间向前或向后变化不会形成连续请求或无限期停查。关闭后台检查会撤销当前旧策略请求；手动检查始终可用。重新加载本机设置会立即同步后台政策，已编辑草稿仍保留。

网络、元数据、校验或下载失败使用 15 分钟开始、翻倍至最多 6 小时的退避。成功检查重置退避。GitHub 暂无稳定 Release 的 404 是一次正常检查，不反复立即请求。后台同一时间只拥有一条请求；人工检查可以取消旧后台检查或下载并成为新 owner，人工请求进行时周期检查不插入。

## 自动下载与人工安装

自动下载只在启用策略后的后台检查发现匹配新版时发生；保存开关本身或人工检查不会立即自动下载。下载继续使用固定项目的 HTTPS Release 来源、匹配平台产物及 SHA-256 校验；响应、归档和解包内容保留已有大小与条目限制。没有遥测、账户或客户上下文上传。

请求及回复绑定唯一 ID、固定来源、当前版本、平台、偏好代次；下载另绑定完整 Release 元数据。旧请求、取消请求或策略变更后的结果不能接管状态。取消中止拥有的网络 future；已经开始的阻塞解包／校验可能继续完成，它保留私有暂存包的清理 owner，不能成为安装授权。

下载完成后仍继续周期检查。检查期间保留旧的已校验包；同一 Release、检查失败或下载失败时可返回旧包，新包完成校验后才替换。发现另一个版本但没有自动下载时，可以选择手动下载新版或“返回已下载版本”。“取消更新请求”只撤销本次检查或下载，并恢复保留的旧包；已下载且没有请求进行时，按钮明确显示“丢弃已下载更新”，由用户主动丢弃这个包。关闭面板不会丢弃它。暂存内容不在重启时自动恢复，下一次启动只恢复设置及成功检查时间。

“确认安装并重启”是唯一启动安装 helper 的交互。它保留已有清单预检、备份、失败回滚和回滚不完整时保留恢复材料的逻辑。自动下载始终不安装。平台签名、公证、现有安装目录实际更新、Windows／Linux桌面及完整发行安装矩阵仍开放，详见[发布流程](../RELEASING.md)。本功能开发与测试不会覆盖本机现有应用。

## 边界与验证

只检查该公开项目的稳定 Release；没有自定义更新源、预发布通道、静默安装、系统后台守护程序或跨进程全局下载锁。多个应用实例各自拥有服务；StateStore 冲突保护防止旧检查 metadata 覆盖另一个实例的新设置。遇到冲突需重新载入状态后再保存保留的草稿；不会自动用旧策略覆盖获胜设置。

独立临时目录、自有 loopback HTTP、受控 GPUI和真实 StateStore 测试用于验证调度、单请求、取消、迟到结果、整包校验和偏好保存。最终主树完整工程检查及macOS宽窗口设置保存／重开、后台无稳定版本提示与SSH草稿保留已有各自证据；GitHub实际更新包下载、签名发行、实际安装和其它目标原生桌面仍开放。候选历史见[策略测试](../testing/records/2026-10-08-automatic-update-policy.md)，最终组合见[整合测试](../testing/records/2026-10-08-update-toolbar-main-combination.md)，决策见[ADR 0077](../adr/0077-automatic-update-policy.md)。

更新动作绑定用户看到的具体对象。下载使用当时展示的完整 Release；返回、查看、安装和弃包绑定同一个已校验暂存包，包含 Release、摘要及归档／解包路径。取消仅作用于当时的请求身份。后台结果或策略变化使旧入口过期时，点击不执行其它动作，需查看新界面后重新选择。
