# 配置备份与显式恢复

本次功能提交收录 CON-04 的配置备份与显式恢复。最终 824 输入严格工程门禁、新标准 macOS 包／57 打包和有效／损坏配置的原生恢复、取消、重启及完整字节读回已完成；修后中文浅色和英文深色均实际显示当前 2／恢复后 1，损坏当前数量显示无法读取。新的非作者最终组合复核无 P1/P2 阻断、数量归属 P2 已关闭；收尾只更新四份状态文档，其余 820 输入不变，提交后的精确三平台 CI 待验证，最小 OS 几何、辅助技术、其它平台桌面和断电耐久性仍独立开放。详细成功、失败、中断与未验证边界见[主树整合记录](../testing/records/2026-10-08-configuration-recovery-main-integration.md)。

每次成功解码当前配置并通过 revision 校验的保存，会先把旧元数据写入本机 `state.json.backups`。首次保存没有旧版本；工具栏的“配置恢复”面板也可明确“备份当前有效配置”。历史最多八份，使用本机单调序号保留最近八份，列表显示 UTC 时间和序号。序号决定轮转，文件时间只用于展示。历史槽位以原子替换更新，完整磁盘资料始终受同一状态锁保护。

元数据包括连接、文件夹、软删除资料、片段、历史摘要、主机信任及偏好。SSH／AI 凭据只有原有引用；不会打开、复制或修改 OS 凭据、私钥文件或认证加密 vault。片段、名称等用户文本仍属于配置，用户应避免把秘密写在其中。恢复历史资料不能找回已经删除的凭据条目，也不能解除凭据库的密码认证。

恢复入口要求先关闭全部 SSH 标签，停止 AI、外部 MCP、批量与定时任务，并完成待保存的最近记录／审计。正在运行的操作不会由恢复按钮暗中中止。进入面板后，正常配置保存和更新检查时间写回暂停，以保留独立审核范围。

该入口检查的是桌面持有的会话、权能和操作状态。既有 MCP 撤权会把已发出的 Running 操作记为 OutcomeUnknown，并取消／清除本机句柄；这不证明已发出的远端进程或写入已经物理停止，也不构成实际 Join 完成的承诺。恢复不发行新远端操作、不重放旧授权；已有未知结果仍须独立核实。

用户流程为：

1. 打开“配置恢复”，读取本机历史。
2. 选择可用备份，查看当前配置是有效、缺失、损坏还是此程序无法读取的 schema；分别查看当前配置和恢复后配置的连接、回收站、文件夹、片段、AI 配置和信任数量。缺失、损坏或无法读取的当前配置显示“无法读取数量”；有效空配置显示真实零数量。
3. 明确勾选“我已审核替换影响并同意恢复所选备份”。这一步仍不写磁盘。
4. 点击“明确恢复所选备份”。工作区再次检查没有活动权能，然后在 worker 中验证原件、revision 和备份完整字节。

读取、选择、预览及取消均不会恢复。当前文件、process-local revision 或所选槽位发生变化时，旧审核被拒绝，需要重新读取。新配置发放新 revision，旧内存快照不能继续保存。

恢复前，当前文件的完整原始字节保存到 `state.json.originals` 的独立 owner-only 文件中；损坏、截断和未来 schema 的原件也保持原字节。原件最多八份，不自动删除，达到上限时恢复会在替换前拒绝；可使用“打开配置位置”自行归档原件。当前文件缺失时没有虚构原件。超出 4 MiB、符号链接、非普通文件或 Unix 权限不安全的配置必须手动处理，本功能不会放宽既有存储约束。

备份包装格式为版本 1，应用 schema 继续使用现有版本及既有缺省字段迁移。未来备份 schema、包装版本、未知字段或无效序号不自动迁移／降级。用户可明确选择此程序能读取的旧备份来替换一个未来 schema 当前文件，完整未来原件会另行保留；这属于显式回退，不代表程序理解未来数据。损坏／未来历史会显示不可恢复；历史存在未知文件、重复序号或损坏条目时，正常轮转失败关闭，需先手动归档并保留问题材料。

原子替换前的失败不会改变当前配置。替换后的目录同步失败会尝试原子回滚完整原件（原件缺失则回到缺失）；若不能确认回滚，报告需要人工修复，保留任何已有的独立原件。错误结果不能被描述为成功恢复或成功回滚。

用户在等待期间点击关闭，只预约在本次成功结果传播后关闭。实际失败会取消这份预约，保留面板和实际 typed error；审核失效、已经确认回滚及无法确认回滚需要人工修复有不同结果说明。用户阅读失败后可再次明确关闭或重新读取审核，旧关闭请求不能替代对尚未出现的失败结果的确认。

成功恢复会刷新语言、主题、AI 配置和命令片段来源，清空旧 AI 上下文及临时凭据，并保持对外 MCP 禁用。未发送的命令草稿保留为无目标草稿。恢复不连接任何主机、不执行命令、不恢复传输队列、不恢复 Agent／MCP 授权、不自动发布同步资料。之后需要用户重新选择会话、提供凭据并审核操作。

该功能没有增加云账户、网络备份或加密 vault 导入。Windows 权限继承 per-user 配置目录，没有新增显式 ACL 实施；可信目录和合作文件锁的既有边界保持。同用户恶意替换路径组件、系统崩溃／断电、阻塞文件系统 syscall 和整个应用退出期限仍需要自己的验证。
