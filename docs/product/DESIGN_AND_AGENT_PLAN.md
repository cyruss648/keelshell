# 界面设计与智能体能力计划

更新：2026-10-04。状态：正式纳入产品范围，尚未实现或验收。本文覆盖后续主题、视觉体系、MCP 服务端与本地智能体接入；不取代既有远程 SSH 目标。

用户明确要求 MCP 是 **KeelShell 向其他智能体提供能力**。不开发在 KeelShell 内连接任意第三方 MCP 服务的通用 MCP 客户端。应用调用本地 Claude Code/Codex CLI 与对外 MCP 服务是两个独立入口，可以共用受控远程工具和审核机制。

## 界面目标与验收

| 编号 | 目标 | 实现计划 | 完成标准 |
| --- | --- | --- | --- |
| UI-01 | 明暗主题，默认跟随系统 | 持久设置 `System / Light / Dark`；缺失新字段默认 System；启动读取系统外观，运行时监听变化；用户显式选择优先于系统 | 三种模式、重启、系统运行时切换与旧配置迁移有领域/GPUI回归；三平台原生分别记录。切换不丢会话、草稿、审核或在途工作 |
| UI-02 | 统一主题与状态色 | 将固定浅色常量及散落颜色迁移到语义 token；提供画布、浮层、边界、正文、次级正文、强调、选中、成功、警告、失败、未知/进行中及焦点状态 | 自绘区域与 GPUI Kit 控件同步；所有主要屏幕明暗截图核对；普通文本以4.5:1作为设计门槛，状态还须有文字/图形提示 |
| UI-03 | 更丰富且克制的控件 | 使用统一线性图标、连接/认证类型标记、状态徽章、分组操作、进度/速率卡、骨架与空状态；高频动作直接可达，次要动作有清晰菜单 | 不用彩色装饰替代层级；同类操作/状态一致；长中文/英文、危险/禁用/忙碌/未知均可辨认 |
| UI-04 | 专业工作区 | 保持连接、终端、监控、文件、命令与 AI 的明确分区；统一字阶、行高、间距、密度、边界与浮层；优先完善终端工作区和文件/任务区，再统一设置/更新面板 | 用户能区分“已连接”“已审核”“已开始”“完成/未知”；900×580最小窗口和宽窗口分别有原生证据，侧栏/固定页脚/滚动正文不遮挡关键操作 |
| UI-05 | 一致的键盘与辅助技术体验 | 最上层模态管理、焦点陷阱与返回焦点、完整操作目标名称；修复背景AX隔离缺口及更新日志格式呈现 | 中英文、Tab/Shift-Tab、Escape、两层模态与原生辅助技术树逐项验证；不能只用视觉遮罩声称背景已隔离 |
| UI-06 | 可持续设计资料 | 在 `docs/design` 管理设计准则、token/组件状态、截图基线和参考来源；独立审查形成带证据的修复项 | 新组件有明暗/状态/响应式规范；截图对应精确构建与隔离数据；设计文档与代码在同一功能提交更新 |

当前代码在启动时固定使用 Light，`design.rs` 以及多个面板包含浅色常量，因此主题实现应先建立基础 token 与外观监听，再逐屏迁移，不能只切换 toolkit ThemeMode。终端 ANSI 色板与应用外壳分别管理，检查光标、选区、搜索和CJK可读性；白底应用图标继续保留。

视觉方向由实施方主导：采用适合长时间远程运维的紧凑工具型桌面界面，保持单一品牌强调色，使用中性色构建层级，以少量语义色传达状态。浅色不是整屏纯白，深色也不做简单颜色反转。

## AI 与 MCP 目标

| 编号 | 目标 | 实现计划 | 完成标准 |
| --- | --- | --- | --- |
| AI-LOCAL-01 | 配置本地 Claude Code、Codex CLI | 与 API 供应商并列的命名配置；选择可执行文件、检测版本/能力、模型、独立工作目录、超时/回合预算与环境变量引用；先支持两种官方适配器 | 不装伪端点、不调用交互PTY；仅检测版本不请求模型；凭据/环境值不入metadata；未安装、未登录、协议不兼容与服务错误分别报告 |
| AI-LOCAL-02 | 应用内调用与可见过程 | Ask优先：审核选中上下文后发送，结构化事件呈现回答/步骤/错误/取消；随后接通受限Agent工具和审批事件 | 大输出、UTF-8分块、乱序/畸形事件、超时、取消、迟到结果及会话切换有回归；真实安装版本另做显式、隔离的请求验证 |
| AI-LOCAL-03 | 进程所有权与授权 | 工作线程启动明确 executable+argv，问题走stdin；控制继承环境/工作目录/自动配置与hook；拥有子进程与后代清理；能力不足失败关闭 | 三平台分别验证取消/退出后无自有孤儿进程；不默认使用绕过审批/沙箱的开关；不能仅依据提示词承诺CLI不会访问其他本地数据 |
| MCP-01 | 对外 MCP 服务 | 专用MCP服务模块/可执行入口；优先stdio，桥接正在运行的桌面应用及已授权SSH会话；版本协商与工具schema来自实现时锁定的官方SDK | 外部Claude Code/Codex可发现工具并调用真实受控会话；独立协议测试与原生应用桥接验收；不靠mock声称真实CLI互通 |
| MCP-02 | 连接与工具作用域 | 默认关闭；明确允许的连接/活动会话、工具、路径与上下文范围；应用端每次请求复核当前权威策略、会话/路线身份 | 取消授权立即阻止后续请求和排队任务；旧会话ID不能指向重连后的新会话；凭据/主密码不经过模型或MCP客户端 |
| MCP-03 | 读取与审核式动作 | 先提供允许会话元数据、用户授权的有界终端片段、SFTP目录/常规文件与固定监控读取；命令/文件修改仅创建明确提案，由应用用户确认 | 任意shell不能因“只读”标签自动运行；批准绑定精确目标、参数/内容摘要与单次有效期；客户端无自行批准接口；等待/拒绝/取消/结果未知有明确状态 |
| MCP-04 | 本地连接与文档 | 提供Claude Code/Codex配置示例、连接/工具检查与诊断；stdio bridge使用受认证的本地IPC，GUI未运行或目标未连接时返回可识别错误 | 不自动解锁vault或代登录SSH；公开示例仅占位符；stdout保持协议输出，诊断有界且脱敏；不暴露通用第三方MCP客户端 |
| AI-AGENT-01 | DBX式工作流 | 模型API、本地智能体共用配置选择、目标/上下文条、Ask/Agent、步骤记录、停止及审核；工具能力按供应商实际支持显示 | 当前连接/上下文清晰可见；Agent真实步骤与建议分开；工具授权不因模型/插件返回文本而扩大；回合预算终止有证据 |

本地智能体进程属于 AI 后台服务，不属于本地终端管理。它也不代表模型离线：CLI可能使用云端账户、网络与自身日志策略，发送前须展示运行方与上下文；不能因“本地CLI”隐藏数据发送边界。

服务端工具命名暂拟为 `keelshell_list_sessions`、`keelshell_read_selection`、`keelshell_sftp_list`、`keelshell_sftp_read`、`keelshell_monitor_snapshot`、`keelshell_propose_command` 和 `keelshell_get_action_status`，最终以版本化schema为准。一般SSH文本不具有可靠的只读判定；执行提案沿用现有人工审核，不提供模型自行解锁或确认的捷径。

## 工程顺序

1. **设计基础**：明暗语义token、System设置与迁移、系统外观变化；形成主要工作区明暗基线和组件状态规范。
2. **逐屏升级**：连接/终端/监控、文件与任务、AI配置/聊天、更新与凭据；同步修复可访问性和实际滚动/最小窗口问题。后续多步骤任务界面使用同一体系。
3. **共享AI契约**：区分API与LocalAgent配置；统一上下文快照、取消、预算、步骤和操作提案；实现明确的版本能力探测。
4. **MCP服务端最小闭环**：stdio入口、应用桥接、授权策略和少量读取工具；先验证外部客户端读取，随后加入应用端审核提案。
5. **本地智能体**：Codex与Claude Code的Ask适配，然后受限Agent与应用端审批；不静默复用任意用户插件、hooks或工具配置。
6. **完整验收**：真实CLI/MCP互通、恶意/失效请求、撤权/重连、进程清理，以及三平台明暗原生矩阵。编译、fixture和原生各自记录。

原有传输/目录/批量任务等目标继续保留；优先收敛已经开始的后端切片，再进入主题基础，避免反复新增硬编码界面。本文没有授权遥测上传、自动安装CLI、读取用户登录文件内容或覆盖已安装应用。

## 参考与研究边界

DBX官方文档明确描述了本地Claude Code/Codex配置、Ask/Agent与受限工具访问；其MCP文档描述对外工具和服务端作用域。采用这些交互原则，SSH授权按KeelShell自己的会话/路线/文件模型实现，不复制数据库规则。见[AI助手](https://dbxio.com/cn/docs/ai-assistant)、[MCP集成](https://dbxio.com/cn/docs/mcp)和[已有本机观察](../research/dbx-ai-reference.md)。本轮没有查询数据库、调用模型或改变DBX配置。

已只读检测本机Codex CLI `0.160.0` 与Claude Code `2.1.285`的版本/帮助。Codex官方提供JSONL非交互输出与app-server结构化协议；Claude Code官方提供程序化运行与流输出。适配器需按支持版本测试，不能把帮助命令当作登录、付费账户或真实工具互通验收。见[Codex非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[Codex App Server](https://learn.chatgpt.com/docs/app-server)和[Claude Code程序化调用](https://code.claude.com/docs/en/headless)。Codex长期交互优先评估app-server，单次exec仅用于最小Ask闭环；Claude Code需验证官方程序化审批路径，不从终端提示文本猜审批状态。

[MCP官方传输规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)已检查。它与旧协议的消息/取消模型存在差异，实现前须锁定SDK兼容范围并测试协商，不硬编码历史版本行为；本计划不新增第三方MCP客户端。
