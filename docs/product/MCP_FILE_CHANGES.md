# 外部智能体提议远程文件修改

外部 MCP 服务新增 `keelshell_propose_file_change`。它只把精确现有文件的完整替换提交给 KeelShell 人工审阅；外部智能体不能批准或自行写入。应用内 API / CLI Ask 保持独立。

1. 在真实已认证 SSH 会话打开 MCP，勾选“提交待审文件修改”，填写要授权的 canonical 远程目录，再明确授权。默认没有勾选任何能力。文件提案与读取文件分别授权；模型文本不能扩大目录或读取权限。
2. 客户端使用确切 `target` 三个 UUID、`path`、`expected_sha256` 和 `replacement` 提案。旧 hash 必须来自完整原文；已授予 `keelshell_sftp_read` 时，读取结果包含完整 UTF-8 `text` 与对应 `sha256`。
3. 提案 API 后台复核已存在的常规 UTF-8 文件及旧 hash，仅回传 pending 提案 ID/digest。没有读取授权时，当前原文及当前 hash 不通过成功/失败响应泄露。错误只能说明提案不能被接受，不可据此区分原文内容。
4. 回到 KeelShell 的操作提案，打开完整文件审阅，核对目标路径、SSH 路线、连接/会话/路线 ID、前后 hash 和全部 diff。diff 显示旧正文每行删除与替换正文每行加入；不可见控制和方向字符显式转义，未以转义显示执行字节替换实际正文。
5. “暂不处理”保留待审提案；“拒绝修改”结束该提案。只有明确点击“确认完整目标并替换文件”才消费一次批准并写入捕获的原 SSH 连接。有效期 300 秒，重连、路线变更、换 SSH handle、重新授权或撤权均使旧批准失效。
6. 查询 `keelshell_get_action_status` 的 `action_kind`（`command` / `file_change`）和原有 `state`：等待、拒绝、到期、取消、运行、成功、失败、结果未知。文件修改结果未知时先独立核对远端，不能自动重试同一提案。

旧文件与替换正文分别最多 64 KiB；替换可为空，但文件必须已经存在。不支持新建、删除、移动、符号链接、特殊对象、非 UTF-8 或不完整内容。JSON-RPC 请求整个编码帧仍限制为 128 KiB，大量转义字符可能先触及该限制。提案、原文、diff、输出和授权只在本次应用内存中，应用退出不恢复。

写入要求远端真实支持 OpenSSH POSIX rename version 1。临时文件完整写完并关闭后才替换原目标，缺扩展时没有非原子回退。staging 前和 rename 前复核完整旧内容、大小、mode、mtime 与 canonical 路径；最终读回精确 replacement。只保留既有 writer 的 rwx 权限策略，ownership/ACL/special mode bits 可能改变。SFTP v3 的检查是观察，不是阻止恶意远端并发替换的原子锁，结果未知也不代表取消已经回滚远端。

历史供应商客户端七项 schema 的实验继续保留原范围；新增第八项工具已在新标准 macOS 开发包和自有外部客户端中通过实际文件审阅闭环，供应商调用和其他平台原生须另行建立。实现与门禁见 [ADR0051](../adr/0051-reviewed-mcp-file-replacement.md) 和 [开发记录](../testing/records/2026-10-05-mcp-file-proposals.md)。

A 的作者门禁通过后，新独立复核发现失败重新授权会泄漏准备配额的 P2；A 的失败材料保持。B 修复准备任务的 generation/ID 所有权生命周期，完整作者门禁、新非作者限定复核及主树完整门禁通过。新 macOS 八工具自有客户端实际批准后精确读回、拒绝后保持和已观察并发修改拦截通过；首次原生操作失败保持，最小原生三主题双语矩阵、外部供应商和发布验证仍分别开放。

## 撤权时的远端读取边界

撤权取消本地准备任务并阻止旧结果进入新审阅，不承诺已经停止服务端
正在处理的 SFTP READ。受控复核中，反复替换授权后旧本地 worker 已为零，
服务端阻塞读取仍可等待 READ 返回，随后处理关闭并释放。界面准备计数
仅表示当前本地所有权，不能解释为远端跨授权的全局任务上限或完成证明。
