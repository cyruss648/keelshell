# 远端监控能力与按项降级

## 2026-11-16 macOS 扩展

本批增加 macOS 远端只读资源及进程列表。真实 Mac SSH 六项、Linux 能力恢复
两项 opt-in、正常 GUI/MCP 构建及全部非作者范围复核通过；
最终集中工程门禁 r3 通过，713 项输入与 52 个新增默认 Rust 名已逐项核对。
真实远端监控不替代新卡片的桌面、键盘、IME 或辅助技术验收。

| 项目 | Linux | macOS |
| --- | --- | --- |
| CPU / 运行时间 / 负载 | `/proc` | Mach / 系统接口 |
| 物理内存 | 总量与内核 available 估计 | 总量与空闲页；used/available 估计未知 |
| 网络累计字节与采样速率 | `/proc/net/dev` | 系统接口实际计数 |
| 文件系统容量 | 可选 `df -Pk` | 可选 `df -Pk` |
| 进程列表 | 固定 `ps` 列 | 固定系统 `ps` 列，只读 |
| 磁盘 I/O / iowait | 独立采样，缺失时未知 | 未支持，不能显示成 0 |
| 监听端口 / 进程核对与终止 | 显式读取/审核操作 | 未支持；终止入口不提供 |

macOS 需要远端已有 Python 3；不会自动安装。解释器缺失按连接负缓存，
用户显式重新检测后才重试。空闲页不是可用内存估计，界面单独标明，
内存趋势和 MCP used 字段不从空闲页推算。两平台计数器不能直接相减。
详见 [ADR 0143](../adr/0143-darwin-resource-monitoring.md)及
[本批记录](../testing/records/2026-11-16-host-monitor.md)。

## 用户行为

当前认证SSH连接中的CPU、内存、网络和磁盘信息来自真实采样。
文件系统容量、进程列表和监听端口分别依赖远端可用接口；
一个可选接口不可用时，保留其他可用信息，并说明不可用项及原因。
不能把权限不足、命令缺失、格式不支持或未知结果表示成零。

监控区域显示各项当前能力。只有证据充分时才区分命令缺失、选项不兼容、
权限受限和格式异常；无法确定时保留未知。连接/传输失败独立报告，
不从一次SSH故障推断远端工具不存在。

用户可显式重新检测。已确认不可用的可选命令不随每轮刷新重复执行；
重新检测后按实际结果恢复可用项。检测不安装软件、不提权、不改变远端配置。
旧数据保留时说明其年龄和状态，不能让旧值看起来是新的成功样本。

## 归属与资源

能力与采样都属于当前认证连接。新连接重新建立状态；
旧任务、暂停前任务及迟到回复不得覆盖新状态。
后台worker执行有界SSH操作，绘制和主题/语言切换只读取已有状态。
暂停后不自动检测或采集，显式操作的范围与反馈应在界面明确。

沿用霜白、曜石、雾紫注册表、语义token和GPUI Kit控件。
原因说明具备中英文文本，紧凑窗口中可以访问重新检测和采样控制。
CPU/内存趋势的未知值、时间轴和断段合同继续遵循[资源趋势](HOST_RESOURCE_TRENDS.md)。

## 验收

- `df`缺失、不兼容、失败时，可读的核心资源仍成功返回。
- `ps`、`ss`的能力分别处理，未知原因不误归类，缓存避免重复无效命令。
- 显式重新检测可以发现修复后的接口；重连、暂停ABA及迟到完成被隔离。
- 暂停、绘制和主题/语言切换期间无新增自动采集。
- 实际命令、模型测试、受控SSH、完整工程门禁和开发包原生观察分别留证。
