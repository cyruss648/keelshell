# 原生工作区

工作区按全局操作、连接导航、当前会话和工具区组织。霜白、曜石、雾紫共享同一布局；
主题家族、明暗模式与布局状态分别管理，增加主题不需要改业务视图。

## 响应式工作区层级

2026-11-13 的工作区视觉切片为窄窗口保留明确的专业工作台层级。900×580 的
紧凑布局中，新建工作区窗口、AI、凭据库和配置备份/恢复入口都保持可见；动作
可以使用图标理解，并通过完整双语 AccessKit label 和 tooltip 保留语义。AI
助手列按窗口宽度的 34% 计算，并限制在 240–360px，避免打开后把活动终端压缩
到不可用尺寸。

连接导航和主机监控共享同一 rail，但各自有持续可读的 header。紧凑连接导航
使用 236px，主机监控使用现有 260px 监控根布局；header 高度来自
`ChromeTokens::pane_header_height`。工作区 rail 使用 `Group` 语义并标记为
“工作区导航”/`Workspace navigation`，当前 panel 分别标记为“连接导航”/
`Connection navigation` 和“主机监控”/`Host monitoring`。

本片继续复用 registry、Palette、组件和 chrome token。三套主题不在工作区视图中
按 theme id 分支；新增主题仍只扩展 registry 和对应 token。键盘动作、现有 focus
handle、SSH 会话、AI 审核和配置状态沿用原路径。

## 连接和主机信息

连接后，左侧默认显示保存的 SSH 连接，按文件夹层级排列。搜索匹配连接的现有字段；
父文件夹保留，便于辨认结果。点击文件夹可折叠或展开；搜索临时展开匹配路径，
改变搜索重新展开，清空后恢复原浏览折叠状态。折叠偏好目前只保留在本次进程内。
“新建连接”打开连接编辑器；“管理连接”提供完整的收藏、回收站、导入导出等操作。
导航搜索与管理器复用查询文本，但管理器的收藏、回收站和文件夹过滤不会隐藏侧栏连接。

已有会话必须仍然存活且与当前保存的目标、跳板和信任绑定一致，才会显示为已连接并切换过去。
修改连接目的地不会改变已经打开的 SSH 会话；点击修改后的连接会进入正常认证和主机密钥审核。
被删除的旧连接行不能连接同名替代项。

搜索框按向下键进入连接树，Tab/Shift-Tab 可进入或离开。树内支持：

| 按键 | 操作 |
| --- | --- |
| 上 / 下 | 移动到上一个 / 下一个可见条目 |
| 左 | 折叠当前文件夹；已折叠或叶条目回到父级 |
| 右 | 展开当前文件夹；已展开则进入第一子项 |
| Home / End | 选择并显露首项 / 末项 |
| Enter / Space | 松键后展开文件夹，或连接 / 切换所选会话 |

移动选择不会发起连接或发送命令。查询、删除、隐藏导航或打开弹窗后，
旧按键不能激活替代条目；从树开始长按的键不会随鼠标切换流入另一 SSH 会话。
同时按住 Enter 和 Space 会取消这次激活，需松开后重新操作。
删除或过滤当前项会选择仍可见的原父级，必要时继续回到上层祖先。
当前会话文字与键盘选择分别表达，浏览其它连接不会切走会话。

“主机信息”显示当前会话的既有监控与诊断面板。页面切换保留这些实体和原始会话身份，
不会凭保存的连接生成在线状态，也不会自动执行命令或发送 AI 上下文。

## 会话和工具

会话标签位于终端上方的独立栏，支持水平滚动、前后切换、新建和关闭。
会话数量、每个标签的连接语义和上一个/下一个会话动作也持续可见；macOS 使用
Command-Option-Left/Right，Windows/Linux 使用 Control-Alt-Left/Right。快捷键只
切换已有会话，不创建连接、不发送命令，也不覆盖当前草稿。
窗口尺寸或侧栏变化后，活动标签的关闭入口重新显露；正常渲染不打断用户的手动滚动。
全局设置和主题按钮保留在最上方。

终端下方保留多行命令草稿、准确的审核目标、执行按钮和独立补全目录。
紧凑补全只调整布局，不把补全目录当作远程 shell 的当前目录，也不因切换面板自动查询。
文件、命令和隧道入口标明当前选择；隐藏后重新显示使用原来的面板和草稿。

顶部侧栏按钮可收起连接区。窗口宽度不足 1280 时，显示 AI 助手会让出左侧空间；
此时主动打开连接区会收起 AI，保留 AI 实体和草稿。AI 侧栏在窄窗口按有界比例
分配宽度，连接导航在紧凑宽度收窄到 236px，监控页保留 260px。侧栏被窗口调整隐藏时，
其中的输入焦点回到工作区背景，避免继续编辑不可见搜索框或把后续按键送入终端。
侧栏显示偏好和选中的导航页目前只属于本次应用进程。

AI 助手使用“捕获、提问、预览、发送、审核回复、保存知识”六阶段轨道表达当前
审核边界。回复到达后会把回复审核区显露到正文滚动视口，长上下文仍保留完整滚动
查看；知识保存动作固定在助手底部审核栏，Agent 停止并编辑问题会在最新布局后
显露问题输入框；模型输出不会自动执行命令、修改文件或保存知识。详细流程见
[AI 助手审核工作流](AI_ASSISTANT_WORKFLOW.md)。
