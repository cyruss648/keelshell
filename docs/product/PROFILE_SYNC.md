# 端到端加密连接配置同步

KeelShell 可由用户显式开启连接元数据同步。两个独立客户端通过同一个用户选择的共享或网络挂载目录交换认证加密快照，分别执行「读取并审核差异」和「批准、启用并发布」。读取不会创建快照、修改配置、连接 SSH 或执行命令。这是双端状态同步，不能用一份本地加密导出文件替代。

## 使用流程

1. 先为两台设备提供共同访问的目录。该文件系统须支持所有参与客户端之间的协作文件锁和原子文件替换；KeelShell 不创建云账户，也不负责挂载或网络传输。仅复制文件的最终一致云盘缓存不能保证本功能的跨客户端 CAS，不能作为已经验证的传输。
2. 在第一台设备的连接管理器打开「加密同步」，填写绝对目录和同步密码，读取差异。空目录会提出创建新的同步空间，但不会立即写入。
3. 对每条连接选择本地或共享版本；添加、修改和删除均参与审核。完整选择后，核对全部路线影响及本机文件夹保留映射；有影响时需单独确认，修改任何选择都会撤销这份确认。再次输入本次密码，明确批准后保存本机配置并发布加密快照。
4. 第二台设备填写自己的挂载路径和相同密码，读取已认证同步空间。对每条差异选择版本后批准，保存本机配置并发布共享状态。
5. 后续离线修改必须重新读取。双方改变同一记录会标记冲突，不能省略、额外添加或替换未展示的审核项。其它设备再次读取后取得明确选择的结果。

差异按完整记录审核，列表每页 20 条，所有页的选择保留，未审核全部差异时批准不可用。确认与取消操作位于独立固定底部区域，长内容在正文滚动。默认中文，同时维护英文及两种主题。

## 数据边界

同步的结构只表示连接 ID、显示名称、旧式分组标签、主机、端口、远程用户名、标签、收藏、跳板 ID、非秘密代理元数据和重连偏好。文件夹树与具体文件夹放置保持本地；新接受的连接放在本机根目录。已经分配本机文件夹的记录明确显示本机保留位置及最终本机分组显示，共享旧式分组标签单独保存在同步基线，不覆盖文件夹派生路径。首次同步时本机文件夹路径不会变成共享标签；随后改名、重分配、移至根目录或删除空文件夹不会制造共享编辑。未分配文件夹的普通旧式标签按选择正常同步。已从本机回收站接收恢复的记录保留本机文件夹位置。

密码、私钥路径与内容、认证方式、vault 引用和密文、主机信任、AI 设置与密钥、历史、审计、远程输出及会话运行状态均不进入共享结构。已有完全相同目标与完整路线保留本机认证配置；新导入或目标路线改变的连接使用本机 SSH Agent 默认值，需要由用户另行配置认证。父跳板的地址、账户或代理改变也会影响未直接编辑的下游连接：确认区上方按页列出每个受影响连接的完整前后路线及认证引用撤销。批准后仅清除配置中的认证方式与 credential 引用，不删除 OS/vault 中的凭据条目。同步不会改变正在运行的 SSH transport 实例，删除保存的连接也不会自动断开在途会话。

## 版本、删除与恢复

每条记录带设备版本向量。删除保留认证墓碑，不因另一台设备持有旧配置而自动复活；同时删除与离线编辑需要明确选择。接受共享记录只确认已有版本，不制造回声编辑。接收远端删除时，本机回收站记录本机批准的接收时间，不将远端未同步时钟或 epoch 0 当作删除时间。

本机记录已认证的空间身份、共享 generation、SHA-256 摘要和记录基线。旧 generation、同 generation 的不同密文、消失的已见记录或墓碑、降低的记录版本及同版本改写均拒绝。已经建立关联的客户端拒绝换目录或换空间。新客户端以及用户明确解除关联后的客户端没有外部版本锚点，不能证明共享目录没有在它第一次接入前遭到回滚。

本地状态与共享快照属于两个不同文件。保存的批准先进入本机原子状态，记录待发布密文和非秘密版本收据，再执行共享 CAS 与原子替换，最后保存本机确认。中断或发布失败时，不称为同步完成。用户可以重新输入密码继续同一份密文，已发布的相同密文仅完成确认而不重复增加版本。如果共享版本后来变化，可以明确放弃未发布收据并重新审核，已经批准的本地选择保留；已经发布的收据必须先继续确认。

「关闭同步」保留版本锚点、本地配置与待完成批准。「解除本机同步关联」需要第二次确认，保留本地连接和共享密文，但丢弃本机回放保护。丢失密码无法解密远端快照；可保留本机连接，明确解除关联，并选择新的空共享目录、新密码重新建立空间。不会自动删除、重置或覆盖无法认证的原快照。

## 加密与验证边界

同步复用凭据库的固定 Argon2id（64 MiB、3 次、1 lane、32 字节 key）和 XChaCha20-Poly1305，实现单独域、随机盐和随机 nonce。KDF 参数先验证，整个连接快照位于认证密文中。每次操作密码只进入 zeroizing worker 所有者；派生 key、KDF 工作内存、临时明文均使用 zeroizing 所有者。提交后清空 masked 输入及其撤销历史。GPUI 输入的短暂编辑分配不提供锁页或所有分配副本的内存擦除保证，不能宣称具有这些保障。

最多 2,000 条同步记录，每条最多 64 个设备版本。共享 envelope、应用状态均受 4 MiB 文档上限约束，明文快照最多 2 MiB；超过限额拒绝而不截断。2,000 条是记录计数上限，并非任意大小的连接都能达到该数量；待发布本机状态同时保存密文和非秘密收据，其总字节限制可能更早达到。界面明确报告容量错误，现有本机和共享内容保留。文件锁只协调遵循约定的客户端，不防御持有解密密码的恶意写者或同用户进程替换路径。

已实现候选包含双隔离客户端文件状态测试、认证后 wire 反例和生产 GPUI handler/布局测试。最终作者门禁、非作者复核和原生验收见[测试记录](../testing/records/2026-10-06-profile-sync.md)。真实跨机器网络挂载、最终一致文件同步器、Windows/Linux 原生桌面和云服务验收尚未完成；没有上传真实配置，也没有覆盖用户应用。

## 与已批准的内存定时计划共存

同步面板的保存租约覆盖持久配置与延迟摘要，不接管已有 SSH 的命令审核权限。
隐藏的已批准定时计划仍绑定原认证连接及原精确参数命令，同步批准不会执行
命令、自动重连或把授权转移到导入的连接。保存的配置变化不等价既有连接实例
变化；真正的捕获路线/连接变化和静默参数编辑均需撤销等待授权。参数、展开
命令、输出与定时账本不同步、不落盘。新组合的受控证明和未验收范围见
