# 主题与外观

工作区工具栏的“主题”打开原生选择器；连接管理器顶部也有同一入口。

| 内置主题 | 推荐外观 | 风格 |
| --- | --- | --- |
| 霜白 / Frost | 浅色 | 灰蓝底色、轻边框、清晰列表、海军蓝终端 |
| 曜石 / Graphite | 深色 | 暖黑石墨、琥珀强调色、小圆角、近黑终端 |
| 雾紫 / Lavender | 浅色 | 低饱和紫灰、柔和圆角、深紫终端 |

“应用 · 浅色/深色”保存主题和推荐外观，保存成功后立即生效。随后可单独选择浅色、深色或跟随系统。每个主题都有浅深两种配色，系统变化不会覆盖主题选择或写入配置。选择器保留当前主题名称、应用状态和保存失败信息。

主题保存在本机设置中。旧配置会使用霜白，并保留之前的明暗模式。加载到尚不支持的主题 ID 时会显示霜白并说明回退原因，原 ID 不自动丢弃。

切换主题不改变分栏布局、已连接会话、未发送命令和编辑草稿。终端默认色随主题变化，程序明确指定的 ANSI/truecolor/OSC 颜色继续生效。主题切换不执行命令、不发送 AI 上下文。

这是内置主题选择功能；自定义文件导入和下载主题尚未提供。实现及验证边界见[测试记录](../testing/records/2026-11-04-native-themes.md)。

## 新增主题

1. 在 app 的 `design/registry.rs` 增加 `ThemeDefinition`，包含稳定 ID、双语说明、推荐外观、浅/深 Palette、组件圆角和终端默认色。
2. 加入 `registry()`；选择器自动列出新项。核心设置无需枚举新 ID，业务视图无需增加分支。
3. 运行设计 token、主题持久化与 Workspace 切换测试，并执行完整工程检查。
4. 在主要界面和实际原生窗口检查焦点、输入、列表、错误提示、长文字和最小窗口；补充测试记录。

更多主题数量下需要单独验证选择器布局，当前三个内置项的布局测试不能直接外推到任意数量。主题文件格式或插件机制需要新的设计决策。
