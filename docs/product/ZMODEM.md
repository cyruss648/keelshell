## 使用流程

在已经连接的远端 SSH 终端里启动 `rz` 或 `sz`。应用检测完整且校验有效的
协议起始帧；普通日志或不完整的相似文本不会自动授权传输。检测本身不运行
远端命令，也不建立第二条用于替代终端的 exec 通道。

上传时，远端接收请求触发本地文件选择。选择后先显示真实 SSH 目标、每个
完整本地路径、文件名、字节数和 SHA-256。确认时重新核验源文件及连接；
源、选择或审核变化需要重新准备。应用只发送经过这次确认的文件。

下载时，每个远端文件单独显示文件名及声明长度，用户选择一个新的本地文件名，
再审核并确认。只有完整接收、私有 staging、无覆盖发布及完整读回均通过后，
才出现“已验证保存”的回执。后续文件需要分别选择目标和确认；已有本地文件、
目录或链接不会被覆盖。

传输占用当前终端期间，键盘、粘贴、鼠标协议、AI 命令和终端自动回复的普通
输入会被拒绝。旧排队输入不会在完成后重放。退出或取消需要等待协议写入及
精确输入交接；若远端在已开始的普通写入被流控阻塞时启动协议，桥接会停止
继续发送，并保留已经发送前缀的未知风险。

## 结果与限制

协议上传只能说明数据交换结果。远端 `rz` 控制目录、覆盖与保存策略；
应用不能据此证明它保存的最终路径、未覆盖既有远端文件或保存后的内容。
取消也不证明远端删除了已接收的数据。

下载结果未知时，本地目标和 staging 的隔离记录继续保留，与 SFTP 的目标互斥
共享。之后的成功不能清除先前未知结果。关闭前的两次风险确认只允许用户确认
已核对的未知结果，不清理文件、不释放后台仍在工作的写入，也不解除后端隔离。
不会自动重试不确定的写入。

目前本地文件观察和安全发布后端支持 macOS/Linux；Windows 后端显式返回
`Unsupported`，不能把协议编译、错误分支或 headless 检查表示为 Windows
文件传输已完成。Windows 安全后端与三平台桌面、IME、辅助技术及发行验收
继续列入路线图。

本批实际观察到 Debian `sz 0.12.21rc` 和 macOS lrzsz `0.13.1` 直接连接 PTY 时，
部分下载在完整保存之后、收到 ZFIN 之后退出 `0`，但应用没有收到最终 `OO`。此时单文件
“已验证保存”与整批协议成功分别报告；不因为退出码为 `0` 就补签握手完成。
同一独立 peer 经临时管道转发到真实 SSH PTY 的对照检查通过，但不替代
直接 PTY 兼容验收。该兼容缺口继续开放，具体失败及对照见本批测试记录。

## 协议与预算

- 支持 HEX/BIN16/BIN32 头、CRC16/CRC32、控制字节转义、增量分片、ACK、
  ZRPOS 重传、取消及 ZFIN/OO。
- 最多 32 个普通文件，每个不超过 64 MiB，总量不超过 128 MiB。
- 文件名必须是可移植 UTF-8 basename；拒绝路径分隔符、穿越、设备名、
  alternate data stream、重复及大小写别名。
- 必须声明长度，并核验完整内容长度。协议流量、分片、包数、重试和等待都有界。
- 拒绝 ZCOMMAND；任何协议内容都不能转化为可执行终端命令。

core 只负责纯协议；session 负责文件、连接及审核；app 负责唯一 PTY 写入通道
和原生审核。Frost、Graphite、Lavender 共用注册表、Palette 与组件 token，
完整审核正文滚动，确认和取消位于固定动作区。

设计见 [ADR 0136](../adr/0136-reviewed-pty-zmodem.md)。
