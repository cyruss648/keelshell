## KeelShell 设计决定

1. 独立 AI 设置：命名配置目录、默认配置、供应商预设、协议、认证引用、端点、模型、Token 限额、显式代理与连接测试。配置名用于区分个人、团队网关和本地模型。模型列表发现失败仍可手动输入。
2. 聊天栏：配置/模型选择、与会话绑定的目标、可移除上下文项、问题输入、停止、回答中的复制/插入命令栏。避免在每次聊天时填整套服务配置。
3. Ask 负责解释输出、生成命令、分析已选片段；诊断 Agent 将来使用明确、窄化的远程读取工具，显示每一步的目标、输入和结果。任意 shell 文本不能仅凭模型自称“只读”而自动执行。
4. 远程文件建议显示原文与修改差异，再由用户写回；命令建议绑定原 SSH 会话且进入审阅栏。切换标签不改变在途请求或建议的目标。
5. 元数据与凭据分开。持久 JSON 不接受 API Key、请求头值或代理密码明文。请求头、代理、模型发现与聊天应使用同一套经过验证的配置，不能测试一个目标却发送到另一个目标。
6. 协议在模型层可表达，不等于后端已支持。UI 只启用真实已接通、测试通过的协议。未接通的 CLI 或高级能力只在路线图记录。
