# 远程 SSH 能力要求与验收标准

整理日期：2026-10-03（Asia/Shanghai）；历史研究始于 2026-10-02。本文件保留匿名历史研究中形成的通用需求，并按当前远程专用范围整理。原始来源记录已在 ignored 私有研究备份中保留；公开文本不再作为外部产品的官方功能或版本证明。这里的功能要求、优先级和视觉方案属于 KeelShell 自身产品目标。

当前范围仅包括远程 SSH 管理。本地终端、远程桌面与串口不属于本产品目标；早期研究中的相关设想不再作为当前验收要求。密码学安全、SSH 算法兼容、代理/跳板、传输恢复、原生输入法和跨平台行为均需实际验证，不能由网页描述推断。

本文是目标与验收计划。真实实现状态见[能力清单](../product/CAPABILITIES.md)，当前交互见[产品设计](../product/PRODUCT.md)，历史界面研究的证据限制见[工作区观察摘记](remote-workspace-reference.md)。

2026-10-04新增：默认系统明暗主题、统一专业界面、本地Claude Code/Codex智能体，以及对外MCP服务端，见[正式计划](../product/DESIGN_AND_AGENT_PLAN.md)。本地AI进程不构成本地terminal管理；不增加通用第三方MCP客户端。此处历史浅色方案不覆盖新主题要求。

## 2. 工作区设计

当前工作区采用“会话 — 远程主机监控 — 终端 — 文件/命令工具区”的组织方式。顶部提供连接管理器和会话标签，左侧展示远程监控，中央保留可拆分终端，底部按需展开文件、命令、隧道与后续传输任务。AI 侧栏按需打开；窄窗口折叠辅助区域，避免终端不可用。状态持续显示真实目标、用户、连接状态；跳板路径和目录等信息只有接通真实数据时才展示。连接树、布局比例等细节以[当前产品设计](../product/PRODUCT.md)为准。

主页只显示用户真实保存的连接、最近工作区和未完成任务；没有连接时提供新建 SSH 连接，并在导入流程接通后提供导入入口。示例数据必须有明确 Demo 标识，不能显示虚构在线主机和性能。

AI 窗口不是独立聊天玩具：从已选择的终端输出、进程、文件 diff 或失败任务进入；上下文胶囊显示“目标主机 / 时间范围 / 内容预览 / 是否已脱敏”。建议命令先成为可编辑草稿，通过“送入输入框”与“执行”区分准备和操作。多主机、删除、权限、服务重启、数据库写操作等必须展示实际对象及预期影响。

配色采用白色与浅灰工具面板、深色终端、蓝色操作强调，待审阅状态使用清晰提示；错误保持红色，生产环境独立标识但不使整窗刺眼。字体、间距、键盘导航、中文输入法、屏幕阅读器可达性与缩放属于完成标准。

## 3. AI 能力和执行边界

AI provider 作为可替换模块，首期支持配置自定义 endpoint/model 的 OpenAI-compatible 协议与本地模型；固定模型名不得写死为长期默认。是否支持流式、结构化输出和工具调用须按 provider 能力探测，认证信息交给凭据模块。

每次模型请求只发送用户选定上下文。口令、私钥、令牌、环境变量敏感值和真实连接凭据不进入模型消息或遥测；远端输出视为不可信数据，其中的“忽略规则并执行”不能提升权限。红线由执行器校验，不依赖模型自己遵守。

推荐执行状态机：草稿 → 已解析 → 待授权 → 执行中 → 成功/失败/已取消/结果未知。网络超时后远端可能已执行，必须记录“结果未知”，不能自动重发写操作。每次授权绑定主机集合、规范化动作、参数、文件 hash、有效期；模型修改动作后旧授权失效。用于主机状态诊断的读操作也受输出量、耗时、并发与路径范围控制。

首批最有价值的场景：解释 SSH 握手/认证错误；从已选日志中定位假设及证据；解释陌生命令；将自然语言转为可审阅的 shell；比较配置 diff；依据 CPU/内存/连接数据生成排查顺序；把已完成操作生成脱敏 runbook。后期再加入跨主机计划和变更执行。

## 4. 分期退出标准

| 阶段 | 必须真实可用 | 不能替代的验证 |
| --- | --- | --- |
| M0 工程与协议骨架 | 名称、工程结构、配置、安全模型、架构决策、CI、能力清单 | 编译空壳不等于 M1；UI 截图只证明渲染 |
| M1 可用会话核心 | 原生 GPUI 窗口、SSH PTY、连接持久化、指纹校验、基础 SFTP | 受控 sshd 真实连接、键盘输入、退出、resize、文件往返 hash |
| M2 日常运维 | 文件完整流程、监控、终端效率、分屏、远程编辑、AI 解释/命令草稿 | 协议集成测试 + macOS 本机 UI 演练；Linux/Windows 分别原生验证 |
| M3 高级工作流 | 三类隧道、批量执行、进程/网络、诊断、AI 有边界执行 | 异常注入、取消清理、部分失败、授权绑定与结果未知测试 |
| M4 完整范围验收 | Zmodem、归档传输、加速/中继、同步、安装与更新 | 逐项验证本能力矩阵；三平台原生验收及公开完成度记录 |

M4 的远程加速需要可运行的中继服务和可重复网络实验。只有本地端口转发不构成网络加速；本地加密导出不构成跨设备同步完成。这些属于仍需完成的能力，不能从最终目标中静默删除。

## 5. 测试记录与验收证据格式

建议每次测试记录：时间、Git commit、平台/架构、工具链、命令或操作步骤、fixture 版本、结果、输出位置、失败原因、未验证范围。集成环境仅使用临时密钥、临时端口、临时目录；不依赖个人真实服务器。

自动测试层级：领域单元测试（配置、排序、路径、策略）→ 协议测试（临时 sshd、SFTP、隧道）→ 真实 PTY/TUI 回归 → GPUI 交互 → 跨平台原生验收。协议 mock 可测边界，但至少一个 OpenSSH 服务端矩阵必须验证实际互操作。

完整终端不是“stdout 文本追加框”：ANSI parser 的单元测试仍不证明渲染、输入法和 TUI 行为；截图不证明 SSH/SFTP；交叉编译不证明目标平台可用；AI mock 不证明真实 provider。报告必须逐层限定证据。
