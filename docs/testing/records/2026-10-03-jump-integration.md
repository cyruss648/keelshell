## 实现与独立审查

连接编辑器可从已有配置选择跳板，支持搜索、分页和明确的直连选项；自身、循环、缺失或超过四个跳板的路线不能保存。连接时依次展示当前跳、完整路线、独立认证和指纹审批，最终仅目标进入终端标签与最近记录。目的地由上一跳解析，没有直连回退或本地监听代理。

每次连接持有自己的父链，不复用其他标签的会话。关闭或取消使请求 token 失效，迟到认证结果、保存回调不能恢复被取消的请求。保存忙碌期间下一跳暂停，保存完成后再检查当前配置。加密凭据版本 2 绑定规范化路线前缀与最终认证；旧版本仅允许直连。最近记录保存前重新比较完整配置快照，包含上游认证变化。

连接编辑保留固定按钮与滚动正文；认证普通/解锁模式为 480、保存模式为 560、指纹审批为 480 的逻辑高度上限，并受窗口高度限制。完整路线使用浮层，连接进度卡不抢占已有编辑器焦点。

领域、协议、工作区状态机分别进行了交叉只读审查，无阻断发现。额外补充取消请求 A 后立即启动 B、目标凭据 Save → Unlock 两项真实协议回归后再次独立核对。审查不替代运行证据。

## macOS 原生验收

通过 `packaging/package.py` 使用本机 debug 二进制生成独立 `.app`，指定 isolated `KEELSHELL_DATA_DIR`；未安装或替换现有应用。启动两个仅监听回环地址的 SSH 夹具，跳板仅允许把 `target.fixture.invalid:22` 转发到指定目标夹具端口。终端只回显，SFTP 仅使用临时目录，exec 拒绝执行系统命令。

实机完成：

1. 在中文连接编辑器选择已保存跳板、保存，并核对自身选项不可选。
2. 先后核对跳板与目标的不同指纹，分别输入测试密码；只有目标出现终端标签，SFTP 列出目录和中文文本文件。
3. 中文命令经审核栏发送后完整回显；读取目标 `welcome.txt`。原生输入工具的逐字符中文输入未产生中文，改用粘贴并在发送前核对完整文本；未据此宣称系统输入法候选窗验收。
4. 重构建紧凑布局后重启，英文路线浮层明确展示两跳顺序。取消第二跳认证后，两个夹具端口只剩监听，没有已建立的客户端连接。
5. 重新连接两跳，目标回显 `echo verified-jump-route`，SFTP 再次读取中文文本。关闭唯一目标标签后，再次确认没有残留客户端连接。
6. 应用正常退出（exit 0）；两个夹具通过正常中断退出（exit 0），监听端口关闭，临时 SFTP 根目录均已移除。隔离 state 只有一个直接指纹、一个路线指纹和最终目标的最近记录。

最终原生二进制 SHA-256：`961a00595aa0b83414a6b5f482e2aa42470435081ee7aa52177a121a858f022f`。构建/打包日志在 `work/jump-native-build-final.log`、`work/jump-native-package-final.log`，结构化结果在 `work/jump-native/verification.json`。中文初次信任流程属于紧凑布局调整前的构建；最终构建复验了英文认证、取消、重连、终端、文件读取与清理。

## 证明边界

本机 GPUI 与真实回环协议测试证明上述受控流程，不能代表真实客户服务器、OpenSSH 全配置互操作、真实 Linux 监控、系统输入法或 Windows/Linux 桌面验收。SOCKS/HTTP 上游代理、外部 ProxyCommand、keyboard-interactive、已建立会话重连仍未实现；四跳上限由领域测试覆盖，原生验收使用一个跳板。异常未确认通道可能导致专属父链有界断开，详见协议记录。未创建发布标签。
