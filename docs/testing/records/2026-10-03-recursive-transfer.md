# 有界递归 SFTP 传输记录

日期：2026-10-03。范围：远程 SSH 文件面板中的目录上传/下载，不包含本地终端、递归删除、覆盖合并、断点续传或暂停。

## 实现与操作

- `keelshell-session/src/sftp/directory.rs` 实现不透明 `DirectoryTransferPlan`。`plan_directory_transfer` 只读扫描，记录源/目标、目录与普通文件的相对路径、类型、文件长度及可用修改时间；保留空目录。快照绑定最初 SSH 连接，不能转交给另一连接执行。
- `TransferQueue::enqueue_directory` 与单文件传输复用同一单 worker FIFO。执行前完整重扫并比较快照，然后逐项重新检查源类型、大小/修改时间和路径祖先。文件从打开后的句柄再检查元数据；下载使用远端 `fstat`。
- 文件面板输入本地绝对路径后点击“上传目录”，或选中远端目录后点击“下载选中项”。扫描结果显示完整源/目标、文件/目录数量、总字节和限制，用户点击确认才写入。审核操作持有原始快照，后续输入草稿不会更换目标。
- 字节进度、完成和取消沿用队列事件。目录错误/取消消息保留完整目标位置；取消和失败可能留下已完成文件、部分文件及空目录，不自动递归删除它们。
- “上传文件”和“上传目录”使用明确的独立入口。误将目录传给单文件上传时，在创建远端文件前拒绝。

## 限制与不变量

每次扫描最多 30 秒；一次队列目录执行（含再次扫描）最多 15 分钟。快照含根目录共最多 10,000 项，根下最多 32 层，路径最多 4,096 字节，总文件长度不超过 16 GiB。远端连续返回超过 16 个无进展的目录包会失败。所有等待由对应总 deadline 约束。

源和目标必须是有名称的绝对路径，不支持复制整个文件系统根。符号链接、特殊文件、未知远端文件类型和缺失文件长度均拒绝；扫描和执行检查所有静态祖先，不跟随预先存在的符号链接。macOS 临时目录经 `/var` 别名时，应选择其实际路径；测试夹具使用 canonicalized 临时目录，不放宽产品检查。

目录成员名按跨平台可移植子集验证：拒绝 `.`/`..`、斜杠、反斜杠、控制字符、Windows ADS 冒号、保留设备名、末尾空格/点等。每个目录拒绝重复名称和小写后重名。没有进行 Unicode 规范化或完整文件系统别名推断；剩余目标别名碰撞依靠独占创建报错，不覆盖原有文件。

目的根及每个目录必须新建。上传普通文件使用 SFTP `CREATE | WRITE | EXCLUDE`，下载使用本地 `create_new`；不使用会替换现有文件的 POSIX rename。独占创建避免有意覆盖，并使未完成文件保持可见。目录整体没有事务性，也没有承诺每个传输文件的原子可见性或崩溃持久性。已有 UTF-8 编辑器的原子替换行为保持独立。

静态检查和复查不能完全消除本地/远端另一个进程在检查后替换祖先目录的竞态；远端服务器也必须遵守 SFTP 独占创建与 mkdir 语义。没有基于目录句柄的完整路径隔离。相同长度和可用修改时间的原地内容修改可能无法识别；传输期间新增目录成员不构成稳定快照保证。失败后需要用户检查保留目标，不自动重试、合并或清理。

取消会关闭目录工作所用的独立 SFTP 子系统并放弃在途请求；正常清理保留共享 SSH 会话。本轮后续会话所有权加固增加了异常兜底：通道 CLOSE 无法在有界时间内进入协议队列时，会关闭或中止共享 SSH 连接，避免留下无人管理的通道。CLOSE 排队成功不代表远端已经确认关闭。进度及取消字节数统计已经确认的写入；取消前已到达服务器但尚未确认的请求可能继续完成，因此该字节数不能证明远端最终长度。界面始终要求检查不完整目标。

## 自动验证

`cargo test -p keelshell-session --locked` 通过：30 个单元测试、4 个远程范围检查、38 个回环 SSH/SFTP 协议集成测试（共 72 项）。本增量新增 3 个边界单元测试和 8 个目录集成测试。

新协议测试使用独立回环 SSH 服务、内存远端文件系统和隔离本地临时目录，队列终态等待最多 8 秒；覆盖：

- 嵌套二进制往返一致、Unicode 文件名、零字节文件、空目录及全空根目录。
- 审核后本地/远端源变化拒绝，已有本地/远端目标拒绝且哨兵内容保留。
- 活动传输取消保留部分树，后续 FIFO 工作继续完成；排队工作取消不创建目标。
- 远端恶意目录名、Windows ADS/设备名/尾点、大小写重名、远端符号链接/符号链接祖先拒绝。
- Unix 本地符号链接根、子项及目标祖先拒绝；该用例在 Windows 不运行，其余名称验证跨平台执行。
- 已审核计划不能改由另一条已认证 SSH 连接执行。
- 误用单文件上传目录不会创建远端目标。

`cargo clippy -p keelshell-session --all-targets --locked -- -D warnings` 通过。局部门禁日志保留在 ignored `work/recursive-transfer-session-tests-repaired.log` 与 `work/recursive-transfer-clippy-final.log`。

## 失败与修复记录

1. 首轮 7 个定向目录相关测试有 1 个失败：受控服务器为空目录返回空 NAME 包再返回 EOF，初版严格拒绝了空 NAME。改为允许有界无进展包，保留总扫描 deadline；重跑 7/7 通过，日志 `work/recursive-transfer-first-repair.log`。
2. 首次 session 全套范围守卫将新 getter `local()` 识别为禁止的本地 shell 入口签名。改用语义明确的 `local_path()`/`remote_path()`，没有放宽守卫；完整测试通过。失败日志 `work/recursive-transfer-session-tests.log` 保留。
3. 首次严格 Clippy 检出队列分支的冗余返回变量；第二次检出测试夹具 mutex 的 unwrap。均修复，最终严格门禁通过；失败日志 `work/recursive-transfer-clippy.log`、`work/recursive-transfer-clippy-repaired.log` 保留。

本记录只证明受控协议与本机测试。原生 macOS UI、三平台 CI 与真实服务器互通由后续集成验收单独记录；本记录不声称已经完成这些验收。


## 确认条布局回归与修复

本轮原生验收反馈指出：长目录完整路径与限制说明使确认正文按最小内容宽度撑开，确认/取消按钮被推到窗口外。此处记录的是问题复现、实现修复和 GPUI 自动布局证据，不代表重编译后的原生桌面复测已经完成。

所有文件操作确认统一使用 `files.rs::confirmation_bar`。正文设置 `min_w_0`，正常换行，最大高度 96 px，双轴滚动保留完整路径；按钮组固定不收缩。目录审核将源、目标各占一行，数量与限制随后显示。文件面板根布局也明确宽度并允许正文收缩。

`files/layout_tests.rs` 实际渲染同一个生产确认组件，包含长路径和 40 行额外说明。在 1440×900 窗口中，覆盖 1408、760、480 px 文件区域及中文/英文六种组合；检查确认/取消按钮的完整 bounds 均处于文件区域和窗口内，正文高度不超过 96 px、正文不与按钮重叠、按钮尺寸未塌缩，并真实点击两个按钮验证事件送达。测试不以仅找到控件作为通过条件。

旧布局在同一几何回归中失败：1408 px 文件区域内，确认按钮的 x 坐标达到 68121 px。失败证据保留在 ignored `work/recursive-confirmation-layout-before-bounds.log`，没有通过放宽断言掩盖问题。

修复后 `cargo test -p keelshell-app --locked files:: -- --test-threads=2` 为 **8/8 通过**，日志 `work/recursive-confirmation-layout-files-tests.log`；`cargo clippy -p keelshell-app --all-targets --locked -- -D warnings` 通过，日志 `work/recursive-confirmation-layout-clippy.log`。`git diff --check` 通过。此前测试模块 glob 导入触发测试宏递归，已改为显式导入；该编译失败日志 `work/recursive-confirmation-layout-before.log` 也保留。
