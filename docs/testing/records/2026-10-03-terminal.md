## Terminal unit coverage — 16 passing tests

| Area | Cases | Behaviors checked |
| --- | ---: | --- |
| Emulator | 8 | Split UTF-8; Unicode and true color; alternate screen; grid resize and selection; device status replies; application cursor; bracketed paste; Control/Alt modifier encoding; SGR/basic mouse modes; palette mutation, query and reset. |
| Input queue and IME state | 5 | A 100 KB paste remains complete and ordered through backpressure; oversized input is rejected before partial admission; resize retries use the latest dimensions; UTF-16 replacements affect the intended range and do not split surrogate pairs. |
| Output queue | 2 | A packet larger than a frame budget preserves its suffix before later packets, errors and exit; zero allowance consumes nothing; the parser receives UTF-8 and escape sequences correctly even when every byte is split. |
| Worker ownership | 1 | Shutdown signals and joins owned workers, preserves close failures, tolerates repeated shutdown, and refuses a late worker. |

The output poll now checks a 4 ms cooperative time budget, a 64 KiB byte budget,
256 ANSI events and 128 transport events per frame. It feeds at most 1 KiB to
the parser at once and drains existing ANSI events before admitting more input.
Exhausting a budget leaves data and events queued for the next poll. A parser
call or individual event can run past the time check; this is not a hard real
time guarantee. Transport queues remain bounded and apply backpressure.

## GPUI regression coverage — 4 passing tests

`ui_tests.rs` mounts the production terminal under the production GPUI Kit root
with controlled transport channels. Tests call the complete frame pipeline and
dispatch real GPUI pointer, key and input events.

1. **Frame phase, focus and keyboard routing:** a complete frame installs the
   terminal input handler during paint, a click focuses the terminal, received
   output becomes visible, and Unicode text, Enter, Control-Space and Alt-Left
   produce the exact expected transport bytes.
2. **IME, paste and release:** preedit never reaches the transport; UTF-16 range
   queries encompass complete Unicode scalars; committing writes only committed
   text; bracketed paste cannot be terminated by an embedded Escape; releasing
   the rendered terminal sets its transport cancellation flag.
3. **ANSI flood:** 4,096 BEL events cannot be consumed in one poll. Later text
   and the exit event remain pending and eventually arrive in their original
   order across bounded test-clock frames.
4. **Modal occlusion:** an actual input inside a full-window `.occlude()` modal
   receives text and clipboard paste while the underlying terminal has mouse
   reporting enabled. No text, paste bytes or stray mouse-up reach the terminal.

The modal regression also fixed an independent issue: `on_mouse_up_out` used
to send a terminal mouse release for clicks that began in another control. It
now completes only a gesture whose press was reported by that terminal. GPUI's
standard Div handlers already respect hitbox occlusion for down, move and wheel;
the Connection/Login overlay must retain its `.occlude()` boundary.

## Failure evidence and repair

- The first native launch found that registering `handle_input` in canvas
  prepaint panicked. Registration moved to paint. The full-frame test above is
  specifically intended to fail if that runtime phase regression returns.
- The first two-test headless run passed keyboard/rendering and failed the
  release assertion. Inspection of GPUI showed that entity handles dropped
  outside an App transaction are released by `App::flush_effects` at the next
  update. Running parked tasks alone does not flush such a drop. The test now
  performs an empty App update and retains the original strict cancellation
  assertion; it passes. No production cancellation bypass was added.
- A retry encountered a separate `Textarea::id` API compilation error in the
  assistant. The assistant owner corrected its use of the component's default
  identity and the GPUI test attribute imports. The complete 28-test run above
  includes all subsequent fixes.

## File-panel integration covered by this change

All file work runs in the application-owned worker registry. Panel release and
application shutdown cancel it; the worker still awaits bounded SFTP cleanup.
The 5-second outer cleanup limit accommodates the transport's 2-second staged
file cleanup and 2-second protocol close limits. Upload/save call the session
library's atomic replacement APIs; unsupported server semantics fail closed.

Three path tests reject missing/relative directories, traversal and display
control characters, and preserve Unicode and literal filename content. Mutation
targets use the successfully loaded canonical directory rather than an editable
navigation draft. Each panel and confirmation shows its fixed host. Save results
update the saved baseline without overwriting edits made during the operation;
editing after approval invalidates that pending save. Loading another file over
unsaved edits requires an explicit discard confirmation.

The SSH/SFTP fault-injection and atomic replacement results are recorded
separately in [the session test record](2026-10-03-session.md). A pre-save read
followed by rename is not a remote compare-and-swap operation. A remote change
between those steps remains possible. A cancelled or timed-out rename may have
committed; the UI asks the user to inspect before retrying and never retries a
mutation automatically. Interrupted downloads or cleanup failures may leave
explicit partial/staged files.

## Native evidence and remaining acceptance

The parent task reported a real macOS launch, a real local `printf` response and
correctly rendered Chinese text pasted through the clipboard before this final
overlay/budget rebuild. CUA's `typeText` path did not deliver the same Chinese
characters; clipboard paste succeeded. This does **not** constitute native OS
IME candidate-window acceptance.

At the time of this record, rebuilding and rechecking the final modal fix in a
native window is pending with the parent task. The tests here do not establish
GPU pixel fidelity, native Chinese/Japanese candidate-window behavior,
cross-platform native acceptance, window-manager force-quit behavior, production
SSH interoperability or a hard real time UI latency bound. Ordinary quit awaits
registered workers; the platform's 200 ms `on_app_quit` hook remains a fallback
for external quit paths. Windows and Linux require their own native acceptance.
