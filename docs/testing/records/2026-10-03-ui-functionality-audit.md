## 已确认的结构

当前工作区的主路径清楚：连接管理器 → SSH 会话标签 → 深色远程终端 → 命令栏 → 文件、命令和隧道工具区。AI 侧栏通过明确的上下文选择、请求预览和命令建议进入工作流；建议不会绕过命令审核。中文默认和英文切换通过统一的 `i18n::t` / `Message` 保留双语文本，远程内容不会被当作翻译资源。

已接通并在能力清单中有对应证据的主要远程能力包括：连接树与组织、认证和主机身份校验、跳板/代理、SSH PTY、SFTP 文件操作与传输队列、监控、端口转发、命令片段与补全、批量任务和 AI 配置/审阅。实现状态仍以能力清单的“证据 / 剩余验收”列为准。

## 发现与建议

| 优先级 | 观察 | 建议的验收行为 |
| --- | --- | --- |
| P0 | 审查基线时应用菜单未暴露项目主页、版本和更新入口。 | 已在后续实现中改为应用内“关于与更新”面板：提供项目主页、版本、变更日志、检查更新、下载进度和已校验包查看入口；网络失败保留可重试原因，更新包复用发布产物校验和。三平台原生安装权限、签名、替换与回滚仍需发布构建后验证。 |
| P1 | 顶部工具栏包含多个带文字的固定控件，在小窗口下可用宽度不足。 | 设置窄宽度断点：保留连接、新建、AI 和语言入口，其他动作折叠到更多菜单；每个图标保留双语 tooltip 和键盘可达性。 |
| P1 | 会话标签主要显示配置名称和断开文字，多个相同名称的目标不易区分。 | 在标签副标题或 tooltip 中展示 `用户@主机:端口` 与跳板/重连状态；显示真实连接状态，不能仅依赖颜色。 |
| P1 | 左侧监控栏在窄窗口和空会话场景会占用显著空间。 | 没有活动会话时隐藏监控栏；窗口低于断点时折叠为按钮；AI 打开时保持终端最小可用宽度。 |
| P1 | 文件工具区同时显示路径、属性、编辑器和传输操作，低宽度下操作密度较高。 | 保留路径和当前主操作，次要动作进入行菜单；操作失败原因和刷新要求仍固定显示在状态区。 |
| P2 | 连接列表对每行提供多个文字动作，鼠标路径清楚但键盘效率有限。 | 增加行焦点、Enter 连接、上下移动和可访问的操作菜单；保留显式 Connect 按钮供触摸/鼠标操作。 |
| P2 | 空列表状态有新建入口，但没有导入配置的同级引导。 | 空列表同时提供“新建连接”和“导入 JSON/OpenSSH 配置”（待后端接通）；没有真实导入能力时不要显示可用按钮。 |

## 范围差距

以下是产品目标仍未完全覆盖的能力，应继续按路线图推进：OpenSSH 配置导入、keyboard-interactive 认证、可拖拽或嵌套分屏、多窗口、文件语法高亮与 diff、并行传输、归档/Zmodem、中继测速和完整系统档案。它们不能由当前卡片、截图或编译结果推断为已完成。

## 本次结论

工作区的信息架构已经适合远程 SSH 日常操作，且远程目标、审核边界和多语言入口可见。应用内项目/更新入口已补齐；下一轮应优先完成窄窗口布局策略，并用真实三平台窗口检查工具栏、焦点、中文输入法和菜单可达性。更新面板目前只提供经过校验的安装包查看入口，不会覆盖正在运行的安装。此次审查没有修改更新器或 AI 诊断代码。
