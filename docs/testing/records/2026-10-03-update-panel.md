# 关于与更新面板验证

## 已验证

- 面板从主工具栏打开，默认显示本地 `CHANGELOG.md`，并提供项目主页链接。
- 检查与下载任务使用独立 Tokio 工作线程；请求有连接、响应大小和总超时，重定向只允许 GitHub 发布资产域名。
- 版本、项目地址、发布页地址、平台目标和资产文件名均经过固定格式校验。
- 下载先校验发布提供的单行 SHA-256 文件，再写入唯一临时目录；校验失败不会覆盖安装目录。
- 单元测试覆盖平台文件名、版本比较、校验文件格式、GitHub URL 限制和下载响应上限。
- 校验后的 ZIP/TAR.GZ 会在唯一临时目录中安全解包；拒绝绝对路径、父目录、重复条目、符号链接、特殊文件、超大文件和超过总量/条目上限的归档。安装计划再次按 `package-manifest.json` 验证每个文件的 SHA-256。
- 校验后的临时目录由就绪状态持有；下载失败、关闭面板或放弃安装时会删除归档和解包内容。只有成功启动 helper 后才解除清理责任，避免 helper 尚未读取 payload 时被父进程清理。
- `package-manifest.json` 必须声明发布脚本的回执边界，并列出当前平台可执行文件，其 `binary_sha256` 必须与文件清单一致；缺失二进制或伪造回执会失败关闭。
- 显式选择“自动安装并重启”会启动同一二进制的隐藏 helper。helper 只复制清单文件，文件占用时有界重试，文件先完整写入同目录临时文件并同步后重命名，部分失败按相反顺序回滚，成功后重新启动应用。

本轮回归：更新器单元测试扩展至 12 项（临时目录生命周期、平台可执行文件/回执边界、临时文件重命名覆盖）；`keelshell-app` 全部测试、workspace Clippy、格式、依赖策略、全 workspace 测试与文档门禁需由本次提交后的集成门禁重新记录。

远端 Quality 记录：`37164178313` 在 macOS 26、Ubuntu 24.04 和 Windows 2025 全部通过。此前 `37163215455` 与 `37163711331` 分别发现 Linux 和 macOS 路径断言被错误地带到 Windows 宿主执行，已由 `69d1129`、`964836b` 按宿主路径语义隔离；最终 Windows 全 workspace 测试通过。

## 未验证边界

当前构建证明的是发布发现、变更日志展示、下载、完整性校验、归档安全解包以及 helper 的本地清单校验/回滚逻辑。它没有执行真实 GitHub 下载，也没有在 macOS、Windows、Linux 的已签名安装目录中完成替换和重启。由于签名、公证、系统权限和各平台文件占用路径仍未完成三平台原生验收，发布包仍需在对应环境中人工验证；开发构建会明确退回手动安装。
