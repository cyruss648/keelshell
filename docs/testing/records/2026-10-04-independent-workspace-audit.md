## F2：模态能力研究与实现边界

核对当前锁定版本 `gpui-kit 0.7.0`、`gpui-component 0.7.0`、`gpui-base 0.7.0` 与 `gpui-pre 0.3.7` 源码后的结论：

1. 组件层 `Dialog` 委托基础层 `Dialog`。基础实现具有 `Role::Dialog`、稳定焦点句柄、`FocusTrapElement`、Escape/确认/取消分发与遮罩关闭控制。`WindowState::open_dialog` 保存先前焦点，关闭路径负责恢复焦点；Tab/Shift-Tab 由基础 Root 限定在有效陷阱中。它可以承接当前自绘模态的键盘范围和焦点恢复，但迁移不能只换一层视觉容器。
2. 现有基础 `Dialog` 没有设置 AccessKit 的 `Modal` 标志，当前 GPUI `StatefulInteractiveElement` 也没有公开 `aria_hidden`、`aria_modal`、`inert` 或背景子树排除接口。`Window` 的辅助技术 API可读取启用状态、调试树及注册动作；内部节点构建器不是应用层的公开隔离 API。角色为 Dialog 或视觉 `occlude()` 本身不能证明背景节点不可导航。
3. AccessKit 已有 `Node::set_modal()`，macOS 和 Windows 适配器分别暴露原生模态属性；但增加这个标志与排除背景可操作节点是不同的工作，仍须实际辅助技术验证。因此，本轮没有通过给整个背景隐藏角色或凭空调用不存在的 API 来关闭 F2。

建议后续按三个可验收切片推进：先集中定义最上层模态与返回焦点，迁移到稳定的 Dialog/focus-trap 生命周期；再补充框架支持的模态标志与非活动子树隔离能力；最后验证连接管理器 → 新建连接等两层模态。验证应同时覆盖中文/英文、连续 Tab/Shift-Tab、Escape 只关闭当前层、返回触发控件，以及原生可访问树和屏幕阅读器不能激活背景快速连接或前一层管理器操作。迁移后仍须保留各业务模态的保存、取消和秘密清理语义。
