## 修改范围

仅两份测试源码变化：`crates/keelshell-app/src/assistant_tests.rs` 与 `crates/keelshell-ai/tests/request_options_http.rs`。生产代码、依赖、Cargo.lock 和工具链不变。

界面回归为发现模型、连接测试和 Apply 后的 Ask 分别创建自有代理 exchange，在对应控件已可触发请求后、点击前启动接收。完整真实请求通过原路由、认证、内容断言后才记录到达，随后验证请求仍在等待响应，再释放回复。原有 6 秒接收、3 秒 I/O、6 秒回复和 5 秒 UI 期限保持；半行输入不能逐字节刷新总读取预算。取消或失败会请求停止、关闭 gate，并有界等待 worker 退出后 join。

受控原六秒接收探针证明：准备阶段尚未准入请求时，接收期限可以先到期。这证明存在测试生命周期缺口，但原 CI 未记录界面点击时点，不能据此认定原 CI 的具体时序原因。新增四项行为回归覆盖准备超过六秒后再触发、无 peer 截止、接受半行后取消和等待回复时取消。

隔离子进程保留原 `env_clear`、`NO_PROXY/no_proxy=*`、固定失效环境代理及真实三请求夹具。父进程同时异步读取两路输出，每路最多 32 KiB，超额失败；原八秒总预算包含终止、reap 和 EOF，并为清理预留一秒。父进程要求成功退出、两路 EOF 与完成真实 HTTP 断言后的专用回执；无行为的成功 stub 不能通过。新增五项回归覆盖非零错误输出、超时、双流容量、继承写端和缺失真实回执。

**原 Windows 子进程失败原因仍未知。** 当前候选让新 CI 的失败具备有界错误输出，不因 macOS 通过宣称 Windows 已修复，也不先继承任意用户环境或猜测缺失环境变量。
