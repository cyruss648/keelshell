# 2026-10-06 Codex 对外 MCP 原生尝试与准确边界

不增加通用第三方 MCP 客户端。本记录保留两轮新 macOS 尝试的实际失败，
不能把目录准入或授权界面当作工具调用、人工审核或 SSH/SFTP 业务成功。

## 第二轮：真实目录准入通过，业务仍失败

使用独立新夹具、新界面和新能力，保持原 300 秒准备及准入审查期限。
完整指纹、52 字节片段、七项工具、目录和复制提示重新记录；标记及时消费。
控制器只在内存读取临时能力，随后实际清空剪贴板，两项 helper 均 wait/exit 0。

实际首笔模型 POST 为 43,299 字节，SHA-256
`56de70e07da471a303f81b8dcb1c1c8b484841f570a01d6ce2965c63839d9e28`。
根与新非作者分别全文读取 POST、头部、五份 raw stdio 和 14 条 journal，
重新执行准确目录比较：八项 MCP 工具、四项完整禁止调用函数定义、
32 个固定 schema 差异、一个原 schema 完全一致项及完整 UUIDv5 carrier 绑定。
实际固定 HTTP 400 已写出并 flush；此阶段 0 SSE、0 业务 RPC。
CLI 实际 wait/reap 退出 1，伴随程序实际 wait 退出 0；记录器无错误，
其间接 OS 状态仍未知。HTTP worker 已停止；指定模型/IPC/SSH 三端口的
TCP 结果为 `[0, 0, 1]`，不是完整网络隔离矩阵。

新的非作者结论为限定真实固定 400 目录准入通过。根读取完整审查证据后，
通过新的实际界面截图单独放行受控 SSE 阶段。第二阶段首笔 POST 再次通过目录检查，
实际写出一个固定 SSE 工具调用；随后 Codex 的首个 `tools/call` 请求附带 `_meta`。
原记录器只接受精确 `name` / `arguments` 参数，因 `RPC params keys` 拒绝，
未转发给伴随程序或桌面。因此本轮 **0 个已授权业务 RPC、0 个配对业务结果**。

Codex 下一笔 POST 使用 `input_text` 数组表示客户端 `Transport closed` 错误；
原控制器仅接受字符串输出，因 `unreviewed output payload type` 停止。
该数组是失败输出，不能作为成功工具输出格式或业务内容的证明。
最终记录器 journal 保留原拒绝，伴随程序实际 wait 退出 0，记录器 planned exit 1
及错误不被改写为通过；严格收尾检查也失败，业务 final-readback 文件未生成。
控制器工具实际退出 1，不能仅用失踪 PID 推断这个退出结果。

GUI、fixture 与两轮 CLI 的实际持有 wait/reap 已记录；两个伴随程序的实际 wait 为 0。四个间接身份的原收尾和独立复查仅保留无类型 `null`，没有 errno、返回字节数或 typed ABSENT，不能据此区分 ESRCH 与查询未知，也不能证明完整间接进程清理。四个所属端口保留实际拒绝码 61，HTTP workers 停止，准确夹具根与私有目录移除的观察仍保留。间接记录器 planned status 不替代 OS wait，其 OS 状态仍未知；未取得原进程组逐一消失的证据。

原生输入逐字核验相等。原失败后的独立复核限定确认 0 个已授权业务 RPC 与记录器对额外元数据的拒绝，不能沿用目录准入作为业务结论。后续新离线反例证明验证器可把 UNKNOWN 误分类为已退出，未证明该情况在旧运行时实际发生；旧封存日志和审查正文保持原样，本段记录新的证据边界。

## 后续边界
