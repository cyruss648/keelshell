## 批量参数与依赖任务

两目标均经实际 host key 核对与临时测试认证；没有选择保存凭据。批量面板明确
选择两个已认证目标，为同名 `release` 参数分别填写 `候选一's` 与 `候选二`。
根在确认前看到了每个目标及其完整展开命令，随后两条回执均显示成功、退出 0。
分别选择输出后，界面显示两个不同的原值，包含的单引号保留。

依赖工作流的两个任务选择同一目标。后续任务明确依赖前置任务，只填写一个共享
目标参数 `共享's`。完整审核显示两条展开命令、依赖关系、选项及同一认证连接
实例；人工确认后两任务都成功、退出 0。分别查看输出得到 `first:共享's` 和
`second:共享's`，stderr 为空。

服务端测试 shell 实际执行 `/bin/sh -c` 并保留原始命令、开始/结束时间、stdout、
stderr 和退出码，不返回预设业务结果。根逐字核验四条业务记录：精确命令和 UTF-8
输出均匹配，stderr 为空，退出码均为 0；前置任务结束时间早于后续开始时间，
两任务及前面的同目标批量命令复用同一条真实 SSH 连接。更早的六条 CLI 预检
按 ID 单独排除，未冒充 UI 操作。

这关闭本轮正常执行及单引号参数的有限场景；取消、连接替换、未知结果、更多
目标、长输出和三平台原生组合仍需各自验证，不能用领域或 GPUI 测试替代。

major 数值错误已按真实字节纠正，原修正材料保留。

没有累加。暂停按钮变为继续；暂停期间显式刷新更新了数值且继续按钮保持。
本轮没有通过定时审计证明暂停期间完全无自动请求。

采样来自 Podman VM 的真实 Linux 内核。它不证明 macOS 宿主磁盘、物理硬件、
