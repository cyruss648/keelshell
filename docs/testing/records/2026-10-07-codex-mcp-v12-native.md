# 外部 Codex MCP V12 原生尝试

KeelShell 向外部智能体提供 MCP 服务。应用内调用 API 或本地 CLI Ask 是独立功能；本记录不增加通用第三方 MCP 客户端，也不将本轮部分结果作为完整业务验收。

## 输入与隔离范围

三次新尝试使用当前 `0cca8ac59d12afdc68512b45db8830810835c634` 检查点及其目录镜像工作副本。689 份工程输入的映射 SHA-256 为 `99dd29c8e56d828b2df8c372267ff14cfa3f51030789545da06789fcd2d3f91c`；标准 macOS GUI、MCP 伴随程序、自有 SSH/SFTP 夹具和官方 Codex 0.160.0 私有副本共 709 行运行绑定，在结束后逐正文复核。V3 完整运行绑定 SHA-256 为 `505f4b00a8139f29ce3f79b4e5730229b5f8d0228bdbaef9f4d5cc1f617f4df1`。每次使用新的应用和 CLI inode、隔离临时资料、选区、授权、客户端与服务端口，不沿用前一次的能力。

SSH/SFTP、固定模型响应和 HTTP 服务均自有隔离；实际原生应用及外部 Codex CLI 运行，不调用云模型、客户服务器或任意系统 shell。测试命令为夹具实现的固定操作。CLI 的受限网络策略允许本轮模型与桌面 IPC，拒绝直接访问夹具 SSH 端口。控制器的既定业务目标为 22 次配对工具调用及实际桌面撤权；目录准入采用固定 HTTP 400，不能单独算业务完成。

V3 实际读回当前授权会话、准确的含中文 52 字节选区、`/bin` 目录和 UTF-8 文件。越界路径与未授权监控得到 `FORBIDDEN`，错误路线得到 `STALE_SESSION`。一条命令在原生完整审阅及确认后回传成功，另一条在原生拒绝后回传 `rejected`。文件替换在完整三行原文／新文与目标审阅、人工确认后回传成功，并经实际 SFTP 重新读取精确替换正文与完整 SHA-256。

第 20 次工具调用返回第二份文件提案的 `pending_review`。原图 `18-file-rejected` 在暂停后约 56 秒已显示同一文件、目标及摘要的“已拒绝”，但确认标记在暂停后约 237 秒、清理结束后约 57 秒才写入，没有被控制器消费。第 22 个 HTTP 请求等待约 180 秒后返回测试错误；HTTP 请求序号与文件快照序号均不是工具调用次数。本轮只有 20 次配对工具调用，不能将该截图或迟到标记作为第 21／22 次读取与撤权通过。

该失败来自根测试操作未及时交付确认标记，不能由此推断产品拒绝功能失败，也不能将及时的桌面观察改写成完整 Codex 流程成功。后续验证继续保留准确选区、真实桌面审核及原期限，不改生产授权边界或测试期望。

## 终结与复核

三个原 controller 均由原持有者取得实际退出 1。V3 admission／business CLI 均实际 wait 1；GUI 按记录的自有出生身份发送 SIGTERM 后实际 wait -15，SSH/SFTP 夹具实际 wait 0。两阶段伴随程序实际 wait 0；内部 recorder 的 OS wait 未由 Codex 暴露，保持 `UNKNOWN_NOT_EXPOSED_BY_CODEX`，其计划退出值不能替代实际 OS wait。

V3 原清理记录及根新的只读检查确认 19 个已记录进程组不存在、4 个自有端口拒绝连接、两个 HTTP worker 结束、私有能力与夹具目录移除、已记录直接子进程均完成 wait，清理错误为空。根逐正文读验 410 份原材料／7,810,227 字节和全部 709 行输入后生成独立的终结读回收据。这里只声明已记录自有资源的限定清理，不声明完整供应商进程枚举或桌面人工撤权。

V1／V2 的新非作者失败证据复核已完成并由根逐正文读验：V1 364 份／6,282,553 字节，SEAL SHA-256 `4461e8fb511dfb1877a050b2578fd9dbef48d7236f56bc7c979dd8a71bbe7e72`；V2 53 份／1,422,255 字节，SEAL SHA-256 `40747e9b7c082541c9357920b426e3615706c6376de67070f51d765226a92b28`。这些是保留实际失败与边界的复核，不是业务 PASS。V3 新非作者完整失败证据复核已经完成，确认 20 项真实配对结果及语义步骤、原生拒绝截图与迟到标记的区别、未发出的第 21／22 项和未到达的撤权。根完整读验其 426 份／8,508,791 字节封存正文与原始证据，SEAL SHA-256 为 `c6f5be9f8830f1dd10d81b630028f3ed240ec6684be8a2625376ac2f098f37d3`。原失败、测试操作错误及 recorder OS wait 未知边界保持，不将失败证据复核作为业务 PASS。

本轮未修改生产源码、未提交推送或发布标签、未覆盖安装任何已有应用。三平台桌面、完整 Codex 授权／拒绝／撤权、供应商模型与发布安装更新仍需各自验收。此前尝试和失败继续保留，见[旧当前尝试记录](2026-10-06-codex-mcp-current-attempts.md)。
