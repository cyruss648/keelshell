# 目录同步 CI 失败观察

此独立分支基于 `0cca8ac59d12afdc68512b45db8830810835c634`，只增加既有目录同步行为测试的诊断，没有修改生产代码、等待期限、确认次数或任何文件字节断言。

原提交的 Quality attempt 1 在 Windows 和 macOS 成功，Linux 的唯一 app 失败为 `directory_sync_reviews_exact_content_and_uploads_only_after_confirmation`：确认后目标仍为 `old!`，预期为 `new!`。旧日志没有同步任务终态，原因尚未确定，见[原 CI 记录](https://github.com/cyruss648/keelshell/actions/runs/37481523251)。

测试的 idle 条件在成功、失败及拒绝后都可成立。新增观察在确认点击后记录 busy、worker 和 pending，最终字节断言失败时附带实际状态、挂起状态与原子写入次数。仍使用原 12 秒等待和一次确认；不自动重试或把拒绝视为成功。

本分支不包含未提交的目录镜像、审核布局或远程协议诊断。提交前已实际通过依赖策略（0／0.048秒）、格式（0／1.302秒）、严格locked workspace/all-target Clippy（0／209.583秒）及五项目录同步行为测试（0／98.856秒，测试本身0.57秒）。672份工程输入、14,360,545字节在检查前后逐字节相等；自有子进程实际wait结束、进程组已消失，私有临时目录已清理。完整日志与终结记录保存在该树忽略的 `work/ci-observation`。这些是本机源码检查，尚未确认原Linux失败原因。

新非作者已完成限定复核，没有发现阻断问题；根全文读回29份封存材料、261,869字节。移除新增两观察块及断言诊断参数后，整个测试文件与基线逐字节相等，生产源码没有变化。`worker`诊断字段仅表示operation ID存在，不证明OS线程存活；新增快照带来少量观测耗时，idle自身超时不会进入最终字节断言消息。新提交的三平台CI需要实际终结后核对。源码测试成功不能代替原生桌面、跨平台打包或安装更新验收。
