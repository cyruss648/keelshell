# 文件审核正文滚动与读回 — 2026-10-07

## 已观察与仍未确认的原因

父任务在当前主树的 macOS 开发包中，连接隔离自有 OpenSSH Linux 服务，实际生成五项目录镜像计划。CUA 的 03、05、06 原始 JPEG 只显示审核正文的目标、本地根、远端根前三行；两次针对审核区的页滚动后仍未完成全部正文读回。07 实际取消后工具恢复，父任务另行核验本地/远端目录和正文未改变，未点击批准。这是未完成原生审核流程的证据；不能仅凭截图确定 renderer 根因。

独立工作树逐正文导入主树 689 个冻结输入后，给相同单字符串审核 renderer 添加 ScrollHandle 观察，未改原布局。实际 GPUI 单组件 48 行测试形成 1,200 px 纵向范围且 wheel 到达 -1,200 px；实际 FilesPanel 的五项 SFTP 镜像也形成 517.5 px 范围、wheel 到达 -517.5 px，并在 notify/repaint 后保留位置。这两项 PASS 不支持“48 px 上限必然导致零纵向范围”的猜测，也不等于旧原生现象已修复。CUA 原动作的独立坐标映射 receipt 缺失，仍需新原生复验。

## 已证实的窄问题与修复

长不折行路径的横向回归在旧单字符串 renderer 中实际失败：51 行含 512 字符路径，max x 为 0、max y 为 1,408 px，要求可横向读到完整路径的断言实际退出 101。原正文、源输入、raw log 和实际终结 receipt 均保留。旧原生 AX 提供批准/取消按钮而没有审核正文 label，完整辅助技术阅读尚未通过。

修复仅改变通用文件审核正文呈现：保留原始换行，逐行使用不压缩、不折行元素，真实双轴滚动条与每行原文字 Label；正文上限为 72 px，动作继续位于滚动区域外。新提案回到审核开头。没有变更计划内容、128 KiB 完整审核上限、目标授权、执行时复核、批准/取消 handler 或任何传输/删除协议。目录同步、镜像、续传和普通文件审核复用此组件。

- 两个生产组件 GPUI 测试通过。900×580、1440×900，中文/英文与 System/Light/Dark 共 12 组，51 行原文标签逐条相等；实际 wheel 使尾部 marker 与长路径末端进入裁剪视口；确认和取消在真实 bounds 内点击成功。现有 480/760/1408 px 宽度动作回归同时保留。
- 一项实际生产 FilesPanel + 隔离 TCP SSH/SFTP 测试通过。两个窗口尺寸与两语言三主题共 12 组，五项实际计划的 17 行原文全部保留，尾部确认 notice 和实际 SHA-256 行分别经 wheel 可达，重绘保持偏移；每次实际取消后原远端/本地字节保持、目标新增文件仍缺失、目标独有空目录仍存在、WRITE/job/journal 未开始，新审核回到开头。实际计划在宽窗口可能随平台字体完全适配，不强迫不必要的横向溢出；512 字符主回归在两个尺寸均要求真实横向位移。
- 原单字符串观察阶段的 64 个 review 过滤测试实际通过；没有将其计作修复后证据。该较广运行留下一个测试私有空 state lock 目录，原 namespace/receipt 保留；消费者实际退出且 fresh FD/PID/PG 检查无活跃读取后，已只清理该精确私有空目录。

前一 691 输入的完整标准 scripts/check.py 已实际退出 0，877.526 秒，前后输入相同、leader 已回收、进程组消失、TMP 为空。其生产呈现源码与最终候选相同。随后仅补充真实 Cancel 空目录读回与字体可移植测试、结果文档，最终候选重新运行同一标准门禁；新输入及终态另附封存包，不继承前一输入的通过结论。没有新增依赖，依赖策略继续要求 x.y。

## 原生与后续边界

上述成功属于无窗口 GPUI 布局/动作与隔离 TCP SSH/SFTP 行为，不是原生像素、VoiceOver、Windows/Linux 桌面、客户环境或多平台发布验收。新 macOS 产物和真实正文/两轴/取消流程、原动作映射及完整辅助技术阅读仍开放。原未完成纵向读回的原因保持未定。

远程目录字段输入后 Enter 未加载、Refresh 才加载是独立 UX 建议：可明确“加载目录”与 Enter 行为，但输入 draft 不能切换 mutation authority；必须等成功认证列表返回 canonical 目录。本窄修复未实现该导航改动。较大的审核详情面板可在新原生复验后评估，不能扩大批准范围。
